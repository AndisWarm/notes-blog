04 DNS 域名解析¶

面试问法：DNS 全称 / 域名层级 / 解析工作流程 / 端口 / host 文件 / TCP 还是 UDP。 共 5 题。

Q1 DNS 的全称了解么？¶

一句话答案¶

DNS = Domain Name System（域名系统），把域名转换成 IP 地址的分布式数据库系统。有了它，我们只需要记住 www.baidu.com，不用记 39.156.66.10 这种 IP。

大白话讲解¶

IP 地址是"数字门牌号"，域名是"店名"。没有 DNS，你上网得记住每家店的数字门牌号——人类记不住，DNS 就是那个"查号台"。

域名的层级结构（面试爱考）：

域名用句点分隔，越靠右层级越高（外国思维：从小到大）。比如 www.server.com 真正的全名是 www.server.com.（最后那个点代表根域名）：

.                ← 根域（最顶层）
├── .com         ← 顶级域（com、cn、org…）
│   └── server.com  ← 权威域（某个公司的域名）

DNS 服务器也对应分三层：

  1. 根 DNS 服务器（.）：只管"指向哪里的顶级域服务器"；
  2. 顶级域 DNS 服务器（.com）：只管"某个域名归哪个权威服务器管"；
  3. 权威 DNS 服务器（server.com）：域名解析结果的原出处——"我的域名我做主"。

关键点：根域 DNS 服务器的信息保存在互联网中所有 DNS 服务器里，所以任何 DNS 服务器都能找到根，然后"顺藤摸瓜"找到目标。

Q2 DNS 域名解析的工作流程？¶

一句话答案¶

客户端 → 本地 DNS → （缓存没有则）根 DNS → 顶级域 DNS → 权威 DNS → 拿到 IP 逐级返回。

大白话讲解¶

用"查号"的比喻走一遍（查 www.server.com 的 IP）：

  1. 客户端把 DNS 请求发给本地 DNS 服务器（你电脑网络设置里填的那个，如 114.114.114.114）。
  2. 本地 DNS 先查自己的缓存表：有就直接返回；没有就找"老大"——根域名服务器。
  3. 根 DNS 不直接给答案，它说：".com 归顶级域管，我给你 .com 顶级域服务器的地址。"
  4. 本地 DNS 找"老二"——顶级域服务器，问 www.server.com 的 IP。
  5. 顶级域服务器说："server.com 归它的权威服务器管，我给你权威服务器的地址。"
  6. 本地 DNS 找"老三"——权威 DNS 服务器，问 www.server.com 的 IP。
  7. 权威 DNS 服务器（原出处）查表，返回 IP。
  8. 本地 DNS 把 IP 返回给客户端，客户端拿它去建立连接。
客户端 → 本地DNS → 根DNS → 顶级域DNS(.com) → 权威DNS(server.com) → 一级级返回IP

记忆要点：本地 DNS 全程跑腿，根/顶级/权威三级服务器各自只"指路"或"给答案"。缓存命中（第 2 步）是最快路径，所以"浏览器缓存 → 系统 hosts → 本地 DNS 缓存"逐级查。

Q3 DNS 的端口是多少？¶

一句话答案：默认端口号是 53（UDP 和 TCP 都用它）。

（送分题。）

Q4 改过 host 文件吗？¶

一句话答案¶

host 文件 = 本地的"域名 → IP"绑定表，优先于 DNS 解析生效，把域名直接指向指定 IP。

大白话讲解¶

host 文件的作用是让某个域名直接访问指定 IP，不走公共 DNS。典型场景：

  • 程序员测试没上线的项目：服务器只有 IP 没有域名，在 host 里写一行 192.168.1.100 www.test.com，输入域名就能访问测试服，不用记难背的 IP。
  • 也可以用来屏蔽网站（把域名指向 127.0.0.1 让它无法访问）。

优先级：浏览器缓存 → hosts 文件 → 路由器缓存 → ISP 的 DNS 缓存（hosts 排在公共 DNS 之前）。

Q5 DNS 的底层使用 TCP 还是 UDP？¶

一句话答案¶

两个都用，端口都是 53：普通查询用 UDP（快、轻量）；区域传送、UDP 响应被截断（超 512 字节）、DNSSEC 签名响应用 TCP。

大白话讲解¶

为什么查询用 UDP？

  • 低延迟：不用建连，直接发直接收；
  • 简单快速：没有连接管理和流量控制开销；
  • 轻量级：UDP 头部只有 8 字节，小请求小响应非常合适。

什么情况改用 TCP？

场景 原因
区域传送（Zone Transfer） 主从 DNS 服务器之间同步数据，量大且必须完整可靠 → 必须 TCP
UDP 响应被截断 传统 DNS 的 UDP 报文上限 512 字节，超出后响应里会带 TC 标志，客户端自动回退到 TCP 重查
DNSSEC 签名响应 签名让响应变大，容易触发截断回退

现代扩展（加分项）：

  • EDNS0：把 UDP 报文上限协商到 4096 字节，减少 TCP 回退；
  • 加密 DNS：DNS over TLS（853 端口）、DNS over HTTPS（443）、DNS over QUIC——防止查询被窃听篡改。

尽管 UDP 会丢包，但 DNS 靠"超时重传 + 请求重试 + 缓存"保证了可靠性，丢包风险可容忍。

本单元小结¶

概念 一句话记住
DNS 全称 Domain Name System，域名 → IP 的查号台
域名层级 越靠右层级越高：根 . → 顶级 .com → 权威
解析流程 本地 DNS 跑腿：根指路 → 顶级指路 → 权威给答案
端口 53（UDP/TCP 都用）
host 文件 本地绑定表，优先于 DNS
UDP 还是 TCP 查询用 UDP；区域传送/截断回退用 TCP
