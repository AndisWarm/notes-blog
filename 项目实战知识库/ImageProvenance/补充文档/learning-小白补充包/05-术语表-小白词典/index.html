05 术语表：小白词典¶

遇到看不懂的词就翻这里。按主题分组，每个词给：一句话定义 → 本项目里的位置。 想深入某个词，看"出处"列对应的文档。

A. 区块链 / 以太坊¶

术语 一句话定义 本项目里 出处
区块链 全世界共同持有、只能追加不能篡改的公共账本 用 Hardhat 在本地模拟 02 篇
以太坊 能跑小程序（合约）的区块链 系统运行的底层平台 02 篇
开发链 / 本地链 在你电脑上模拟的以太坊，数据在内存、关了就清零 Hardhat（端口 8545） 01、02 篇
区块 账本的一页：一批交易的打包单元 你每笔交易都会进新区块 02 章
交易 (Transaction) 让链上状态发生变化的唯一手段 登记、授权、分账都是交易 02 篇
nonce 账户的交易序号，防止重放 重启 Hardhat 后 MetaMask 记着旧 nonce 会导致 pending 01 篇 1.6
gas 链上操作的"油费"，存储最贵 链上只存 32 字节哈希的原因 02 篇
EVM 以太坊虚拟机：每台电脑上确定性重放合约代码的沙箱 合约跑在它里面，不能上网不能随机 02 篇
EOA 外部账户（人用的账户），由私钥定义 你的 MetaMask 账户 02 章
合约账户 由部署交易创建的账户，没有私钥 四个合约的地址 02 章
地址 账户的门牌号（0x 开头 40 位十六进制） 0x70997970C51812dc3A010C7d01b50e0d17dc79C8 等测试账户 02 篇
私钥 / 公钥 钥匙 / 锁 私钥在 MetaMask，公钥公开 02 篇
RPC 节点对外提供的查询/操作接口 http://127.0.0.1:8545；curl 直接发 JSON-RPC 02 章
Chain ID 区分不同链的编号 本项目 = 31337 01 篇
事件 (Event/Log) 合约发出的广播，附在交易回执里 后端监听器 2s 拉取感知链上变化 02 篇
回滚 (revert) 交易失败时状态全部撤销 "合约拒绝"提示的来源 02 篇
方法选择器 合约方法签名哈希的前 4 字节，标明"调用哪个方法" txRequest.data 前 8 个 hex 字符 02 章
msg.sender 合约里"本次调用的发起者"（由签名恢复，伪造不了） 项目身份闭环的核心 04 章
ABI 合约的"说明书"（方法、参数、事件格式） 后端打包交易、前端直调合约都用它 04、07 章

B. 密码学 / C2PA¶

术语 一句话定义 本项目里 出处
SHA-256 密码学哈希：内容差 1 字节，输出全变 originalHash / signedHash / manifestHash 03 篇
pHash 感知哈希：内容越像输出越接近 登记时的相似图预警 05 章
数字签名 私钥盖章、公钥验章：内容没改 + 本人所为 MetaMask 签交易、CA 签 C2PA 声明 03 篇
证书 把"身份 + 公钥"绑在一起的数字身份证 tools/ca/sign.crt 03 篇
CA / 根证书 给证书盖章的机构 / 自签的信任起点 自建：tools/ca/rootCA.pem 03 篇
trust anchor 验证方预先信任的根证书 验签时加载的 rootCA.pem 03、08 章
Trusted / untrusted 签名有效且来源可信 / 签名有效但来源不认识 08 章招牌对照实验 08 章
C2PA 内容来源与真实性标准：把声明嵌进图片 签名分发版里的 manifest 03 篇
manifest C2PA 声明本体（断言 + 硬绑定 + 签名） 嵌在 c2pa-*.png 里 03 篇
assertion manifest 里的一条断言 c2pa.actions、stds.schema-org.CreativeWork 03 章
hard binding 对图像数据分块哈希的硬绑定，改图即断 篡改检测 = Invalid 03、08 章
c2patool C2PA 官方的签名/验证命令行工具 tools/bin/c2patool.exe 08 章
JUMBF C2PA 声明在文件内的存放格式 藏在图片元数据区 03 章
时间戳 (TSA) 第三方对"这一刻文件存在"的盖章 可选配置 TSA_URL，失败优雅跳过 manual/01

E. 易混词速查（高频翻车点）¶

容易混的两个词 区别
原图 vs 签名分发版 原图没有 C2PA 声明；改原图 = "无记录"，改分发版 = "签名后被篡改"
密码学哈希 vs 感知哈希 SHA-256 差一点全变（防篡改）；pHash 像一点就接近（查相似）
签名有效 vs 签名可信 有效 = 没被改且是持钥人签的；可信 = 还要根证书在信任列表里
连接钱包 vs 确认交易 连接只是亮身份；每次操作都会再弹窗逐笔确认
链上数据 vs 数据库镜像 链是唯一真相；SQLite 是监听器抄来的副本，可删可重建
登记 vs 授权 登记 = "这图是我的"；授权 = "我允许你用"
部署 vs 启动 部署 = 把合约刻到链上（每次重启链后要做）；启动 = 拉起服务进程
nonce 清零 vs 链清零 Hardhat 重启链数据没了，但 MetaMask 还记着旧 nonce，必须手动清

  2. 还想要原理 → 点"出处"链接；出处格式说明：XX 篇 = 本补充包，0X 章 = 原 learning/。
  3. 找不到的术语 → 去原 manual/05-API参考.md 和 manual/06-状态对照与数据字典.md 查接口和数据字典。
