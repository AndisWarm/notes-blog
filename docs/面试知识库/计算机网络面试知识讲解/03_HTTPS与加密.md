# 03 HTTPS 与加密

> 面试问法：HTTP 为什么不安全 / HTTP 和 HTTPS 的区别 / HTTPS 握手过程 / 如何防中间人攻击。
> 说明：Q1–Q4 已并入《02_HTTP基础.md》（因为这些问题围绕 HTTP 展开，连着看更好理解），本章专门讲**加密原理与安全机制**，并补充原题的进阶追问。

## Q1 加密三兄弟：对称加密、非对称加密、混合加密

（原题没直接问，但 HTTPS 的所有原理都建立在它们之上，先补上。）

### 一句话答案

**对称加密**：加密解密用同一把钥匙，快但钥匙怎么安全送出去是个问题；**非对称加密**：公钥加密、私钥解密（或反过来），不用送钥匙但慢；**HTTPS 用的是混合加密**：用非对称加密安全地商量出一把对称密钥，再用对称密钥加密正式通信内容。

### 大白话讲解

- **对称加密**：像家门钥匙，锁门开门用同一把。速度快，但问题来了——**钥匙怎么安全地交给对方？** 半路被人抄走一把，门就白锁了。
- **非对称加密**：像公共邮箱，任何人都能把信投进去（公钥加密），但只有你有钥匙能打开（私钥解密）。公钥可以随便发，私钥自己留好，完美解决"送钥匙"问题，但**慢**（比对称加密慢几个数量级）。
- **混合加密**（HTTPS 的做法）：先别急着寄信，先用公共邮箱（非对称）安全地交换一把"临时家门钥匙"（会话密钥），之后所有信都用家门钥匙加密（对称），又快又安全。

**HTTPS 用非对称加密协商出对称密钥，再用对称密钥加密内容——这就是混合加密。**

## Q2 数字证书和 CA 是什么？（HTTPS 防冒充的关键）

### 一句话答案

**数字证书 = 服务器身份证明**，由 CA（证书权威机构）签发，里面装着服务器的公钥和身份信息；客户端用系统内置的 CA 公钥验证证书真伪。

### 大白话讲解

问题来了：服务器把公钥发给客户端，怎么保证这个公钥**真是目标服务器的**，而不是中间人伪造的？

- 服务器的公钥不能自己说了算（"我是淘宝"谁都能说），得让**第三方权威机构（CA）** 认证。
- CA 审查服务器身份后，签发**数字证书**：证书里写着"此公钥属于 www.taobao.com"。
- 浏览器和操作系统**内置了 CA 的根证书（含 CA 公钥）**，用它验证服务器证书的签名是否有效、有效期、颁发机构是否可信。
- 验证通过 → 证书里的公钥可信 → 才用它加密数据。

> 记忆：**CA 就像公证处**，证书就像公证书——有了它，"你说你是谁"才有人信。

## Q3 HTTPS 握手过程（TLS 1.2 RSA 四次握手）

> 完整讲解见《02_HTTP基础.md》Q14，这里给压缩版流程，方便复习。

```
客户端                                  服务器
  │  ① ClientHello（版本+随机数+密码套件）   │
  ├──────────────────────────────────────→│
  │  ② ServerHello + 数字证书              │
  │←──────────────────────────────────────┤
  │  ③ 验证证书 → 生成 pre-master key       │
  │    用服务器公钥加密发送 + 握手结束       │
  ├──────────────────────────────────────→│
  │  ④ 算法变更通知 + 握手结束通知          │
  │←──────────────────────────────────────┤
  │  双方各自用 3 个随机数算出同一个会话密钥    │
  │  之后用会话密钥加密传输 HTTP 内容         │
```

**三个随机数**：Client Random（客户端给）+ Server Random（服务器给）+ pre-master key（客户端生成，公钥加密传输）→ 三者作为原料，双方算出同一个**会话密钥**。

**面试追问点：**

1. 为什么第 3 次握手的 pre-master key 用非对称加密传输？（公钥加密只有私钥能解，保证只有真服务器能拿到）
2. 为什么正式通信不用非对称加密？（太慢，对称加密效率高）
3. TLS 1.3 有什么变化？（移除 RSA、1-RTT、支持 0-RTT 恢复——RTT 含义详见《09》Q3 追问）

## Q4 HTTPS 如何防中间人攻击？

### 一句话答案

**身份校验（证书）让冒牌服务器现形；私钥只有真服务器有，中间人无法解密加密数据。**

### 大白话讲解

中间人想两头骗，必须同时做到两件事，而每件都做不到：

1. **冒充服务器骗客户端**：需要向客户端出示证书 → 客户端验证 CA 签名/有效期/域名 → 中间人的假证书验证失败，浏览器报警中止。
2. **冒充客户端骗服务器**：客户端发出的加密数据（pre-master key）是用真服务器的公钥加密的 → 只有真服务器的私钥能解开 → 中间人就算截获也解不开，更别说继续伪装通信。

> 一句话：**证书证明"你是谁"，私钥保证"只有你能解密"。两个都没有，中间人寸步难行。**

## 本单元小结

| 概念 | 一句话记住 |
| --- | --- |
| 对称加密 | 一把钥匙，快，但钥匙难送 |
| 非对称加密 | 公钥加密私钥解，钥匙好送，但慢 |
| 混合加密 | 非对称商量钥匙，对称传输内容 |
| CA / 证书 | 公证处 + 公证书，证明"你是谁" |
| 会话密钥 | 三个随机数算出的临时对称密钥 |
| 防中间人 | 证书验身份 + 私钥保解密 |
