# 03 进程间通信（IPC）

本章覆盖：进程间通信的六种方式（管道、消息队列、共享内存、信号、信号量、socket）、匿名管道 vs 命名管道、信号 vs 信号量、共享内存的实现、线程间通信方式。

> 建议先读 02 章理解进程和线程的区别，再回来读本章。

---

## 1. 进程间通信有哪些方式？

### 一句话回答
Linux 内核提供了 **6 种**进程间通信（IPC）方式：**管道、消息队列、共享内存、信号、信号量、socket**。按"成本"排序：共享内存最快（直接访问）、管道/消息队列要过内核、socket 用于跨主机。

### 六种方式逐个讲

**① 管道（Pipe）**
- 最简单的方式，分**匿名管道**和**命名管道**两种
- 数据是**无格式的流**，大小受限，**单向**通信
- 数据缓存在**内核**中，遵循**先进先出（FIFO）**原则，不支持 lseek 之类的定位操作
- 类比：一根水管，水只能从一端流向另一端

**② 消息队列（Message Queue）**
- 保存在内核的"**消息链表**"
- 消息体是**用户自定义的数据类型**，解决了管道"无格式字节流"的问题
- 接收方必须与发送方的消息体类型一致才能正确读取
- 缺点：**每次读写都要经过用户态与内核态的拷贝**，速度不是最及时的

**③ 共享内存（Shared Memory）**
- 直接分配一块**共享空间**，每个进程都可以直接访问，像访问自己的空间一样
- **不需要陷入内核态或系统调用**，速度极快，享有"**最快的进程间通信方式**"之名
- 缺点：多进程竞争同一共享资源会造成**数据错乱**，需要信号量保护

**④ 信号（Signal）**
- **异步通信机制**，在内核和进程之间直接交互
- 内核可用信号通知用户空间进程发生了系统事件
- 来源：硬件（如键盘 Ctrl+C）和软件（如 kill 命令）
- 进程有三种响应方式：**执行默认操作、捕捉信号、忽略信号**
- 有两个信号**无法捕捉和忽略**：SIGKILL 和 SIGSTOP（保证任何时候都能结束或停止进程）

**⑤ 信号量（Semaphore）**
- 一个**计数器**，表示资源的个数，用于**互斥访问和进程同步**
- 通过两个原子操作控制：**P 操作**（减 1，可能阻塞）和 **V 操作**（加 1，唤醒等待者）
- 类比：停车场入口的计数器——进去一个减 1，出来一个加 1，满了就等在门口

**⑥ Socket**
- 前五种都只能在同一台主机内通信，**跨主机的进程通信必须用 Socket**
- Socket 也能用于本地主机进程间通信
- 三种常见类型：**TCP** 通信、**UDP** 通信、本地进程间通信

### 记忆表

| 方式 | 通信方向 | 是否跨主机 | 速度 | 特点 |
|------|----------|-----------|------|------|
| 管道 | 单向 | 否 | 慢 | 最简单，无格式流 |
| 消息队列 | 双向 | 否 | 慢 | 有格式消息体 |
| 共享内存 | 双向 | 否 | **最快** | 直接访问，需信号量配合 |
| 信号 | 单向（通知） | 否 | 快 | 异步事件通知 |
| 信号量 | —— | 否 | 快 | 用于同步互斥，不是传数据 |
| Socket | 双向 | **是** | 中 | 唯一能跨主机的 |

## 2. 管道有几种方式？

### 一句话回答
管道有两种：**匿名管道**（只能用于父子等有亲缘关系的进程，通过 pipe 系统调用创建）和**命名管道**（基于文件系统，无关进程也能通信）。

### 两种管道

**① 匿名管道**
- 只存在于**内存**中，是特殊文件，不在文件系统里
- shell 命令中的竖线 `|`（如 `ls | grep xxx`）就是匿名管道
- **单向**通信：数据只能在一个方向流动，要双向就得建两个管道
- **只能用于父子关系的进程**间通信
- 生命周期：随进程创建而建立，随进程终止而消失

**② 命名管道（FIFO）**
- 突破了匿名管道"只能亲缘进程通信"的限制
- 前提：在**文件系统**中创建一个类型为 `p` 的设备文件
- 毫无关系的进程都可以通过这个设备文件通信
- 数据同样缓存在内核，遵循先进先出，不支持 lseek

## 3. 信号和信号量有什么区别？

### 一句话回答
**信号是"通知事件"的异步机制，信号量是"控制访问"的同步互斥机制**。名字像，功能完全不同。

### 对比

| 对比项 | 信号（Signal） | 信号量（Semaphore） |
|--------|----------------|---------------------|
| 本质 | 处理**异步事件**的通知机制 | **同步互斥**的协调机制 |
| 用途 | 通知进程"有事件发生了" | 协调多个线程/进程正确使用公共资源 |
| 典型场景 | Ctrl+C 中断、kill 命令 | 控制同时访问共享资源的数量 |
| 类比 | 有人喊你"着火啦！" | 停车场门口的计数栏杆 |

## 4. 共享内存怎么实现的？

### 一句话回答
**拿出一块虚拟地址空间，映射到相同的物理内存上**。这样这个进程写入的东西，另一个进程马上就能看到，不用拷贝来拷贝去。

### 实现原理

```
进程A的虚拟地址空间 ──┐
                      ├──映射──▶ 同一块物理内存 ◀──映射──┐
进程B的虚拟地址空间 ──┘                                  ┘
```

- 两个进程各自的虚拟地址空间里，都映射到**同一块物理内存**
- 进程 A 写入 → 进程 B 立刻可见，**不需要任何拷贝、不需要陷入内核**
- 相比消息队列（每次读写都拷贝），速度大幅提升

### 注意事项

共享内存快是快，但**多进程同时写**会数据错乱，所以要配合**信号量**做互斥（同一时刻只允许一个进程访问）。

## 5. 线程间通信有什么方式？

### 一句话回答
Linux 提供了五种线程同步与通信机制：**互斥锁、读写锁、条件变量、自旋锁、信号量**。前三者加自旋锁主要解决**同步互斥**问题，条件变量和信号量更多用于**线程间的协作与通信**。

### 五种机制逐个讲

**① 互斥锁（Mutex）**
- 本质是一把锁：访问共享资源前加锁，访问完释放锁
- 加锁后，其他试图加锁的线程会**阻塞**，直到当前线程释放
- 释放时若有多个线程阻塞，它们都会变成可运行状态，先运行的那个拿到锁，其余继续等待

**② 条件变量（Condition Variables）**
- 实现"**等待 → 唤醒**"逻辑的常用方法
- 两个动作：一个线程**等待条件成立**而挂起；另一个线程**使条件成立**
- 使用时**必须与互斥锁结合**：改变条件状态前先锁住互斥量；`pthread_cond_wait` 把自己放入等待列表并解锁（这两个操作是**原子操作**）；返回时互斥量再次被锁住
- 典型场景：生产者-消费者模型（生产者满了就等，消费者空了就等）

**③ 自旋锁（Spinlock）**
- 通过 CPU 提供的 **CAS 函数**在**用户态**完成加锁解锁，**不会主动产生线程上下文切换**，比互斥锁快、开销小
- 加锁两个步骤（查看锁状态 → 置为当前线程持有）由 CAS 合并为一条**硬件级原子指令**
- 竞争失败时**忙等待**（while 循环，最好用 CPU 的 PAUSE 指令减少耗电）
- 适合临界区极短的场景（详见 05 章第 2 节）

**④ 信号量（Semaphores）**
- 表示**资源的数量**，是一个整型变量 `sem`
- 两个原子操作：**P 操作**（sem 减 1，若 < 0 则阻塞等待）和 **V 操作**（sem 加 1，若 ≤ 0 唤醒一个等待者）
- 可以是**命名**的（跨进程）或**无名**的（仅限当前进程内线程）

**⑤ 读写锁（Read-Write Locks）**
- 由"读锁"和"写锁"两部分构成：只读用读锁，修改用写锁
- **写锁未被持有时，多个线程可并发持有读锁**（读锁是共享锁）
- **写锁被持有时**，读锁获取被阻塞，其他写锁获取也被阻塞（写锁是独占锁）
- **读多写少的场景能发挥巨大优势**

### 记忆表

| 机制 | 解决什么问题 | 特点 |
|------|-------------|------|
| 互斥锁 | 共享资源互斥访问 | 竞争时阻塞（线程切换） |
| 自旋锁 | 共享资源互斥访问 | 竞争时忙等待（不切换） |
| 读写锁 | 读多写少的互斥 | 读并发、写独占 |
| 条件变量 | 等待-唤醒协作 | 必须和互斥锁搭配 |
| 信号量 | 资源数量控制/同步 | 计数器 + P/V 操作 |
