# 03 设计模式与代码优化

本章覆盖：干掉 if...else 的八种方法（策略、表驱动、枚举、工厂、多态、卫语句、Optional、函数式）及代码示例；项目中常用的八种设计模式（单例、工厂、策略、模板方法、观察者、代理、责任链、建造者）的意图、场景与代码示意。

---

## 1. 干掉 if...else，你有几种方法？

### 一句话回答
至少有八种：**策略模式、表驱动（查表法）、枚举、工厂模式、多态、卫语句提前返回、Optional、函数式**——每种都有适用场景，核心思路都是"把分支判断从业务代码里挪走"。

### 展开讲

**为什么要干掉 if...else**：分支一多，代码变成"面条"，改一个分支怕碰坏其他分支，测试要覆盖的分支组合指数级增长。但注意：**不是所有 if...else 都要干掉**，两三个简单分支直接写反而更清晰，过度设计也是坏味道。

**方法一：策略模式（最主流）**
把每种分支的算法封装成独立策略类，调用方只依赖接口。

```java
interface PayStrategy {
    void pay(double amount);
}
class AlipayStrategy implements PayStrategy {
    public void pay(double amount) { System.out.println("支付宝支付 " + amount); }
}
class WechatStrategy implements PayStrategy {
    public void pay(double amount) { System.out.println("微信支付 " + amount); }
}
// 使用：不再写 if(type==1)...
PayStrategy strategy = getStrategy("alipay"); // 从工厂/Map 拿
strategy.pay(100);
```

**方法二：表驱动（查表法）**
把"条件 → 行为"的对应关系放进一张表（Map、数组、字典），用查表代替判断。适合逻辑表达模式固定的场景。

```java
Map<String, Handler> table = new HashMap<>();
table.put("A", new HandlerA());
table.put("B", new HandlerB());
table.put("C", new HandlerC());
// 原来的 if...else if...else 变成一行
table.getOrDefault(type, defaultHandler).handle();
```

**方法三：枚举**
把行为直接挂到枚举上，分支变成"取枚举、调方法"，Java 枚举天然带类型安全，比魔法数字强。

```java
enum OrderStatus {
    PENDING { void handle() { System.out.println("待支付"); } },
    PAID    { void handle() { System.out.println("已支付"); } },
    SHIPPED { void handle() { System.out.println("已发货"); } };
    abstract void handle();
}
// 使用
OrderStatus.valueOf(statusStr).handle();
```

**方法四：工厂模式**
if...else 常常出现在"根据类型创建对象"的地方，把创建逻辑收进工厂，调用方只传类型。

```java
class PayFactory {
    static PayStrategy create(String type) {
        switch (type) {           // 创建逻辑集中在这，业务方不再散落 if
            case "alipay": return new AlipayStrategy();
            case "wechat": return new WechatStrategy();
            default: throw new IllegalArgumentException("未知支付方式");
        }
    }
}
```

**方法五：多态（面向对象基本功）**
让对象自己"知道自己该怎么处理"，替代对类型做判断。本质是"把 if 发给对象"。

```java
// 坏味道：if (shape instanceof Circle) 画圆; else if (instanceof Square) 画方...
// 好写法：每个形状自己实现 draw()
class Circle extends Shape { void draw() { /* 画圆 */ } }
class Square extends Shape { void draw() { /* 画方 */ } }
shape.draw(); // 多态分发，shape 是啥就画啥
```

**方法六：卫语句提前返回**
嵌套 if 是"箭头形代码"的元凶，把异常情况提前 return，主流程平铺，可读性大增。

```java
// 坏味道：层层嵌套
if (user != null) { if (user.isActive()) { if (order != null) { ... } } }
// 卫语句：条件不满足立刻返回
if (user == null) return;
if (!user.isActive()) return;
if (order == null) return;
// 主流程直接写，不需要缩进
```

**方法七：Optional（Java 8+）**
处理"可能为 null"的判断链，把 if (x != null) 换成函数式写法，避免空指针和嵌套判空。

```java
// 原来：if (user != null && user.getAddress() != null) { String c = user.getAddress().getCity(); }
String city = Optional.ofNullable(user)
        .map(User::getAddress)
        .map(Address::getCity)
        .orElse("未知");  // 链式取属性，任何一环为 null 都落到默认值
```

**方法八：函数式（策略的轻量版）**
分支少、逻辑简单时，用 Map 存"类型 → lambda"，比建一堆类更轻。

```java
Map<String, Function<Integer, Integer>> calc = Map.of(
        "add", n -> n + 1,
        "mul", n -> n * 2,
        "pow", n -> n * n
);
calc.getOrDefault(op, n -> n).apply(5);
```

### 比喻
if...else 堆砌像**一个人站在路口举着指示牌挨个问路**：岔路一多，牌子和人都疯了。各种方法像**给每条路装上自动导航**：问一句"去哪"，导航（查表、策略、多态）自己把路带出来，问路人（调用方）永远只说一句话。

## 2. 你项目用过哪些设计模式？

### 一句话回答
项目里最常用的八种：**单例、工厂、策略、模板方法、观察者、代理、责任链、建造者**——面试这样答：每个模式说"解决什么问题 + 我在哪用过 + 一句话原理"，比背定义强十倍。

### 展开讲

**① 单例模式**
意图：全局只允许一个实例（连接池、配置中心、日志器），避免重复创建浪费资源。
项目例子：数据库连接池、Spring 容器里默认的 Bean 就是单例。
原理：私有构造 + 静态方法返回唯一实例，并发安全的写法用双重检查锁或枚举。

```java
class ConfigManager {
    private static volatile ConfigManager instance;
    private ConfigManager() {}
    public static ConfigManager getInstance() {
        if (instance == null) {
            synchronized (ConfigManager.class) {
                if (instance == null) instance = new ConfigManager();
            }
        }
        return instance;
    }
}
```

**② 工厂模式**
意图：把"创建哪个对象"的决策集中起来，调用方不直接 new，解耦创建和使用。
项目例子：Spring IoC 容器就是工厂——`getBean("xxx")` 按名字给你对象；支付模块按渠道创建不同支付客户端。
原理：一个工厂方法根据参数返回不同子类对象。

```java
// 上面第 1 节的 PayFactory 就是典型：type 传入，返回对应策略对象
```

**③ 策略模式**
意图：一组算法可以互相替换，行为变化不修改调用方代码。
项目例子：优惠券计算（满减、折扣、免邮各是一个策略，新加一种券只加一个类）；登录方式（密码、验证码、第三方）。
原理：接口 + 多个实现类 + 运行时选择，配合工厂或 Map 消除 if。

```java
interface Discount { double calc(double price); }
class FullReduce implements Discount { public double calc(double p) { return p >= 100 ? p - 20 : p; } }
class PercentDiscount implements Discount { public double calc(double p) { return p * 0.8; } }
// 使用：discount.calc(price)，换成哪种券就传哪个策略
```

**④ 模板方法模式**
意图：把算法的骨架固定下来，把变化的步骤留给子类实现——"流程我定，细节你来"。
项目例子：下单流程（校验 → 扣库存 → 扣款 → 发通知，其中扣款方式各渠道不同）；数据导入（读文件 → 校验 → 入库，解析格式各不同）。
原理：父类定义模板方法（final，按顺序调抽象方法），子类只实现抽象步骤。

```java
abstract class OrderProcessor {
    final void process() {           // 骨架固定，不可重写
        validate();
        deduct();
        notifyUser();
    }
    abstract void validate();        // 子类各自实现
    abstract void deduct();
    void notifyUser() { /* 默认实现 */ }
}
```

**⑤ 观察者模式**
意图：一个对象状态变化时，自动通知所有依赖它的对象，解耦"发布者"和"订阅者"。
项目例子：订单状态变更后，同时触发发短信、更新库存、写日志——订单服务不需要知道这些模块存在；消息队列（Kafka）本质就是观察者的分布式版。
原理：被观察者维护订阅者列表，状态变了逐个调用订阅者的更新方法。

```java
interface Observer { void update(String event); }
class SmsNotifier implements Observer { public void update(String e) { System.out.println("发短信:" + e); } }
class OrderSubject {
    private List<Observer> observers = new ArrayList<>();
    void register(Observer o) { observers.add(o); }
    void statusChanged(String status) { observers.forEach(o -> o.update(status)); }
}
// 使用：new OrderSubject() 注册两个观察者，状态一变全部自动触发
```

**⑥ 代理模式**
意图：不直接访问目标对象，通过代理加一层控制——权限校验、日志、延迟加载、RPC。
项目例子：Spring AOP 就是动态代理（事务注解 @Transactional 就是代理帮你开事务提交回滚）；Nginx 反向代理。
原理：代理类和目标类实现同一接口，调用方访问代理，代理在调用前后插入增强逻辑。

```java
class UserServiceProxy implements UserService {   // 和真实类同接口
    private UserService target;                    // 持有真实对象
    public void getUser() {
        System.out.println("记录日志");              // 调用前增强
        target.getUser();
        System.out.println("统计耗时");              // 调用后增强
    }
}
```

**⑦ 责任链模式**
意图：多个处理器串成一条链，每个处理器决定"自己处理还是传给下一个"，避免在调用方堆 if。
项目例子：审批流（组长 → 经理 → 老板逐级审批）；网关过滤器（鉴权 → 限流 → 黑白名单）；Java 的过滤器 FilterChain。
原理：每个处理器持有下一个处理器的引用，处理不了就 `chain.doNext()`。

```java
abstract class Handler {
    protected Handler next;
    void setNext(Handler h) { this.next = h; }
    abstract void handle(Request req);
}
class AuthHandler extends Handler {
    void handle(Request req) {
        if (req.hasToken()) next.handle(req);   // 通过就传下去
        else System.out.println("未登录，拦截");
    }
}
// 链式组装：auth -> rateLimit -> business
```

**⑧ 建造者模式**
意图：对象的字段很多、构造参数太长，用"一步步设置字段，最后 build"的方式创建，防止漏传参数、参数顺序错。
项目例子：Lombok 的 @Builder；OkHttp 的 Request.Builder；配置对象、DTO 构建。
原理：一个 Builder 类提供 setter 风格方法，全部设完再 build 出目标对象。

```java
User user = User.builder()
        .name("张三")
        .age(25)
        .email("zs@example.com")
        .build();
// 对比：new User("张三", 25, "zs@example.com", null, null, ...) 十来个参数谁记得住
```

**八种模式一句话速记（面试版）**：单例管"只一个"，工厂管"谁来造"，策略管"换算法"，模板管"定流程"，观察者管"发通知"，代理管"加拦截"，责任链管"排队处理"，建造者管"慢慢拼对象"。

### 对比表

| 模式 | 类型 | 解决什么问题 | 项目里的例子 | 一句话原理 |
|------|------|-------------|-------------|-----------|
| 单例 | 创建型 | 全局只一个实例 | 连接池、Spring Bean | 私有构造 + 静态方法 |
| 工厂 | 创建型 | 创建逻辑集中 | Spring IoC、支付渠道 | 传类型返回对象 |
| 策略 | 行为型 | 算法可替换 | 优惠券、登录方式 | 接口 + 多实现 + 运行时选 |
| 模板方法 | 行为型 | 骨架固定细节可变 | 下单流程、数据导入 | 父类定流程子类补步骤 |
| 观察者 | 行为型 | 状态变化自动通知 | 订单通知、消息队列 | 注册订阅者逐个回调 |
| 代理 | 结构型 | 调用前加增强 | Spring AOP、事务注解 | 同接口包一层 |
| 责任链 | 行为型 | 处理逻辑排队 | 审批流、网关过滤器 | 处理不了传给下一个 |
| 建造者 | 创建型 | 参数太多难构造 | Lombok @Builder | 链式设值最后 build |

### 比喻
设计模式像**装修房子的标准图纸**：单例是全屋只装一台总电闸，工厂是找装修公司（告诉需求就给你装好），策略是开关面板（一个面板换不同开关），模板方法是施工流程（流程固定、材料你定），观察者是烟雾报警器（一处冒烟全屋响铃），代理是物业门禁（进门先过安检），责任链是层层审批（先组长后经理），建造者是用清单勾选装修项（勾完一起开工）。
