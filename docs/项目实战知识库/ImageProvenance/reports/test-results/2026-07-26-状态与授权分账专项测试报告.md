## 四、发现的问题与处理

### 问题 1(已修复):c2patool 0.27+ 下所有签名判 Invalid —— 前向兼容缺陷

- 现象:沙箱首轮 E2E 14/15,prepare 返回 c2paStatus=invalid。
- 根因:C2PA 2.1 规范(c2patool 0.27 起强制)要求 `c2pa.created` 动作必须携带 `digitalSourceType`;缺失则 `assertion.action.malformed` → 整体 Invalid。本机 0.26.68 宽容通过,因此此前未暴露。
- 影响:一旦升级 c2patool 或在装有新版工具的机器上演示,签名/验证闭环全线失效。
- 修复:`backend/internal/c2pa/manifest.go` 为 c2pa.created 增加 `digitalSourceType = http://cv.iptc.org/newscodes/digitalsourcetype/digitalArt`(IPTC 词表"人类用数字工具创作");新旧版本均接受,修复后 0.27.3 实测 Trusted,E2E 回到 15/15。
- 论文口径:可写入第 4 章踩坑记录——跨版本规范演进(宽容→严格)是内容凭证生态的现实约束。

### 问题 2(已修复):授权管理页设置分账后无任何回显

- 现象:LicenseView 点"设置分账(上链)"成功后,页面上没有任何地方能看到已生效规则;刷新/重进也无从查询,只能靠链上手查。
- 修复:
  - `web/src/composables/useContracts.js` 新增 `royaltyReadContract`——走只读 provider,不触发 eth_requestAccounts(未连钱包也能读);
  - `web/src/views/LicenseView.vue` 选中作品时调用 `hasRule/getRoyaltyRule` 回显"当前生效规则:创作者 x% / 平台 y%(平台方地址、更新时间)",未设置显示占位说明,设置成功后立即刷新。
- 验证:合约读取路径已由本轮 3.3 用例覆盖;Vue 改动通过语法校验,**本机请跑一次 `npm run build`(或直接起 dev server 点一遍)做最终确认**——沙箱无 npm 无法执行 vite 构建。

## 六、第二轮补齐:链上 Disputed/Revoked 状态镜像到链下与前端

按用户要求补齐原留意项,形成完整闭环:**作者在授权管理页标记状态(上链)→ RegistryV2 发出 WorkStatusChanged → 监听器镜像入 SQLite → 列表/详情/验证接口透出 chainStatus → 前端徽标与警示**。

实现要点:

| 层 | 改动 |
|---|---|
| 数据 | works 表新增 `chain_status INTEGER DEFAULT 0`;旧库启动时自动 ALTER 迁移(pragma_table_info 防重入),沙箱内用既有数据库实测迁移成功、历史作品默认 0 |
| 监听器 | listener 新增 `WorkStatusChanged` 分支:topics[1]=workId,data=status(uint8),`SetChainStatus` 按 chain_work_id 更新;沿用断点续扫游标 |
| API | Work JSON 新增 `chainStatus`(0 Active / 1 Disputed / 2 Revoked);链上反查回退路径(getWorkByHash)同样透出 |
| 前端·授权管理 | 新增"作品链上状态"卡片:状态徽标 + 三个作者操作按钮(标记争议 / 撤销确权声明 / 恢复正常,合约侧仅作者可调用,revert 翻译沿用);下拉列表对非 Active 作品加 ⚠ 标记 |
| 前端·来源验证 | 文件验证结果与按 ID 查询页:非 Active 作品显示红色警示条("作者已标记争议/已撤销声明"),表格增加"链上状态"行——验证方在引用前能看到权属风险 |

验证(全部通过,计入总数):镜像 5 用例(初始 0 / Disputed / 验证接口透出 / Revoked / 恢复 Active,同步延迟均 ≤3s)+ 原有 12 个状态用例回归 + E2E 15 用例回归。`test-license-flow-extended.mjs` 已同步加入 1b 镜像用例。

附:测试脚本可重跑性发现——`evm_increaseTime` 会让链时间永久领先墙钟,凡用 `Date.now()` 计算授权有效期的脚本(含 `test-license-flow.mjs` 第 100 行)在**同一条长活节点上第二次运行**会误触 "invalid expiry"(合约行为正确,是脚本时基问题);每次重启 hardhat 则无影响。`test-license-flow-extended.mjs` 已改用链上区块时间做基准,主脚本如需长活节点重跑,可同样把 `Math.floor(Date.now() / 1000)` 换成 `(await provider.getBlock('latest')).timestamp`。
