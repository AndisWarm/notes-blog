# 01 项目是什么：用大白话讲清楚

## 1.1 一句话版本

> 这是一个**数字照片/画作的"出生证明"系统**——创作者上传作品，系统给它办一张不可伪造的"身份证"，以后无论图片被转发多少次、被谁盗用，都能证明"原作者是谁、什么时候创作的、有没有被改过"。

## 1.2 三分钟版本（给完全不懂技术的人）

### 问题：网上盗图太容易，维权太难

想象你是一位摄影师，拍了一张很好的照片发到网上：

1. **别人右键保存**，说这是他拍的，发到自己的账号上
2. **你去投诉**，平台问："你怎么证明这是你拍的？"
3. 你说："我电脑里有原文件！" 对方说："我也可以有原文件，我可以说我是先拍的。"
4. **你拿不出铁证**——因为数码照片可以复制，修改时间可以改，EXIF 信息可以删

这就是**数字内容确权难**的问题：看不见摸不着的东西，怎么证明"是我的"？

### 传统做法的问题

| 传统方法 | 为什么不够好 |
|----------|-------------|
| 发到朋友圈/微博，用发布时间当证据 | 平台可以改数据，而且你发之前可能已经被人偷了 |
| 去版权局登记 | 流程慢、花钱多、只适合重大作品 |
| 加水印 | 水印可以被裁掉、被 PS 掉 |
| 找公证处 | 贵、麻烦、要线下跑 |

### 这个项目的做法：三重技术保险

**第一重：给照片算"指纹"（哈希）**

就像每个人都有指纹一样，每张照片也可以算出一个**唯一的数字指纹**（叫哈希值）。哪怕照片只改了一个像素，指纹就完全不同。

这个指纹是一串 64 位的字母数字，比如：`a591a6d40bf420404a011733cfb7b190d62c65bf0bcda32b57b277d9ad9f146e`

**第二重：把指纹刻到"公共黑板"上（区块链）**

区块链是一个**全世界很多人共同维护的公开账本**，一旦写上去就改不了、删不掉。把照片的指纹写上去，就等于向全世界宣布："这个时间点，我拥有这张照片。"

关键是：**用你自己的"电子印章"（数字钱包）去写**，而不是让平台替你写。这样证明的就是"你"拥有，而不是"平台"拥有。

**第三重：把证明嵌入照片本身（C2PA）**

C2PA 是一个国际标准（Adobe、微软、BBC 都在用），它可以把"创作者是谁、什么时候拍的"这些信息**加密签名后嵌入图片文件内部**。以后这张照片无论传到哪里，信息都跟着走，而且改不了——一改签名就失效。

### 总结：三层保护

```
第一层：哈希指纹 → 证明"内容没被改过"
第二层：区块链 → 证明"某个时间点已经存在"且"是你发布的"
第三层：C2PA 嵌入 → 证明"无论传到哪里，身份信息跟着走"
```

## 1.3 技术版一句话（给面试官）

> 基于 **区块链（以太坊）** 和 **C2PA 内容凭证标准** 的图像确权与溯源系统：创作者通过自有钱包将作品哈希三元组上链（链上 author = 创作者地址，后端零私钥），结合 **IPFS 分布式存储**、**自建 CA 信任链**、**事件驱动链下索引** 实现四态来源验证、授权管理与分账规则。

## 1.4 项目名拆解

| 名词 | 含义 |
|------|------|
| **Image** | 图像/照片/数字图片 |
| **Provenance** | 来源、出处、 provenance（艺术品收藏界的"流传有序"） |
| **V2** | 第二版——第一版有设计缺陷，这是重构后的版本 |

"Provenance" 这个词在艺术界很重要：一幅画如果 provenance 清晰（流传有序），就能证明是真迹；数字图片也需要同样的东西。

## 1.5 为什么叫 V2？（面试必问）

V1（一期）有四个致命缺陷，V2（二期）全部修复：

| 缺陷 | V1 的做法 | V2 的修复 | 后果 |
|------|-----------|-----------|------|
| **身份失真** | 后端服务器用自己的私钥代签所有交易 | 创作者用自己的钱包签名，链上 author = 创作者 | V1 链上所有作品"作者"都是同一个服务器地址，确权系统里"作者"是假的 |
| **哈希语义不清** | 只存一个哈希，分不清是原图还是签名后的图 | 哈希三元组：原图哈希 + 签名版图哈希 + 声明哈希 | V1 验证时"传原图查不到、传签名图才查到"（或反过来） |
| **权限形同虚设** | 任何人可以给任何作品发授权、改分账 | 所有操作强制校验 `authorOf == msg.sender` | V1 里"小偷可以给别人的照片发授权" |
| **C2PA 不可信** | 用开发证书签名，验证显示"untrusted" | 自建符合 C2PA 标准的 CA，验证显示"Trusted" | V1 的"内容凭证"没有说服力 |

**面试话术**：
> "V1 证明了技术可行，但架构审查发现四个结构性缺陷。最致命的是后端代签——链上 author 恒为服务器地址，确权系统里'作者'字段是假的。V2 的核心就是把'确权'做实：让创作者自己控制私钥，链上记录真实反映创作者身份。"

## 1.6 项目边界（诚实声明，面试加分项）

这个项目**明确不做什么**，体现工程判断力：

| 不做 | 为什么 | 面试话术 |
|------|--------|----------|
| AI 生成检测 | 技术边界：现有技术无法可靠检测 AI 图 | "我聚焦在'确权'而非'辨伪'，这是两个不同的问题" |
| 相似图像检索 | pHash 只做链下预警，不做链上检索 | "相似检索是另一个大课题，我用 pHash 做轻量预警，但不上链" |
| 真实司法链对接 | 用 MockJudicialAnchor 演示调用形态 | "我预留了接口形态，但明确声明不接真实司法链，保持研究边界" |
| 代币/真实支付 | RoyaltyV2 只记录分账比例，不处理钱 | "分账规则上链，但支付逻辑不在范围内，避免金融合规风险" |
| 公链主网部署 | 只在本地链和测试网运行 | "系统架构链无关，但部署主网涉及真实资产，属于下一步" |

**关键术语：GIGO 边界**
> Garbage In, Garbage Out（垃圾进，垃圾出）——区块链只能保证"上链后不被篡改"，不能保证"上链前是真的"。如果创作者拿别人的照片去登记，系统无法阻止。这是所有区块链存证系统的共同边界，诚实承认是专业表现。

## 1.8 演示故事线（面试时讲这个）

> "假设摄影师甲拍了一张照片，用我的系统：
> 1. 上传 → 系统算出三个指纹，嵌入 C2PA 声明，存到 IPFS
> 2. 甲用自己的 MetaMask 钱包点一下，指纹上链——链上记录'甲是作者'
> 3. 乙想偷这张图，上传系统 → 系统提示'已存在'，拒绝重复登记
> 4. 乙把图改了一下再传 → 系统识别出'这是甲的签名版，但被改过了'
> 5. 甲可以给丙发授权：'允许你用这张图做商业用途，到 2027 年底'——这个授权也上链
> 6. 任何人拿到这张图，都能验证：是不是原图？有没有被改过？作者是谁？授权状态如何？"
