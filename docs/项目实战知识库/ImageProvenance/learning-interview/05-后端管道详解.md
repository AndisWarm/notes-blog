# 05 后端管道详解：十步流程与优雅降级

> 后端是全系统的"厨房"——重活都在这里做，但**不碰私钥**。

## 5.1 后端技术栈

| 组件 | 选型 | 理由 |
|------|------|------|
| 语言 | Go 1.25 | 编译快、部署简单、并发好 |
| 框架 | Gin | 轻量、中间件丰富、社区成熟 |
| 数据库 | SQLite (modernc.org/sqlite) | 纯 Go 免 CGO、单文件零运维、匹配单机演示 |
| 链交互 | go-ethereum | 官方库、功能完整 |
| C2PA | c2patool (外部进程) | 官方工具、避免 CGO 绑定 |
| 存储 | IPFS / 本地内容寻址 | 接口抽象，可替换 |

## 5.3 关键设计：后端与私钥的"绝缘"

### 代码证据

```go
// backend/internal/chain/client.go
// Client is a READ-ONLY chain client plus a calldata builder.
// V2 deliberately holds no private key: registration transactions
// are signed and sent by the creator's own wallet in the frontend.

func (c *Client) RegisterCalldata(...) (string, error) {
    data, err := c.RegistryABI.Pack("registerWork", ...)
    // 打包 calldata 不需要私钥！
    return hexutil.Encode(data), nil
}
```

### 三个证据点（面试时说）

1. **代码审查**：搜遍 backend/ 目录，没有任何私钥配置项
2. **健康检查**：`/api/health` 返回 `signerMode: "creator-wallet"`
3. **链上数据**：所有作品的 author 都是用户地址，不是服务器地址

## 5.4 优雅降级清单

| 依赖 | 挂了会怎样 | 代码位置 | 设计意图 |
|------|-----------|---------|---------|
| c2patool | c2paStatus=unavailable，登记继续 | buildC2PAAssets 开头 CheckTool | C2PA 是增强项，不是核心 |
| IPFS | 自动落本地内容寻址存储 | router.go 按 STORAGE_MODE 选 Store 实现 | 存储层抽象，IPFS 可替换 |
| TSA | 跳过时间戳，不阻塞 | `if err == nil` 才写入 | 外部服务不可靠，本地优先 |
| 链未部署 | prepare 可用，无 txRequest | `if h.chain != nil` | 纯链下模式也能演示 |
| 中文字体缺失 | PDF 回退 ASCII | report/pdf.go | 证据报告仍可用 |

**面试话术**：
> "每个外部依赖都有降级路径。这是后端设计的'优雅降级'原则——核心功能不依赖任何单点。c2patool 挂了，登记还能继续；IPFS 没起，自动落本地。降级优先级排序是后端设计的常见考题。"

## 5.5 验证四态的实现

```go
// VerifyFile 函数判定顺序
```

```go
// 1. 计算上传文件 SHA-256
computed := hash.ReaderSHA256(...)

// 2. 链下索引三级查找
if work, tier, err := h.repo.FindByAnyHash(computed); err == nil && tier != domain.MatchManifestOnly {
    return 态1或态2
}

// 3. 链上反查兜底（数据库丢了也能验）
if onchain, err := h.chain.GetWorkByHash(ctx, computed); err == nil && onchain != nil {
    return 态1或态2 (source="chain")
}

// 4. 提取 C2PA manifest 里的 identifier 反查
if result := h.manifestOnlyCheck(...); result != nil {
    return 态3（签名后被篡改）
}

// 5. 全部落空
return 态4（无记录）
```

**关键细节**：
- DB 命中 manifest-only 级别时**不直接返回**，继续走完整 manifest 提取流程
- 链上反查路径的 `source` 字段返回 `"chain"`，前端显示"链上反查（本地索引未命中）"

## 5.6 性能数据（timingsMs）

实测单次 prepare：

| 步骤 | 耗时 | 占比 |
|------|------|------|
| 哈希 + manifest | 50ms | 6% |
| pHash | 30ms | 4% |
| **C2PA 签名** | **250ms** | **31%** |
| IPFS 存储 | 5ms | 0.6% |
| TSA 时间戳 | 450ms | 56% |
| 数据库 | 14ms | 2% |
| **总计** | **799ms** | 100% |

**优化方向**（面试追问）：
- C2PA 250ms：c2patool 是外部进程调用，可改为工作池复用
- TSA 450ms：可并行化或批量处理
- SQLite 单写：`SetMaxOpenConns(1)` 串行化，多实例需换 PostgreSQL

## 5.7 仓储层设计

### 三表结构

```sql
-- works 表：作品索引
CREATE TABLE works (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    chain_work_id INTEGER DEFAULT 0,  -- 0 = 未上链
    original_hash TEXT UNIQUE,        -- 三级查找第一级
    signed_hash TEXT,                 -- 第二级
    manifest_hash TEXT,               -- 第三级
    status TEXT DEFAULT 'UPLOADED',   -- UPLOADED/SIGNED/PINNED/PENDING_ANCHOR/ANCHORED
    chain_status INTEGER DEFAULT 0,   -- 链上状态镜像
    -- ... 其他字段
);

-- licenses 表：授权镜像（事件驱动）
CREATE TABLE licenses (
    chain_license_id INTEGER PRIMARY KEY,
    chain_work_id INTEGER,
    licensor TEXT,
    licensee TEXT,
    revoked INTEGER DEFAULT 0,
    -- ...
);

-- chain_cursor 表：事件监听游标
CREATE TABLE chain_cursor (
    name TEXT PRIMARY KEY,
    last_block INTEGER
);
```

### 迁移策略

```go
// 防重入 ALTER（SQLite 无 ADD COLUMN IF NOT EXISTS）
var n int
db.QueryRow(`SELECT COUNT(*) FROM pragma_table_info('works') WHERE name = 'chain_status'`).Scan(&n)
if n == 0 {
    db.Exec(`ALTER TABLE works ADD COLUMN chain_status INTEGER DEFAULT 0`)
}
```
