# 02 启动与健康检查

## 五个服务,按序五个窗口

| # | 命令 | 端口 | 成功标志 |
|---|---|---|---|
| 1 | `powershell -NoProfile -ExecutionPolicy Bypass -File scripts\dev\start-hardhat.ps1` | 8545 | `Started HTTP and WebSocket JSON-RPC server` + 20 个测试账户列表 |
| 2 | `powershell -NoProfile -ExecutionPolicy Bypass -File scripts\dev\deploy-contracts.ps1` | — | 打印四合约地址,写入 `contracts/deployments/localhost.json` |
| 3 | `powershell -NoProfile -ExecutionPolicy Bypass -File scripts\dev\start-ipfs.ps1`(可选) | 5101 / 8181 | `Daemon is ready`;跳过则后端自动用本地存储 |
| 4 | `powershell -NoProfile -ExecutionPolicy Bypass -File scripts\dev\start-backend.ps1` | 8080 | `Starting V2 backend ... (signer mode: creator-wallet)` + `chain listener started` |
| 5 | `powershell -NoProfile -ExecutionPolicy Bypass -File scripts\dev\start-web.ps1` | 5173 | Vite `ready`,浏览器可打开 |

> 顺序原因:合约部署要连链(1→2);后端启动时读部署文件与 ABI(2→4);
> 前端从后端 `/api/chain/info` 拉合约地址(4→5)。

## 健康检查

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\dev\check-health.ps1
# 或手动:
curl http://127.0.0.1:8080/api/health
```

`/api/health` 关键字段:

| 字段 | 期望值 | 含义 |
|---|---|---|
| `status` | `ok` | 后端存活 |
| `chainReady` / `chainId` | `true` / `31337` | 链可达且部署文件已加载 |
| `signerMode` | `creator-wallet` | 后端零私钥(V2 身份闭环标志) |
| `c2patool.available` | `true` | 签名工具可用(附版本号) |
| `c2paTrust` | `true` | trust anchor 已配置,签名可验为 Trusted |
| `storageBackend` | `ipfs` 或 `local` | 当前存储模式 |

## MetaMask 网络配置

前端右上角"连接 MetaMask"会自动请求切换/添加网络;手动添加参数:

| 项 | 值 |
|---|---|
| 网络名 | Hardhat Local |
| RPC URL | `http://127.0.0.1:8545` |
| Chain ID | `31337` |
| 货币符号 | ETH |

## 常见启动问题

| 现象 | 原因与处理 |
|---|---|
| 前端黄条"链信息不可用——请先启动 Hardhat 并部署合约" | 步骤 1/2 没做或后端在部署前启动;补做后重启后端 |
| 钱包余额 0,无法发交易 | 顶栏出现"领取测试币"按钮,点一下即充 10 测试 ETH(仅本地链;水龙头会自动补挖一个空块,余额立即可见) |
| MetaMask 交易一直 pending | 重启过 Hardhat 但没清 MetaMask nonce——设置 → 高级 → 清除活动与 nonce 数据 |
| 重启 Hardhat 后一切"消失" | 本地链数据在内存中,重启即清零:需重新 deploy(步骤 2)+ 重启后端;链下 SQLite 里的旧记录 chainWorkId 已失效,演示前建议直接删 `backend/data/index.db` 一起归零 |
| prepare 返回 500 且日志含 c2patool | 检查 `tools/ca/` 是否已生成证书(见 01 篇首次安装第 2 步) |
| 上传返回 400 "title is not valid UTF-8" | Windows curl 的 GBK 编码问题,用网页端上传 |
