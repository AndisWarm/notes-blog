# 03 演示:多账户登记、授权与分账

用三个角色把系统功能完整走一遍:**创作者甲**(登记作品、签发授权、设分账、标状态)、
**使用方乙**(接受授权,兼演越权攻击者)、**平台方**(只出现在分账规则里,不需要操作)。
全程只用浏览器 + MetaMask;5 分钟答辩压缩版见 [`../docs/06-演示脚本.md`](../docs/06-演示脚本.md)。

## 0. 账户准备(二选一)

**方式 A:导入 Hardhat 测试账户(推荐,开箱即有余额)**

MetaMask → 账户菜单 → 导入账户,粘贴私钥:

| 角色 | 私钥 | 地址 |
|---|---|---|
| 甲(创作者) | `0x59c6995e998f97a5a0044966f0945389dc9e86dae88c7a8412f4603b6b78690d` | `0x7099…79C8` |
| 乙(使用方) | `0x5de4111afa1a4b94908f83103eb1f1706367c2e68ca870fc3fb9a804cdab365a` | `0x3C44…93BC` |
| 平台方(可不导入,只用地址) | `0x7c852118294e51e653712a81e05800f419141751be58f605c371e15141b007a6` | `0x90F7…b906` |

> ⚠️ 这是 Hardhat 公开测试私钥,**全世界都知道**——只能在本地链上玩,绝不能在任何真实网络使用。

**方式 B:用你自己的 MetaMask 账户**

连接后顶栏会提示余额不足并出现**"领取测试币"**按钮,点击即到账 10 测试 ETH
(本地水龙头,仅 chainId 31337 生效;到账后余额直接显示,无需等待)。

## 1. 甲:登记作品上链(创作者页)

1. 右上角**连接 MetaMask**,切到甲账户(页面会自动请求切换到 Hardhat Local 网络)。
2. 选择图片文件(PNG/JPEG),填标题,如"风景写生·演示"。
3. 点 **① 生成声明与签名** —— 这一步全部在链下:
   - 结果卡片出现**三哈希**(originalHash / signedHash / manifestHash)与签名版 CID;
   - 徽标显示 **C2PA trusted**(自建 CA + trust anchor 验证通过);
   - 若与已登记图相似,会出现黄色 **pHash 相似预警**(仅提示,不拦截)。
4. 点 **② 钱包上链确权** → MetaMask 弹出交易 → 确认。
   - 绿色横幅显示区块号与交易哈希;
   - 数秒内(监听器 2s 轮询)作品列表状态从 `PENDING_ANCHOR` 翻为 **`ANCHORED`**;
   - **列表"作者地址"= 甲的钱包地址**——这是 V2 的核心:后端零私钥,谁签名谁是作者。
5. 演示防抢注(可选):同一张图再走一次 ① → 后端直接 409"该文件已注册过";
   即使拿旧 calldata 强发交易,合约也会以 `duplicate: original hash` 回滚。

## 2. 甲 → 乙:签发授权(授权管理页)

1. 保持甲账户,进入**授权管理**,下拉选中刚登记的作品。
2. "签发授权"卡片:被授权方填**乙的地址**,用途如"网页横幅 web-banner",有效期 30 天 → 点**签发授权(上链)** → MetaMask 确认。
3. 提示"授权已上链,等待事件同步…",约 3 秒后**已同步的授权记录**表格出现这条记录
   (授权 ID / 乙地址 / 用途 / 到期时间)——记录来自链上事件镜像,不是前端本地状态。
4. 再签一笔短期授权(如 1 天)给乙,演示同一作品多笔授权并存。
5. 撤销演示:对其中一笔点**撤销** → 确认 → 3 秒后该记录"有效期"列变为**已撤销**。
   链上 `isLicensed(作品, 乙)` 只要还有一笔未过期未撤销就仍为 true。

## 3. 乙:越权攻击演示(换账户)

MetaMask 切到**乙**账户(页面右上角地址变化),仍在授权管理页选同一作品:

| 攻击 | 结果 |
|---|---|
| 乙给自己"签发授权" | 红色提示:**合约拒绝:当前钱包不是该作品的链上作者(越权保护生效)** |
| 乙修改分账规则 | 同上,`not author` 回滚 |
| 乙点"标记争议/撤销声明" | 同上——状态标记也只有作者能做 |
| 乙撤销甲签发的授权 | 合约 `not licensor` 回滚 |

> 这组失败是演示重点:权限由 **LicenseV2/RoyaltyV2 → IRegistry.authorOf** 在链上强制,
> 不是前端判断——换任何客户端直接调合约也一样被拒。

## 4. 甲:分账规则(切回甲)

1. "分账规则"卡片首次显示**"该作品尚未设置分账规则(链上无记录)"**。
2. 平台方地址填 `0x90F7…b906`,创作者份额 8500(基点,总额 10000)→ **设置分账(上链)** → 确认。
3. 成功后卡片立即回显:**当前生效规则:创作者 85% / 平台 15%,平台方 0x90F7…(更新时间)**。
4. 把份额改成 9000 再设置一次 → 回显变 **90% / 10%**,演示规则可由作者更新覆盖。
5. 口径提醒:RoyaltyV2 只在链上记录比例,不做真实支付(研究边界)。

## 5. 甲:链上状态标记(争议 / 撤销声明)

1. "作品链上状态"卡片当前显示**正常**。点**标记争议(上链)** → 确认 → 约 3 秒后徽标变为
   **争议中**,作品下拉列表里该作品出现 ⚠ 前缀。
2. 切到**来源验证**页,按 ID 查询该作品:顶部出现红色警示
   **"作者已在链上将该作品标记为存在权属争议,引用前请自行核实"**。
3. 回授权管理点**恢复正常(上链)**,徽标复原。(**撤销确权声明**同理,警示文案不同;
   所有状态变更都是链上 `WorkStatusChanged` 事件 → 监听器镜像 → 前端,历史记录不删除。)

## 6. 任何人:来源验证四态(来源验证页,无需连钱包)

| 上传内容 | 预期结果 |
|---|---|
| 甲登记时的**原图** | 绿色 **原始文件**(originalHash 命中) |
| **签名分发版**(见下方获取方式) | 绿色 **官方签名分发版**(signedHash 命中) |
| 签名分发版**改动 1 字节** | 红色 **签名后被篡改**(内嵌 C2PA 声明指向登记作品,但字节不匹配;C2PA 校验 Invalid) |
| 任意无关图片 | 黄色 **无记录** |

签名分发版获取:IPFS 模式打开 `http://127.0.0.1:8181/ipfs/<签名版CID>`
(CID 在登记结果卡片里);本地存储模式在 `backend/data/objects/<CID>/` 目录下。

最后点**下载证据 PDF**:包含三哈希、作者地址、区块 + RFC3161 双时间戳与二维码,
扫码直达本验证页(`?workId=` 参数);这是"技术取证材料",不替代司法鉴定。

## 附:命令行(API)演示

```bash
# 上传登记(注意:Windows curl 发中文标题会被 400 拒绝——GBK 编码问题,中文标题请走网页)
curl -F "image=@demo.png" -F "title=demo-cli" -F "authorAddress=0x7099..." \
     http://127.0.0.1:8080/api/works/prepare
# 返回 txRequest{to,data} —— 由钱包/脚本签名发送,后端不代签

# 验证任意文件
curl -F "image=@somefile.png" http://127.0.0.1:8080/api/works/verify-file

# 水龙头(仅本地链)
curl -X POST -H "Content-Type: application/json" \
     -d '{"address":"0x你的地址"}' http://127.0.0.1:8080/api/chain/faucet

# 作品与授权记录
curl http://127.0.0.1:8080/api/works
curl http://127.0.0.1:8080/api/works/1
```
