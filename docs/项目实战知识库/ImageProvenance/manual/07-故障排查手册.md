# 07 故障排查手册

> 按**症状**索引,每条:根因 → 解法 → 原理出处。演示前夜请通读一遍;
> 启动顺序类问题先看 [`02-启动与健康检查.md`](02-启动与健康检查.md)。
> 万能复位手顺(本地链演示环境):关五窗口 → 删 `backend/data/index.db` →
> 依序重启五服务 → MetaMask 清除活动与 nonce 数据。

## A. 钱包与交易

| 症状 | 根因 | 解法 |
|---|---|---|
| 交易一直 pending,不弹确认或确认后无回执 | 重启过 Hardhat,MetaMask 记着旧 nonce | 设置→高级→清除活动与 nonce 数据(选中该账户) |
| 弹窗报 internal JSON-RPC error / cannot estimate gas | 交易会 revert(如非作者操作)或链没起 | 看页面红色提示的中文原因;确认 8545 存活 |
| 余额明明充了还是 0 | 充值走了别的网络/账户;或未出新块 | 确认 MetaMask 在 Hardhat Local + 正确账户;系统水龙头已自动补挖块,若手动 setBalance 需自行 evm_mine |
| "已在钱包中取消" | 用户点了拒绝 | 重新操作即可(前端对 user rejected 的翻译) |
| 连接钱包后 chainId 不是 31337 | 未切网络 | 前端会自动请求切换/添加;手动参数见 02 篇 |
| 换了自己的新账户,无法支付 gas | 新账户余额 0 | 顶栏"领取测试币"(仅本地链;测试网用公共水龙头) |

## B. 登记(prepare / 上链)

| 症状 | 根因 | 解法 |
|---|---|---|
| 400 `title is not valid UTF-8` | Windows curl 按 GBK 发中文表单 | 网页上传,或终端切 UTF-8(见 05 篇提醒) |
| 409 `already registered (xxx hash match)` | 同一文件(或其签名版/声明)已登记 | 预期行为=防重复;换文件;matchTier 指明撞哪层 |
| `c2paStatus: "unavailable: …"` 且无 txRequest | c2patool 路径错/不可执行 | 核对 `C2PATOOL_PATH`;`c2patool --version` 手测;health.c2patool 有诊断 |
| `c2paStatus: "valid-untrusted"` | 信任锚未配置或证书不匹配 | 核对 `C2PA_TRUST_ANCHORS` 指向 tools/ca/rootCA.pem;证书是否重新生成过而后端没重启 |
| `c2paStatus: "invalid"` | manifest 断言不合规——**升级 c2patool 后最常见**是缺 digitalSourceType(本项目已内置,若你改过 manifest.go 需保留该字段) | `c2patool <签名版> trust --trust_anchors …` 看 validation_results 里的失败码定位 |
| 500 `c2patool embed failed` | 证书/私钥路径失效(相对路径坑) | 路径必须绝对(config 启动时已 Abs);确认 tools/ca 三件套存在,首次需 `bash tools/ca/make-ca.sh` |
| 500 `pack calldata` | artifacts 与部署不匹配(改过合约没重新编译/部署) | contracts 重新 compile+deploy,重启后端 |
| 相似预警误报担忧 | pHash 对噪声/渐变类图敏感(病态输入) | 预警仅提示不拦截;原理见 learning/09 的 phash_probe 实验 |
| 点"② 钱包上链确权"无反应 | 未连接钱包 / prepare 未成功 / MetaMask 弹窗被浏览器拦截 | 按钮旁错误提示;检查浏览器扩展弹窗权限 |

## C. 授权 / 分账 / 状态标记

| 症状 | 根因 | 解法 |
|---|---|---|
| "合约拒绝:当前钱包不是该作品的链上作者" | 用非作者账户操作(演示攻击时是预期结果) | 切回作者账户 |
| 签发成功但记录迟迟不出现 | 监听器 2s 轮询 + 前端 3s 后刷新;若长期不出现,监听器可能没起 | 等 3–5s;查后端日志有无 `chain listener started` 与报错;游标是否推进 |
| 撤销后表格没变化 | 同上(事件镜像延迟) | 刷新;超 10s 查后端日志 |
| 分账回显"读取失败" | 未装 MetaMask(只读也需要 window.ethereum 作 provider) | 装插件;或用 harness/脚本读链核对 |
| 状态按钮点了没反应 | 未连接钱包(按钮 disabled) | 先连接 |
| revert 提示是英文原文 | 未收录进前端翻译表的 reason(如 already revoked) | 属预期;需要可在 LicenseView.revertReason 里加映射 |

## D. 验证与证据

| 症状 | 根因 | 解法 |
|---|---|---|
| 登记过的图验证却是"无记录" | 传的不是登记时的**原字节**(重存/截图/压缩都会变哈希),或改的是**原图**而非签名版 | 用登记时的原文件;区分见 learning/01 自测 4 |
| 想演示"签名后被篡改"却得到"无记录" | 篡改对象错了 | 必须改**签名分发版**(内嵌 manifest 幸存才可反查) |
| 验证显示 source=chain | 本地索引缺该记录(删过库/别处登记) | 非故障——链上反查兜底生效,反而是演示点 |
| PDF 中文变问号/缺失 | 未配置 `PDF_UNICODE_FONT` 或字体路径无效 | 指向 simhei.ttf 等 .ttf;无字体时自动回退 ASCII 属预期 |
| PDF 二维码扫码打不开 | `VERIFY_BASE_URL` 与实际前端地址不符 | 按实际部署地址配置后端环境变量 |

## E. 数据与一致性

| 症状 | 根因 | 解法 |
|---|---|---|
| 重启 Hardhat 后列表还有旧作品,但都无法操作 | 链清零而 SQLite 还在,chainWorkId 全部失效 | 删 `backend/data/index.db` 重启后端(演示环境标准归零) |
| 后端宕机期间上链的作品状态没更新 | 正常——重启后断点续扫自动补 | 重启后端等几秒;日志见 `anchored: chainWorkId=…` |
| 怀疑索引与链不一致 | 任何原因 | 终极手段:停后端→删 index.db(或把 chain_cursor.last_block 置 0)→重启,全量重扫重建(幂等安全) |
| `anchored (no local row)` 日志 | 有人绕过后端直接调合约注册 | 非故障;该作品不入索引但链上反查可验(设计讨论见 learning/06) |
| 测试脚本第二遍全挂 invalid expiry | 前一遍 evm_increaseTime 把链时间推前了 | 重启 Hardhat 再跑;或用链上时间基准的 extended 脚本(learning/09 9.4) |

## F. 环境与工具

| 症状 | 根因 | 解法 |
|---|---|---|
| make-ca.sh 生成的证书 Subject 是一串路径 | Git Bash 把 `-subj /C=CN/...` 当路径改写 | 脚本已内置 MSYS_NO_PATHCONV=1;手敲命令记得加 |
| c2patool 报 trust_anchors 是非法 URL | Windows 盘符路径被当 URL scheme | 后端已规避(锚复制到资产目录用相对路径);手动操作照做 |
| ipfs config 参数被改写成 C:/Program Files/Git/ip4/... | 同 MSYS 路径改写 | 用 PowerShell 跑 ipfs 脚本,或 MSYS_NO_PATHCONV=1 |
| 8080/8545/5173 端口被占 | 残留进程 | `netstat -ano | findstr :8080` 找 PID 结束;或改 APP_PORT |
| go run 首次极慢 | 首次拉取/编译依赖(项目内 .cache) | 等待;之后有缓存秒级 |

## 还没解决?

按顺序收集三样再排查/求助:①`/api/health` 完整输出;②后端窗口最近 30 行日志;
③复现步骤(哪个页面、哪个账户、点了什么)。九成问题在 health 字段和后端日志里已给出答案。
