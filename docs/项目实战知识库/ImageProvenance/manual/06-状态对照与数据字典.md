# 06 状态对照与数据字典

> 本系统有**四套状态体系**,分属不同层、回答不同问题,极易混淆——本篇一次讲清,
> 并附全部数据结构的字段字典。答辩被问"状态"、接手改代码前,先翻这页。

## 一、四套状态总览

| 体系 | 取值 | 归谁管 | 存在哪 | 回答什么问题 |
|---|---|---|---|---|
| ① 链下作品状态 `status` | UPLOADED / SIGNED / PINNED / PENDING_ANCHOR / ANCHORED | 后端(prepare 写入,监听器推进) | SQLite works.status | 这件作品在登记流程里走到哪一步了? |
| ② 链上作品状态 `chainStatus` | 0 Active / 1 Disputed / 2 Revoked | 作者(setStatus),事件镜像到链下 | 链上 Work.status;镜像列 works.chain_status | 作者对这件作品的最新链上表态是什么? |
| ③ 验证四态 `matchTier` | original / signed / manifest-only / none | 验证接口每次实时判定 | 不落库(响应字段) | 手里这份**文件**和登记记录是什么关系? |
| ④ C2PA 校验态 `c2paStatus` | trusted / valid-untrusted / invalid / unavailable:… | c2patool 签名后验证一次写入 | works.c2pa_status | 签名版的内容凭证可信吗? |

**一句话区分**:①是流程进度、②是作者表态、③是文件鉴定结论、④是凭证可信度。
①②描述**作品**,③描述**某份文件**,④描述**签名质量**。

## 二、各状态机的流转

### ① 链下作品状态(单向推进)

```text
UPLOADED → SIGNED → PINNED ──(链已配置,calldata 已返回)──→ PENDING_ANCHOR ──(监听到 WorkRegistered)──→ ANCHORED
```
- 实际观察中前三态在 prepare 一个请求内瞬间走完,入库时已是 PINNED 或 PENDING_ANCHOR;
- 只 prepare 不上链 → 永远停在 PENDING_ANCHOR(合法状态,见作品 #5 实测);
- ANCHORED 由**事件**驱动,不是前端回执驱动——后端宕机期间上链,重启后补推进(断点续扫)。

### ② 链上作品状态(可任意跳转,仅作者)

```text
        setStatus(1)              setStatus(2)
Active ────────────→ Disputed ────────────→ Revoked
  ↑ ←──────────── setStatus(0) ──────────────┘   (任意两态间均可直接切换)
```
- 初始恒为 Active(registerWork 写死);
- 每次变更发 `WorkStatusChanged(id, status)` → 监听器 `SetChainStatus` 镜像,延迟 ≤3s;
- 历史不可删:链上只有最新值,变更历史在事件日志里永存。

### ③ 验证四态(判定优先级,不是状态机)

```text
上传文件算 SHA-256
 1. 命中 originalHash → original
 2. 命中 signedHash   → signed
 3. (库 miss 时先走链上 getWorkByHash 兜底,再按相等哈希归入 1/2)
 4. 文件内嵌 manifest 的 identifier 反查命中 → manifest-only(签名后被篡改)
 5. 全部落空 → none
```

### ④ C2PA 校验态

| 值 | 含义 | 产生条件 |
|---|---|---|
| trusted | 签名有效且证书链落在信任锚内 | 正常路径(自建 CA + trust anchor) |
| valid-untrusted | 签名有效但根不在信任列表 | 信任锚未配置/证书不在链内 |
| invalid | 内容或断言校验失败 | hard binding 不匹配、必填断言缺失(如 digitalSourceType) |
| unavailable: <原因> | c2patool 不可用,跳过签名 | 工具路径错误/未安装(登记降级继续) |

## 三、组合语义速查(容易被问懵的搭配)

| 组合 | 含义 |
|---|---|
| status=ANCHORED 且 chainStatus=2 | 已确权登记,但作者其后撤销了确权声明——记录仍在,前端显示红色警示 |
| status=PENDING_ANCHOR 且链上其实已注册 | 后端还没扫到事件(宕机/延迟窗口),数秒后自动翻转 |
| matchTier=signed 且 chainStatus=1 | 文件本身是官方签名版没被动过,但作品正处争议——验证页同时显示绿色结论 + 红色警示,两者不矛盾(一个说文件,一个说作品) |
| matchTier=manifest-only 且 c2paState=Invalid | 标准的"签名后被篡改"证据组合 |
| c2paStatus=unavailable 且 status=PINNED | c2patool 缺失时登记的作品:无签名版、无 txRequest,不能上链 |

## 四、数据字典

### 4.1 SQLite `works` 表 ↔ Work JSON

| 列 | JSON 字段 | 类型 | 来源 | 说明 |
|---|---|---|---|---|
| id | id | INTEGER PK | 自增 | 链下索引 ID(URL /api/works/:id 用它) |
| chain_work_id | chainWorkId | INTEGER | WorkRegistered 事件 | 链上作品 ID,0=未上链 |
| title | title | TEXT | 上传表单 | 入口强制 UTF-8 |
| author_address | authorAddress | TEXT | prepare 传入,**事件回填为准** | 恒小写 |
| original_hash | originalHash | TEXT UNIQUE | 后端计算 | 0x+64hex;唯一约束=链下防重 |
| signed_hash / manifest_hash | signedHash / manifestHash | TEXT(索引) | 后端计算 | 三元组另外两元 |
| original_cid / image_cid / manifest_cid / c2pa_report_cid | *Cid | TEXT | 存储层 | image_cid=签名分发版;local 模式形如 local-<sha256> |
| c2pa_status | c2paStatus | TEXT | c2patool 验证 | 见第二节④ |
| phash | phash | TEXT | 相似模块 | 64bit 十六进制感知哈希 |
| image_file_name / image_size | imageFileName / imageSize | TEXT/INTEGER | 上传文件 | — |
| storage_backend | storageBackend | TEXT | 配置 | ipfs / local |
| status | status | TEXT | 后端 | 第二节① |
| chain_status | chainStatus | INTEGER | WorkStatusChanged 事件 | 第二节②;旧库自动 ALTER 迁移,默认 0 |
| tx_hash / block_number | txHash / blockNumber | TEXT/INTEGER | 事件回填 | 存证交易定位 |
| tsa_timestamp | tsaTimestamp | TEXT | RFC3161 | 空=未配置 TSA 或获取失败 |
| created_at | createdAt | TEXT(RFC3339) | 后端 | UTC |

### 4.2 SQLite `licenses` 表 ↔ License JSON(纯事件镜像,后端从不主动写业务值)

| 列 | JSON 字段 | 来源事件字段 |
|---|---|---|
| chain_license_id(PK) | chainLicenseId | LicenseGranted topics[1] |
| chain_work_id | chainWorkId | topics[2] |
| licensee | licensee | `topics[3]`,存储时转小写 |
| licensor / usage / valid_until | licensor / usage / validUntil | data 解包(小写/原文/unix 秒) |
| revoked | revoked | LicenseRevoked 置 1;upsert 幂等 |
| tx_hash / created_at | txHash / createdAt | 事件所在交易 / 入库时间 |

### 4.3 SQLite `chain_cursor` 表

| 列 | 说明 |
|---|---|
| name(PK) | 游标名,当前仅 "main" |
| last_block | 已处理到的区块高度;删除该行=下次从创世块全量重扫(幂等,安全) |

### 4.4 链上结构(合约 ↔ Go 解码结构)

**RegistryV2.Work**:id, author, originalHash/signedHash/manifestHash(bytes32),
imageCid/manifestCid(string), createdAt(uint64, 区块时间), status(enum WorkStatus)。
**LicenseV2.LicenseRecord**:id, workId, licensor, licensee, usage, validUntil(uint64),
createdAt, revoked(bool)。
**RoyaltyV2.RoyaltyRule**:workId, creator, platform, creatorShareBps/platformShareBps
(uint16,和恒为 10000), updatedAt。BASIS_POINTS 常量 = 10000。

### 4.5 事件与 topics 布局(链下解码的契约)

| 事件 | topics[1..] (indexed) | data (ABI 编码) |
|---|---|---|
| WorkRegistered(id, author, 3×hash) | id, author | originalHash, signedHash, manifestHash |
| WorkStatusChanged(id, status) | id | status(uint8) |
| LicenseGranted(id, workId, licensee, …) | id, workId, licensee | licensor, usage, validUntil |
| LicenseRevoked(id, workId) | id, workId | — |
| RoyaltyRuleSet(workId, creator, platform, …) | workId, creator, platform | creatorShareBps, platformShareBps(**当前未被监听**,历史需回放事件——见 learning/10 练习一) |

### 4.6 验证结果 VerificationResult(不落库)

matched(bool)、matchTier(四态)、reason(人话解释)、computedHash、
source(db / chain,后者=链上反查路径)、c2paState(Trusted/Valid/Invalid,仅 manifest 路径)、
work(关联作品,含 chainStatus 供警示)。

## 五、口径提醒

- "作品状态"被问到时先反问/自答是哪一套:流程态、链上态、鉴定态还是凭证态;
- ①的 ANCHORED 不因②变化而变——撤销声明的作品仍是"已锚定",这是存证系统"记录不可抹"的体现;
- ③永远描述"这次上传的文件",同一作品可同时有四种文件各得四种结论。
