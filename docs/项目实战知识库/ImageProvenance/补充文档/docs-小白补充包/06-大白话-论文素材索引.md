## 一、先理解：毕设论文是什么结构

本科毕设论文（工科）通常是"六章 + 摘要"的标准结构：

| 章 | 内容 | 用什么素材 |
|---|---|---|
| 第 1 章 绪论 | 背景、意义、国内外现状、本文工作 | docs/08 的 STAR、README、文献综述 |
| 第 2 章 相关技术 | 区块链、密码学、C2PA、IPFS、pHash 的技术介绍 | learning/ 的压缩改写 |
| 第 3 章 需求分析与总体设计 | 问题分析、架构、威胁模型、设计决策 | docs/01、02、10 |
| 第 4 章 系统实现 | 每个模块怎么实现的 + 踩坑 | 代码 + learning/ + 开发日志 |
| 第 5 章 测试与实验 | 功能测试、攻击测试、覆盖率、性能、实验 | reports/ 全部 |
| 第 6 章 总结与展望 | 工作总结、局限性、展望 | docs/07 第 27 题、docs/05 |
| 摘要 | 全文浓缩 | 最后写 |

**docs/09 就是这张表的"素材版"**——每一章要写什么、素材在仓库哪个文件、数据怎么复现，
全给标好了。

## 二、docs/09 的核心思想：素材已经备齐，关键在"地图"

项目作者的聪明之处：**工程阶段就把论文素材全部沉淀好了**。
docs/09 不是"写论文指南"，而是一张**找料地图**：

| 论文要写的 | 素材在哪 | 你只需要做 |
|---|---|---|
| 一期缺陷分析（第 3 章） | docs/01 直接引用 | 改写措辞 |
| 总体架构图 | README 的 mermaid 图 | 重绘成 draw.io/Visio 版（论文忌直接截 mermaid） |
| 合约实现（第 4 章） | contracts/*.sol + learning/04 | 整理讲解 |
| 测试用例表（第 5 章） | reports/ 专项测试报告（76 项明细） | 改编成论文表格 |
| 攻击性测试（第 5 章） | reports/attack-cases.md | 威胁-防御-结果三段式改写 |
| 性能与 Gas（第 5 章） | reports/performance-table.md | 直接引用 |
| 踩坑（第 4 章或附录） | docs/04 的六处踩坑记录 | 每条都是现成的"现象→根因→修复→教训"结构 |

**关键纪律（原文档的原话）**："数字不要手抄论文后不改来源，改数据先改报告再引用，
保持单一事实源。"——论文里的数字必须和 reports/ 一致，改数字先改报告。

## 三、论文素材库：文献怎么组织（第 1 章"国内外现状"的写法）

docs/09 把素材库（`F:\毕业设计\韩师academic\论文素材\`）的 10 篇文献按**三条技术路线**归类：

```text
路线 A 哈希存证型：内容哈希 + 元数据上链（刘浩、李林逸、何晓彤）
路线 B 数字水印型：不可见水印嵌入图像（刘颖、陈家琰）
路线 C 特征匹配/加密型：SIFT 相似检索、图像加密（施建锋、李田）
本文路线：C2PA 声明入文件 + 链上锚定 + 四态验证
```

**对比表是第 1 章的核心表格**，对比点都是现成的：

| 与路线 A 的差异 | 本文创作者钱包直发交易（他们大多平台代签）；声明嵌入文件随文件流转；四态验证 |
|---|---|
| 与路线 B 的差异 | 水印改动像素有损；C2PA 不改像素但会被破坏性处理剥离——**两条路线互补**，论文可诚实写"展望：两者结合" |
| 与路线 C 的差异 | 本文明确收窄不做相似检索（pHash 仅预警 + 病态输入实验佐证） |

> 这个组织方式的妙处：**相关工作的每一条差异，都是你自己的设计决策**——
> 文献对比不是凑字数，而是给第 3 章的设计决策做铺垫。

## 四、术语统一表：为什么论文里要"统一用词"

docs/09 第四节给了一张表，比如：

| 论文用词（建议） | 避免混用 | 英文 |
|---|---|---|
| 确权存证 / 登记 | 上传、注册 | registration |
| 哈希三元组 | 三个哈希 | hash triple |
| 事件镜像 | 同步、缓存 | event mirroring |
| 断点续扫 | 断点续传 | resumable scanning |
| 越权 | 非法调用 | unauthorized |

**为什么重要**：论文评阅人可能看到多个同义词（"同步"、"镜像"、"入库"指的是同一件事），
会显得不严谨。全文统一用一套词，答辩口径也保持一致。

## 五、插图清单：10 张图从哪来

docs/09 建议画 10 张图（用 draw.io/Visio 重绘，不直接截 mermaid），例如：

| # | 图 | 素材来源 |
|---|---|---|
| 1 | 系统总体架构图 | README mermaid 重绘 |
| 2 | 两步上链时序图 | docs/08 第 7 节说明 |
| 3 | 哈希三元组关系图 | learning/04 |
| 4 | 四态验证判定流程图 | learning/05 判定树 |
| 5 | 事件监听与断点续扫机制图 | learning/06 |
| 8 | 四态验证结果页截图 | 按 manual/03 采集 |

**建议的写作顺序**（docs/09 第六节，反直觉但实用）：

```text
先 4（实现，素材最全趁热写）→ 5（测试，表格现成）→ 3（设计，从实现反推）
→ 2（技术，learning 压缩）→ 6 → 1 → 摘要
```

每写完一节，回 docs/07 对应题目过一遍口径——保证论文表述与答辩回答一致。
