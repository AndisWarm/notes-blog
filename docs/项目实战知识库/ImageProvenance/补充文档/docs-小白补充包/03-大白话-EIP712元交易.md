# 03 大白话：EIP-712 元交易设计

> 对应原文档：`docs/05-EIP712元交易设计（展望）.md`
> 本文作用：在读原文档之前，先讲清三个问题——什么是"元交易"、为什么需要它、它和一期代签有什么区别。
> 这篇是 docs 里**概念门槛最高**的一篇，建议配合 `learning-小白补充包/02`（钱包与交易）一起读。

## 一、先回顾：现在系统里"上链"是怎么做的

二期主路径（已经实现）：

```text
创作者钱包（MetaMask）──签名──发交易──→ 合约
                                        author = msg.sender = 创作者
```

这条路径完美解决了身份问题，但有一个**隐藏门槛：gas 费**。

- 在以太坊上发任何交易都要付 gas（网络费）；
- 在本地演示链上 gas 免费，所以没感觉；
- 但将来部署到真实网络（测试网/联盟链），**用户必须持有 gas 代币才能发交易**。

问题来了：普通创作者凭什么为了登记一张图去购买代币？门槛太高。

## 二、元交易：把"签名权"和"付钱权"分开

**核心洞察：签名的人不一定要是付钱的人。**

```text
正常交易：  创作者签名 + 创作者付 gas + 创作者发交易
元交易：    创作者只签名（证明"我同意登记"），平台/中继者付 gas 并发送交易
```

元交易（meta-transaction）就是：创作者对"我要登记的内容"做**签名**，
把这个签名交给**转发者（relayer，比如平台后端）**，由转发者出 gas 把交易发上链。

## 三、关键问题：转发者能造假吗？

这是元交易方案的核心疑点，也是它和一期代签的本质区别所在。

**一期的代签**：后端持有私钥，想写谁当作者就写谁——**能伪造身份**。

**元交易**：创作者只交出一个"签名"（对特定内容的签名），转发者**拿不到私钥**：

```text
创作者用私钥对"哈希三元组 + 自己的地址 + 序号 + 截止时间"签名
        ↓
转发者只能原样把这个签名提交上链
        ↓
合约用 ecrecover（从签名恢复签名者地址）→ 得到创作者地址
        ↓
author = 恢复出的创作者地址（不是转发者地址）
```

**转发者改任何一字节 → 签名就失效 → 恢复不出创作者地址 → 交易被拒。**

所以：转发者只能"代付钱"，不能"顶替人"。这就是原文档说的
"半信任（只能代发不能伪造）"。

## 四、需要补的密码学概念

### 1. ECDSA 签名

以太坊用的数字签名算法。签名 = 私钥对消息的"盖章"。

```text
私钥签名：只有持有私钥的人能做
公钥验签：任何人都能做
```

以太坊的地址 = 公钥的哈希后 20 字节。所以"能签出有效交易" = "持有该地址私钥"，
这就是链上身份的本质。

### 2. ecrecover

Solidity 内置函数：**从签名反推出签名者的地址**。

```text
ecrecover(消息哈希, v, r, s) → 签名者地址
```

元交易的核心就是它——不靠 `msg.sender`（那是转发者的地址），
而是靠签名恢复出**真正的创作者**。

### 3. EIP-712：结构化签名

普通签名是对一串字节签名（钱包里显示"你正在签一串看不懂的东西"）。
EIP-712 是标准化的**结构化数据签名**：

- 签名内容有明确的字段定义（类型 + 字段名）；
- 钱包能**读出来展示**（"你正在授权登记以下内容：哈希xxx，截止时间xxx"），
  用户不是盲签。

### 4. nonce 和 deadline：防重放、防囤签

| 机制 | 防什么 | 类比 |
|---|---|---|
| nonce（序号） | 同一个签名被反复提交（重放攻击） | 票据编号，用过作废 |
| deadline（截止时间） | 签名被"囤起来"很久以后再用 | 优惠券有效期 |
| 域分隔符（chainId + 合约地址） | 在别的链/别的合约上重放 | 票据只在本店有效 |

三者合起来叫"三层防重放"。

## 五、方案对比表（原文档的核心表格，翻译成人话）

| 方案 | 链上作者是谁 | 创作者要付 gas 吗 | 对后端的信任要求 |
|---|---|---|---|
| 一期：后端代签 | ❌ 后端地址（假的） | 不用 | 完全信任（后端想伪造谁就伪造谁） |
| 二期：钱包直发 | ✅ 创作者（真实） | **要** | 不用信任（后端没有签名权） |
| 展望：EIP-712 元交易 | ✅ 创作者（ecrecover 恢复） | **不用** | 半信任（只能代付，不能伪造） |

## 六、为什么二期"只设计不实现"？

原文档给了三个理由，用大白话翻译：

1. **本地链 gas 免费**——元交易解决的问题（gas 门槛）在演示环境根本不存在；
2. **复杂度太高**——要加转发者钱包管理、nonce 同步、过期处理三块复杂度，
   偏离二期"做实四个闭环"的主线；
3. **答辩口径清晰**——主路径是钱包直发；元交易作为"面向生产环境的演进方向"写进论文展望，
   既体现了思考深度，又不冒险扩大实现范围。

> 这是毕设里很聪明的做法：**把该想的想清楚、写成文档，但不一定都实现**。
> 展望章节有实体支撑（不是空谈），主线不受影响。

## 七、元交易流程（人话版）

```text
1. 创作者上传图片，后端准备好登记数据（三哈希、CID 等）
2. 钱包弹出结构化签名请求（EIP-712）："确认登记以下内容？"→ 创作者点确认，签名生成
3. 签名交给后端（转发者）
4. 后端用自己的钱包付 gas，把交易和签名一起发上链
5. 合约 ecrecover 恢复创作者地址 → 登记成功，author = 创作者
```

创作者全程：一次点击签名。不接触 gas、不接触交易细节。
