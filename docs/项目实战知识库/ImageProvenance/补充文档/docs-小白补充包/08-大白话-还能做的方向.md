# 08 大白话：还能做的方向

> 对应原文档：`docs/还能做的方向.md`
> 本文作用：这篇原文档很短（约 500 字），但信息密度很高——里面提到了很多项目里
> 没有细讲的概念（CI、Sepolia、Docker Compose、账户抽象、MPC……）。
> 本文把每条方向翻译成人话，并讲清它的取舍逻辑。

## 一、先理解原文档的"四档"逻辑

原文档把"还能做的事"按**投入产出比**分成四档：

```text
第一档 答辩前收尾（必做，小时级）——不做的直接后果是答辩有风险
第二档 低成本高回报（可选，半天~一天）——提升工程素养展示点
第三档 论文展望（只写不做）——你已有基础，直接引用
第四档 做真东西（毕业后）——生产化路线图
```

**核心判断**（原文档原话）：第一档必须做；第二档挑 CI 和测试网两项就够；
毕设评分看的是**闭环完整 + 论证清楚**，继续堆功能不如把精力压到论文和答辩演练。

## 二、第一档：答辩前的收尾（为什么"必做"）

| 事项 | 人话 | 为什么必做 |
|---|---|---|
| 本机 `npm run build` | 把前端改动构建验证一遍 | 开发日志里一直挂着"唯一需要人手的环节"，不清掉就是隐患 |
| 用 MetaMask 人工走完整流程 | 按 manual/03 走一遍演示 | 评委很可能现场要求演示，你没走过就是风险 |
| 跑扩展测试脚本 | 31 个扩展用例留一次本机记录 | 让"76/76"这个数字在你机器上真实发生 |
| 截图采集 | 四态验证页、MetaMask 弹窗、trusted 对照 | 论文和 PPT 都要用，现场再截来不及 |

**共性**：这些都是"低成本消除答辩风险"的动作——不是加功能，是补证据。

## 三、第二档：低成本高回报（重点理解这三项）

### 1. GitHub Actions CI（持续集成）

- **人话**：每次把代码推到 GitHub，自动跑一遍合约测试 + 后端单测，结果直接显示在 README 的徽章上；
- **价值**：测试徽章从"手工声明"变成"持续验证"——工程素养的直接展示点；
- **为什么低成本**：项目已有完整测试（20 合约用例 + go test），CI 只是把"手工跑"变成"自动跑"。

### 2. 公共测试网实测一次（如 Sepolia）

- **人话**：把合约部署到真实的公共测试网（Sepolia），拿到真实的交易链接（浏览器上可查）；
- **价值**：真实交易链接比本地链演示说服力强一截；
- **为什么低成本**：架构本就是链无关的——`CHAIN_RPC_URL`、`DEPLOYMENTS_FILE` 可配，
  水龙头接口带 chainId 检查会自动失效（不会误用）。

### 3. 分账规则变更历史

- **人话**：现在分账规则是"覆盖式"的（改一次就没了旧值），但链上其实有全部历史事件
  （RoyaltyRuleSet）；照抄授权记录的镜像模式加一张历史表即可；
- **价值**：能回答"规则被改过几次、改前是多少"——完整审计追踪。

## 四、第三档：论文"展望"章节的素材（只写不做）

每条都有对应的已有基础，论文引用时指向这些文档：

| 展望方向 | 已有基础 | 在哪 |
|---|---|---|
| EIP-712 元交易 | 设计文档已写好 | `docs/05` |
| 真实司法存证链对接 | MockJudicialAnchor 演示了调用形态 | `contracts/contracts/` |
| 分账走向真实支付 | RoyaltyV2 已记录比例，escrow/splitter 方案 | docs/02 分账设计 |
| 账户抽象/托管钱包降低门槛 | 本地水龙头已做初步缓解 | 开发日志水龙头条目 |
| C2PA 扩展到视频/音频 | 规范本身支持，本系统只做了图像 | — |
| pHash 升级为向量检索级相似检索 | 病态输入实验是论据 | `phash_probe_test.go` |

**为什么"只写不做"是聪明做法**：展望章节需要的是"有依据的设想"，
而不是"半成品的功能"。设计文档 + 实验证据 = 展望有实体支撑。

## 五、第四档：毕业后做真东西（生产化路线图）

| 方向 | 人话 | 对应现在的什么 |
|---|---|---|
| 后端鉴权与配额 | 现在 prepare 接口完全开放，任何人都能上传 | 威胁模型里的 R1 |
| SQLite → PostgreSQL | 数据库升级 | SQLite 单写并发受限 |
| 轮询 → WebSocket 订阅 | 事件同步从 2 秒级到毫秒级 | 监听器 2s 轮询 |
| IPFS → pinning 服务 | 文件多副本保全 | 现在只有本地单节点 |
| 合约第三方审计 | 专业机构审合约 | 现在只有自测 + 攻击用例 |
| 多链部署 | 一套代码跑多个网络 | 架构已支持（配置化） |

**注意**：这一档的每一条都能在项目里找到"现状证据"——
不是从零开始，而是"已知缺什么、怎么补"。

## 六、回到正片

原文档只有 25 行，但它是**整个 docs 的收尾篇**——它把前面所有文档里
"没做完的部分"和"将来的可能性"汇总了。
