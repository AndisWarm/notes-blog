# 02 大白话：区块链、钱包与合约

> 目标：用生活比喻建立"区块链/以太坊/钱包/交易/gas/合约"的直觉。
> 本文件**不追求严谨**，只求让原 `learning/02` 里的每个词不再吓人。
> 学完能大致说清"一笔交易是什么"，就可以回去读原 02 章了。

## 2.1 区块链：一本全世界共同记账、谁都不能偷偷改的本子

想象一本**公共账本**，上面按顺序记录着每一笔转账和每一份"合约声明"：

- **每个人手里都有一份完整副本**（这就是"去中心化"）；
- 新记录**按顺序追加**，一页扣一页（这就是"链"）；
- 想改旧记录？要改就得改**所有副本**，而且每一页都盖了前一页的"指纹章"（哈希），
  改一页后面全对不上——**改了立刻被发现**。

所以区块链的核心价值只有一句话：**"写上去就赖不掉"**。

本项目用的不是真比特币，而是 **Hardhat 在你电脑上模拟出的假链**。它和真链
唯一的区别是：假链**只有你一个人在用、一关就清零、测试币随便花**。
学习成本为零，破坏成本为零——这也是为什么原文档敢让你"随便改、随便删"。

## 2.2 以太坊：能记账还能跑小程序的区块链

比特币只记"谁给谁转了多少钱"。**以太坊**升级了玩法：账本上还能存**小程序**，
任何人按规则调用它，结果由所有副本共同算出、共同确认。这个小程序就叫
**智能合约（Smart Contract）**。

本项目就是在以太坊（开发链）上部署了四个合约，用来记录"哪张图属于谁、授权给了谁、
分账比例多少"。**图片本身不上链**（太大、太贵），上链的只有它的"指纹"（哈希）——
这个设计后面 04 篇还会讲。

## 2.3 账户与钱包：一把钥匙和一个门牌号

**账户 = 一对钥匙**：

```text
私钥（只有你知道的密码，像钥匙）      →  谁能用这个账户的唯一凭证
公钥（从私钥算出来，像锁）            →  别人验证"是不是你"用的
地址（公钥再加工，像门牌号 0x7099...）→  别人给你转账/查你用的编号
```

- **没有"注册"**：任何人随时能生成一对新钥匙，生成即拥有账户。所以 Hardhat
  能当场打印 20 个测试账户——它们不是"注册"的，是**算**出来的。
- **钱包（MetaMask）** = 帮你保管私钥、在浏览器里代你签名的东西。你点"连接钱包"，
  实际上是在说"这个页面可以知道我的门牌号"；你点确认交易，实际上是在说"我同意
  用我的私钥给这笔交易盖章"。
- **私钥绝不能给别人**。本项目后端**故意不碰你的私钥**（日志里的 `signer mode: creator-wallet`
  就是在声明这一点）——上链操作必须由你在 MetaMask 里亲手确认。

> 注意区分两个概念：**"连接钱包"≠"授权转账"**。连接只是亮出身份（门牌号），
> 每次真正的操作（登记、授权、分账）都会再弹一次确认框，逐笔批准。

## 2.4 交易：让账本改变的唯一方式

想让链上的账本发生变化，只能发一笔**交易（Transaction）**。一笔交易大致长这样：

```text
{ 发送者(由签名恢复), 发给谁(to), 调用什么(data), 愿意付多少油费(gas), 发送者的签名 }
```

三个关键直觉：

1. **`发送者`不是填上去的，是验出来的**。签名是用私钥盖的，节点拿公钥一验，
   谁签的一目了然、伪造不了。所以合约里看到"这个操作来自 `0x7099...`"就是铁证——
   本项目"链上作者 = 创作者本人"的全部底气在这。
2. **`to` 为空 = 创建一个新合约**；`to` 是某个合约地址 + `data` 非空 = **调用合约的某个方法**。
   `data` 的开头 8 个十六进制字符是"方法选择器"（`registerWork` 的指纹前 4 字节），
   原 learning/01 让你抄的 `txRequest.data` 前 8 位就是它。
3. **交易不是免费的**（要付 gas，见下）。所以在链上做事的原则是：**能少存就少存**。

**本项目里的"一笔交易"长什么样**（登记作品时）：后端把"这张图的三个哈希 + 标题 +
创作者地址"打包成调用 `registerWork` 方法的 `data`，前端拿这个 `data` 请求 MetaMask
签名，你点确认，交易上链，账本里多了一条"作品 #7 属于 0x7099..."的记录。

## 2.5 Gas：链上做事的"油费"

假链也有 gas 概念，只是不用真钱。理解两点就够：

1. **每条链上操作都标了价**，存储（写数据）最贵。所以本项目**链上只存 32 字节哈希**，
   不存图片、不存原文——省油费是链上开发的头号思维，这和普通后端"多存点无所谓"
   完全相反。
2. 你出价太低 → 交易卡住不动（pending）；本地链没这个问题，随便出。

## 2.6 智能合约：账本上的"自助规则"

合约 = 一段**公开、不可改**的程序，部署后任何人按规则调用。两个直觉：

- **确定性**：同一笔交易在全世界每台电脑上重放，结果**必须一模一样**。
  所以合约里不能有随机数、不能上网查资料——一切信息要么由交易带进来，要么
  是链上已有的。这解释了本项目为什么把 C2PA 签名、IPFS 存储都放在**链下的后端**
  做：链上干不了这些活，只能接收"算好的结果"。
- **规则即法律**：合约里写了 `如果 调用者不是作者 → 拒绝`，那就是拒绝，
  谁也绕不过。你在页面上故意用另一个账户操作时看到的红色提示"当前钱包不是该作品
  的链上作者"，就是合约拒绝后把原因传回前端翻译出来的。

## 2.7 事件（Event）：链对外广播的"广播站"

合约可以**发事件**（emit）——类似于"广播一条新闻"：`作品 #7 已登记`。
广播**不改变账本**，只是附在交易回执里的公告，任何人可以按"合约地址 + 主题"订阅。

本项目后端有一个**监听器**：每 2 秒去链上问"有没有新广播？"，有就抄进自己的数据库。
这就是你在页面授权后**等 3 秒记录才出现**的原因——不是卡了，是广播在飞。

## 2.8 把本项目套进这些概念

```text
你（创作者）                  → 一个以太坊账户（0x7099...）
MetaMask                     → 保管你私钥、替你签名
四个合约                     → 账本上的规则：
                               Registry（作品登记簿）
                               License（授权记录簿）
                               Royalty（分账规则簿）
                               MockJudicialAnchor（司法存证接口，测试用）
图片                         → 不上链；只有哈希（指纹）上链
后端                         → 链下干活：算哈希、签 C2PA、存数据库、监听广播
前端                         → 展示 + 把"你要做什么"翻译成交易让你确认
```
