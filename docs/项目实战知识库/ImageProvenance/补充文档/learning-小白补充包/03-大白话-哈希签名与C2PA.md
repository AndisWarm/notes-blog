## 3.1 哈希：内容的"指纹"

哈希（Hash）是一个函数：给它任意内容，吐出一个固定长度的数字串（本项目用
SHA-256，长这样：`e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855`）。

三个性质，全部用"指纹"来理解：

| 性质 | 指纹比喻 | 本项目用在哪 |
|---|---|---|
| **单向** | 从指纹推不出本人长什么样 | 链上公开哈希，不泄露图片内容 |
| **雪崩** | 手指破个皮，指纹完全变 | 图片改 1 个字节，哈希面目全非 → "改了就检出" |
| **抗碰撞** | 找不到两个指纹相同的人 | 哈希可以代表文件本体上链（存证） |

**亲手做一次**（PowerShell）：

```powershell
# 建两个只有一字之差的文件
Set-Content -Path C:\temp\a.txt -Value "hello" -Encoding ascii
Set-Content -Path C:\temp\b.txt -Value "hellp" -Encoding ascii

# 算哈希（注意 Get-FileHash 与 sha256sum 的输出格式不同，看 Hash 那一列）
Get-FileHash C:\temp\a.txt -Algorithm SHA256
Get-FileHash C:\temp\b.txt -Algorithm SHA256
# 对比两串 Hash：完全不同，即使两个文件只差一个字母
```

> 对照项目代码：`backend/internal/hash/sha256.go` 全文 20 行，读一遍就懂——
> 它就是 `Get-FileHash` 的 Go 版本。

**千万别混淆**：本项目还有第二种哈希叫 **pHash**（感知哈希）。SHA-256 是"差一点就全变"，
pHash 是"像一点就接近"（用于找相似图，比如"这张图是不是另一张的截图"）。用途相反，
`learning/05` 会用到 pHash 做相似预警。

## 3.2 数字签名：不可抵赖的"本人盖章"

签名解决两个问题：**内容没被改** + **确实是你干的**。

比喻：你用私章（私钥）盖在文件上，任何人拿你的印章样本（公钥）一比对就能确认
"章是真的、文件盖完章后没动过"。想伪造？没有私章盖不出你的章。想抵赖？
章是你亲手盖的，赖不掉。

两个细节：

1. **签的是"内容"不是"人"**：签名绑定内容和身份，内容一改，签名立刻验不过。
2. **公钥只能验签，不能反推私钥**：所以私钥可以放心用来签名，公钥可以到处公开。

本项目有两处独立使用签名，曲线不同但原理相同：

| 场景 | 签什么 | 谁验证 |
|---|---|---|
| 以太坊交易 | 整笔交易（你的 MetaMask） | 链上每个节点（验出"这是 0x7099... 干的"） |
| C2PA 声明 | 图片里嵌的声明文件 | 任何拿到图的人（用 c2patool） |

## 3.3 证书与信任链："持钥人是谁"由谁来担保

签名只回答"内容没改、是持钥人签的"，**不回答"持钥人可不可信"**——张三的私章
盖的合同，也得先知道张三是谁、有没有资格。这就是**证书（Certificate）**的活：
一本"数字身份证"，把**身份 + 公钥**绑在一起，再由更高一级的机构（CA）签名担保。

信任链长这样：

```text
根证书 Root CA（自签，验证方"天生信任"它 = trust anchor）
   └─ 签发 → 叶子证书（写着"签名者是谁 + 他的公钥"）
                 └─ 用它签 → C2PA 声明（嵌在图片里）
```

验证方从叶子一路验到根：**根在自己的信任列表里 → Trusted（可信）**；
根不认识 → 签名是有效的但**来源不可信（untrusted）**——注意这两个结论的区别，
这就是原 `learning/08` 招牌实验的核心。

本项目 `tools/ca/make-ca.sh` 干的就是造这条链：自己当根、自己发叶子证书，
所以你自己验证自己签的图，根就在信任列表里 → Trusted。

## 3.4 C2PA：把"声明 + 签名"装进图片里

**C2PA**（内容来源与真实性联盟）是 Adobe、微软、尼康、BBC 等共同定的开放标准，
回答一个问题：**"这张图是谁、在什么时候、用什么设备/软件创作的？"**

做法：把一份**声明（manifest）**直接**嵌进图片文件内部**（不是存服务器，是装进
图片自己身体里），随图片流转，任何人有工具就能离线查验。manifest 里装着：

1. **断言（assertions）**：创作动作、作者信息、以及本项目塞进去的
   **originalHash（原图哈希）**——"链上登记的就是我这张图"的证据；
2. **硬绑定（hard binding）**：对图片数据分块算哈希，图被改 → 绑定断裂 → 判 Invalid；
3. **签名**：用 3.3 的叶子证书私钥对整个声明盖章。

**本项目最关键的设计**（答辩高频）：manifest 里嵌 `originalHash`（指向链上记录），
链上又存 `manifestHash`（指向文件里的声明）——**文件与链互相指认**。
图片被改后哈希全变，但幸存的声明仍能指回"这张图曾被登记过"，
这就实现了验证四态中的"**签名后被篡改**"态。

**业界坐标**（让你知道自己学的是真东西）：Adobe 的 Content Credentials、
相机厂商"拍摄即签名"、OpenAI/Google 给 AI 生成图嵌 C2PA 标识——同一个标准。

## 3.5 Windows 上亲手验一次签名（Git Bash 版）

原文档的验签命令用了 bash 语法（`<( ... )` 进程替换），**PowerShell 跑不了**，
请用 Git Bash（项目根目录右键 → Open Git Bash here）：

```bash
cd tools/ca
echo "test message" > /tmp/msg.txt
# 私钥签名
openssl dgst -sha256 -sign sign.key -out /tmp/msg.sig /tmp/msg.txt
# 公钥验签（把证书里的公钥拿出来验）
openssl dgst -sha256 -verify <(openssl x509 -in sign.crt -pubkey -noout) -signature /tmp/msg.sig /tmp/msg.txt
# 期望：Verified OK
# 把 /tmp/msg.txt 改成别的字再验一次 → Verification Failure（内容变了，签名就死）
```

再看一眼信任链：

```bash
openssl x509 -in tools/ca/rootCA.pem -text -noout | head -25    # Issuer 和 Subject 相同 = 自签根
openssl x509 -in tools/ca/sign.crt  -text -noout | grep -A2 "Key Usage"   # 叶子证书的用途声明
openssl verify -CAfile tools/ca/rootCA.pem tools/ca/sign.crt    # OK = 链验证通过
```
