# 01 保姆级：环境搭建与五窗口启动

> 目标：把电脑从"零基础"状态装到"五个窗口全绿、网页能打开"。
> 本文件是 `manual/01-环境与安装.md` 和 `manual/02-启动与健康检查.md` 的**逐步骤细化版**，
> 每个软件都讲"是什么 → 装哪个 → 怎么验证"。装好的同学直接跳到 1.4。
> 版本号以 `manual/01` 的表为准，这里只讲方法和验证标准。

## 1.1 先认识这台系统里的"五个零件"

| 零件 | 是什么（大白话） | 端口 | 没有它会发生什么 |
|---|---|---|---|
| **Hardhat** | 在你电脑上模拟出一条"假以太坊"（开发链） | 8545 | 一切链上操作（登记、授权、分账）全部瘫痪 |
| **部署脚本** | 把四个合约"刻"到假链上，并记下地址 | — | 后端和前端不知道合约在哪，报"链信息不可用" |
| **IPFS / 本地存储** | 存图片原件/签名版的地方（可选） | 5101/8181 | 不启动也行，后端自动改用本地文件夹存储 |
| **后端 (Go)** | 干活的大脑：算哈希、签名、存数据库、监听链 | 8080 | 前端没数据可显示 |
| **前端 (Vite)** | 你眼睛看到的网页 | 5173 | 浏览器打不开界面 |

> 只有五个全启动，浏览器里才能完整演示"登记 → 授权 → 验证"。**启动顺序不能乱**，
> 原因在 1.4 末尾。

## 1.2 逐个安装（只做一次）

### ① Node.js（含 npm）

- **是什么**：运行 JavaScript 程序的引擎。Hardhat、前端 Vite、测试脚本全用它。
- **装哪个**：官网 nodejs.org 下载 **LTS 版**（左侧绿色按钮），一路下一步。
- **验证**（装完**重开**一个终端再试）：
```powershell
node --version     # v22.x.x 之类
npm --version      # 10.x.x 之类
```

### ② Go

- **是什么**：后端程序的语言编译器。本项目的后端 5000+ 行代码由它编译运行。
- **装哪个**：go.dev 下载 Windows 安装包，一路下一步（默认装在 `C:\Program Files\Go`）。
- **验证**（装完重开终端）：
```powershell
go version         # go version go1.25.x windows/amd64
```

### ③ MetaMask 钱包

- **是什么**：浏览器插件，"链上身份 + 签名工具"。本系统**故意不替用户保管私钥**，
  所有上链操作必须由你在 MetaMask 里点确认——这是本项目的核心设计，不是缺陷。
- **装哪个**：Chrome/Edge 应用商店搜 "MetaMask"，装完按引导创建钱包。
  会生成 12 个助记词，**截图存好**（丢了没人能帮你找回）。
- **说明**：本项目只用它连接本地假链，**不需要往里充真钱**。假链测试币由页面
  水龙头按钮发放。

### ④ 项目自带工具（不用装）

`tools/bin/` 下已内置 `c2patool.exe`（C2PA 签名/验证工具）和 `ipfs.exe`（分布式存储），
Windows x64 直接可用。只有换机器/换系统才需要重新下载（见 manual/01 的说明）。

### ⑤ OpenSSL（一半用不到）

- PowerShell 里验证签名需要它，但 Windows 不自带。**本项目只在两处用 openssl**：
  - 生成 demo CA：用 **Git Bash 自带**的 openssl（见 1.3）
  - 手动验签实验：也建议直接在 Git Bash 里跑
- 结论：**不用单独给 PowerShell 装 openssl**，全部在 Git Bash 里做。

## 1.3 首次安装三步（只做一次）

以下命令全部在**项目根目录**（`F:\毕业设计\韩师academic\ImageProvenanceV2`）执行。

### 第一步：装前端与合约的依赖包

在项目根目录开一个 PowerShell：

```powershell
cd contracts
npm install        # 装 Hardhat 及相关（几百 MB，等它跑完，报错见 06 篇）
cd ..\web
npm install        # 装 Vite 与 vue（同样等它跑完）
```

> 这一步最可能出问题的点：网络。npm 默认连国外源，卡住/报错时切换国内镜像：
> `npm config set registry https://registry.npmmirror.com` 然后重试。
> 注意在 `contracts` 和 `web` **两个文件夹各跑一次** `npm install`，别漏。

### 第二步：生成 demo CA（证书）

CA = 给"签名用的证书"盖章的机构。本项目要自建一条信任链（原 learning/08 的主角）。
**必须在 Git Bash 里跑**（脚本用了 bash 语法）：

```powershell
# 在项目根目录打开 Git Bash（右键 → "Open Git Bash here"），然后：
bash tools/ca/make-ca.sh
# 成功后 tools/ca/ 下应出现：rootCA.pem、sign.key、sign.crt、sign-chain.pem
```

验证（Git Bash 里）：
```bash
ls tools/ca/     # 四个文件都在
```

> 这一步**不做**的话，后端 prepare 会 500 报错 `c2patool embed failed`（06 篇 A 类错误）。

### 第三步：启动 IPFS（可选）

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\dev\start-ipfs.ps1
```

- 看到 `Daemon is ready` 就是好了，**这个窗口不能关**（关了它后端会自动回退本地存储）。
- 想省事可以**跳过**：系统自动用本地文件夹存储（`backend/data/objects/`），功能不受影响。

## 1.4 五窗口启动（每次学习都要做，练熟它）

> **五个窗口 = 五个独立的 PowerShell 窗口，每个窗口跑一个服务，窗口不能关**。
> 推荐在**项目根目录**开五个 PowerShell 窗口，按下面顺序一个窗口跑一条命令。

| 步骤 | 窗口命令（PowerShell） | 成功标志（窗口里出现才算过） |
|---|---|---|
| ① 链 | `powershell -NoProfile -ExecutionPolicy Bypass -File scripts\dev\start-hardhat.ps1` | `Started HTTP and WebSocket JSON-RPC server` + 一长串账户列表（20 个，带私钥） |
| ② 部署 | `powershell -NoProfile -ExecutionPolicy Bypass -File scripts\dev\deploy-contracts.ps1` | 打印 4 个合约地址，且 `contracts\deployments\localhost.json` 文件更新 |
| ③ 存储 | `powershell -NoProfile -ExecutionPolicy Bypass -File scripts\dev\start-ipfs.ps1`（可选） | `Daemon is ready`（跳过则用本地存储） |
| ④ 后端 | `powershell -NoProfile -ExecutionPolicy Bypass -File scripts\dev\start-backend.ps1` | 出现 `Starting V2 backend ... (signer mode: creator-wallet)` 和 `chain listener started (registry=0x... license=0x...)` |
| ⑤ 前端 | `powershell -NoProfile -ExecutionPolicy Bypass -File scripts\dev\start-web.ps1` | `ready` / `Local: http://localhost:5173/` |

启动后浏览器打开 `http://localhost:5173/`。

**顺序为什么不能乱**（背下来，面试也会问）：
- ② 依赖 ①：部署要连上链
- ④ 依赖 ②：后端启动时要读部署文件里的合约地址和 ABI
- ⑤ 依赖 ④：前端要从后端 `/api/chain/info` 拿合约地址，不能自己瞎猜

**健康检查**（新开一个窗口）：
```powershell
curl.exe http://127.0.0.1:8080/api/health
```
期望看到 `"status":"ok"`、`"chainReady":true`、`"signerMode":"creator-wallet"`。
字段逐个什么意思，原 manual/02 有表。

## 1.5 MetaMask 连接（第一次必做，之后自动）

1. 浏览器打开 `http://localhost:5173/`，点右上角"连接 MetaMask"；
2. MetaMask 弹窗 → 选账户 → 连接；
3. 前端自动请求添加网络 "Hardhat Local"（RPC `http://127.0.0.1:8545`，Chain ID `31337`），
   **点批准**；
4. 顶栏如果显示余额 0 → 点"领取测试币"按钮，立刻变 10 ETH（本地假链，随便花）。

> 手动添加网络参数（前端弹窗失败时用）：网络名 `Hardhat Local`、RPC URL
> `http://127.0.0.1:8545`、Chain ID `31337`、货币 `ETH`。全部抄原 manual/02 的表。

## 1.6 重启后的"归零"手顺（练熟，之后要用几十次）

Hardhat 是假链，**数据在内存里**，一关窗口全没。所以每次重启 Hardhat 后：
所有链上记录清空，但 SQLite 数据库（`backend\data\index.db`）还记得旧作品——
这些旧记录的链上编号已失效，必须一起清。

**标准归零手顺（每次重启 Hardhat 后做一遍）**：

```powershell
# 1. 关掉全部 5 个窗口
# 2. 删数据库（让本地记录跟"空链"对齐）
Remove-Item backend\data\index.db
# 3. 按 1.4 顺序重新启动 ①→⑤
# 4. 清 MetaMask 的 nonce：MetaMask → 设置 → 高级 → 清除活动与 nonce 数据
#    （不清的话发交易会一直 pending，06 篇 A 类最常见错误）
```

**验证归零成功**：页面刷新后作品列表为空，能正常登记新作品。

## 1.7 启动失败的快速自检

| 现象 | 90% 的原因 | 处理 |
|---|---|---|
| `node` / `go` 不是内部或外部命令 | 装完没重开终端 | 重开终端再试 |
| npm 卡住/报 ERR | 网络 | 换镜像源后重试（1.3） |
| ② 部署失败 | ① 没起或窗口已关 | 回 ① 重开窗口 |
| ④ 报 `chain listener started` 前的错误 | ② 没跑/部署文件缺失 | 重跑 ② |
| 前端黄条"链信息不可用" | ① ② 没做，或 ④ 起得太早 | 补齐 ① ② 后重启 ④ |
| prepare 返回 500 且日志含 c2patool | 没跑 make-ca.sh | 1.3 第二步 |
| 端口被占用 `already in use` | 上次的窗口没关干净 | 00 篇 0.4 的 netstat/taskkill |

> 还不行 → 本包 `06-自救-常见报错FAQ.md`，再不行 → `manual/07` 的终极三件套
> （health 输出 + 后端日志 + 复现步骤）。
