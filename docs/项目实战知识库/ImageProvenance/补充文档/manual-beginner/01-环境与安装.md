## 1.1 这张表在说什么

| 依赖 | 版本 | 它是什么(大白话) | 谁需要它 |
|---|---|---|---|
| Node.js | ≥ 18(实测 22) | JavaScript 的运行环境,前端网页和 Hardhat 链都跑在它上面 | 合约部署、前端、测试脚本 |
| Go | ≥ 1.25 | 另一种编程语言的编译工具,后端服务器用它写 | 后端(第 4 个服务) |
| MetaMask | 浏览器插件 | 你的"数字钱包",保管私钥、签名交易 | 你(创作者) |
| c2patool | 0.26+ | C2PA 标准工具:给图片签名、验证 | 后端内部调用 |
| Kubo(IPFS) | 0.40.x | IPFS 官方实现,分布式存储节点 | 第 3 个服务(可跳过) |
| OpenSSL | 任意 | 生成"自建证书机构"(demo CA)的工具 | 首次安装时用一次 |
| PowerShell | Windows 自带 | 执行启动脚本的终端 | 你(每次启动都用) |

三个"已经内置"的东西:

- `tools/bin/c2patool.exe` 和 `tools/bin/ipfs.exe` 是 Windows 64 位版本,**项目自带,不用你装**;
- 其他平台需要自己下载,并通过环境变量 `C2PATOOL_PATH` 告诉后端工具在哪。

**一句话:** 需要你手动装的只有 **Node.js**、**Go**、**MetaMask** 三样,其余项目自带或系统自带。

## 1.2 一步步安装(首次只做一次)

### 第 1 步:装 Node.js

1. 打开 <https://nodejs.org> ,下载 LTS 版本(≥18 即可,装最新版更好);
2. 一路"下一步"安装;
3. 验证:打开 PowerShell,输入 `node -v` 回车,看到类似 `v22.x.x` 就成功了。

### 第 2 步:装 Go

1. 打开 <https://go.dev/dl> ,下载 Windows 安装包;
2. 一路"下一步";
3. 验证:`go version`,看到 `go version go1.25.x windows/amd64` 即成功。

### 第 3 步:装 MetaMask 浏览器插件

1. 打开浏览器扩展商店(Chrome: <https://chromewebstore.google.com> ;Edge 同理),搜索 "MetaMask";
2. 添加扩展,按引导创建钱包(或导入已有钱包);
3. 建议顺手把 MetaMask 固定在浏览器工具栏,后面每次操作都要点它。

> 创建钱包时它会给你 12 个"助记词"——这等于私钥的备份,**抄在纸上收好**,
> 不要截图存在电脑里。本地演示弄丢了也无所谓,但养成好习惯。

### 第 4 步:安装前端与合约依赖(需要联网,几分钟)

打开 PowerShell,进入项目目录,依次执行:

```powershell
cd F:\毕业设计\韩师academic\ImageProvenanceV2\contracts
npm install        # 合约侧依赖(Hardhat、ethers 等)

cd ..\web
npm install        # 前端侧依赖(Vue、Vite、ethers 等)
```

### 第 5 步:生成 demo CA(自建证书机构)

在 **Git Bash**(不是 PowerShell!)里执行:

```bash
cd /f/毕业设计/韩师academic/ImageProvenanceV2   # 路径以你的实际情况为准
bash tools/ca/make-ca.sh
```

**这一步在干什么(为什么要做)?**

回顾第 00 篇 0.5:C2PA 签名需要一条"证书链",而演示环境没有花钱买的证书,
所以脚本自己生成了三个文件:

| 生成的文件 | 角色 |
|---|---|
| `tools/ca/rootCA.pem` | 根证书——"信任的源头",后端把它配置为信任锚 |
| `tools/ca/sign.key` | 私钥——给图片签名用 |
| `tools/ca/sign.crt` | 叶子证书——证书链的中间环节 |

> **已知坑(重要)**:Git Bash 会把 `-subj /C=CN/...` 这类参数当成路径改写,
> 导致生成的证书 Subject 变成一串乱路径。脚本内部已用 `MSYS_NO_PATHCONV=1` 处理,
> 所以**用脚本就没事**;如果你自己手敲 openssl 命令,记得手动加这个环境变量。

### 第 6 步(可选):初始化 IPFS

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\dev\start-ipfs.ps1
```

**不做行不行?** 行。系统会自动回退到"本地内容寻址存储"(local 模式),
功能完全等价,只是没有 P2P 网络。第 00 篇 0.6 讲过两者区别。
**演示环境建议跳过**,少一个服务少一件事。

### 后端依赖呢?

Go 的依赖模块在第一次启动后端时会自动下载到项目内缓存(`.cache/go-mod`),
**不需要手动操作**。

## 1.3 可选配置(环境变量)——"开关"在哪

后端启动时会读一些环境变量来改变行为。在 PowerShell 里设置环境变量的格式:

```powershell
$env:TSA_URL = "https://freetsa.org/tsr"   # 只对当前窗口生效
```

| 变量 | 作用(大白话) | 什么时候需要动它 |
|---|---|---|
| `TSA_URL` | RFC3161 可信时间戳服务的地址(第 00 篇 0.5 讲过"双时间戳") | 想启用第三方时间戳时;不配则自动跳过,不影响主流程 |
| `PDF_UNICODE_FONT` | 证据 PDF 里中文字体的路径 | 默认自动探测 `simhei.ttf`;找不到时 PDF 中文会变问号,手动指一下 |
| `STORAGE_MODE` | `ipfs`(默认)或 `local` | 想强制本地存储时设 `local`;Kubo 没启动时自动回退,不用手动管 |
| `APP_PORT` | 后端端口 | 8080 被占时改 |
| `CHAIN_RPC_URL` | 区块链 RPC 地址 | 默认 `http://127.0.0.1:8545`,一般不用动 |

完整清单看两处(原手册指路):
- 启动脚本 `scripts/dev/start-backend.ps1`(看它读了哪些变量);
- 后端配置 `backend/internal/config/config.go`(权威定义)。

## 1.4 三个环境坑(提前打预防针)

1. **Windows curl 发中文会乱码**
   - 现象:命令行用 curl 上传,title 是中文时,后端返回 400 "title is not valid UTF-8"。
   - 原因:Windows 老版 curl 按 GBK 编码发送表单,后端只认 UTF-8(这是故意校验,防止乱码入库)。
   - 解法:中文标题走**网页上传**;或者用 UTF-8 客户端(PowerShell 7 可设
     `$PSDefaultParameterValues['*:Encoding']='utf8'`)。

2. **Git Bash 路径改写**
   - 现象:openssl 的 `-subj /C=CN/...`、ipfs 的 `/ip4/...` 参数被 Git Bash 改写成
     `C:/Program Files/Git/ip4/...` 之类的路径。
   - 解法:项目脚本已内置 `MSYS_NO_PATHCONV=1`;自己敲命令时带上:
     `MSYS_NO_PATHCONV=1 openssl ...`。

3. **MetaMask nonce 错乱(本地链特有)**
   - 现象:重启 Hardhat 后,交易一直"pending"不打包。
   - 原因:链重置归零,但 MetaMask 还记着旧的交易序号(nonce,见第 08 篇术语表),新交易序号对不上。
   - 解法:MetaMask → 设置 → 高级 → **清除活动与 nonce 数据**,选中该账户即可。
