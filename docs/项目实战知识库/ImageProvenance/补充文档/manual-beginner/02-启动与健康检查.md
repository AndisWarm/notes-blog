## 2.1 五个服务,各是什么?

| # | 服务 | 它是什么(大白话) | 端口 |
|---|---|---|---|
| 1 | Hardhat(本地链) | 一台"模拟的以太坊",跑在你电脑上;所有上链记录都存在这里 | 8545 |
| 2 | 合约部署(deploy) | 把三个智能合约"装"进本地链,并记下它们的地址 | —(一次性动作) |
| 3 | IPFS/Kubo(可选) | 分布式文件存储节点,存签名后的图片 | 5101 / 8181 |
| 4 | 后端(Go) | 全系统的"大脑":算哈希、签 C2PA、写数据库、听事件 | 8080 |
| 5 | 前端(Vue) | 浏览器里看到的网页(三个页面) | 5173 |

一句话记法:**链存记录 → 部署装合约 → 存文件 → 大脑干活 → 网页操作**。

### 为什么要"五个窗口"?

因为每个服务都是**一直运行的程序**(服务器程序不会自己退出)。
每个服务占一个 PowerShell 窗口,窗口关掉=服务停止。
所以:开 5 个窗口 → 每个窗口跑一个命令 → 都别关。

### 为什么是这个顺序?

```text
1 链  ──▶ 2 部署合约   (合约要装进链里,所以链必须先起)
2 部署 ──▶ 4 后端      (后端启动时要读"合约部署在哪"的文件,所以部署要先完成)
3 IPFS ──▶ 4 后端      (后端启动时要连存储,IPFS 先起更顺;不起也能自动回退)
4 后端 ──▶ 5 前端      (前端启动时要问后端"合约地址在哪",所以后端要先起)
```

注意:**3(IPFS)是可选服务**,跳过它系统会用本地存储,功能不受影响(第 01 篇 1.1 讲过)。

## 2.2 启动操作(照抄)

每个命令开一个新 PowerShell 窗口,窗口路径在**项目根目录** `F:\毕业设计\韩师academic\ImageProvenanceV2`。

```powershell
# 窗口 1:本地链
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\dev\start-hardhat.ps1

# 窗口 2:部署合约(在窗口 1 出现"Started HTTP..."之后执行)
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\dev\deploy-contracts.ps1

# 窗口 3(可选):IPFS
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\dev\start-ipfs.ps1

# 窗口 4:后端(在窗口 2 部署完成后执行)
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\dev\start-backend.ps1

# 窗口 5:前端
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\dev\start-web.ps1
```

### 每个窗口的"成功标志"(看到才算成功)

| # | 成功标志 | 说明 |
|---|---|---|
| 1 | `Started HTTP and WebSocket JSON-RPC server` 加 20 个账户列表 | 链起来了,还打印了 20 个测试账户(第 00 篇 0.4 讲过) |
| 2 | 打印四个合约地址,并写入 `contracts/deployments/localhost.json` | 部署完成,"地址表"存好了 |
| 3 | `Daemon is ready` | IPFS 就绪;窗口报错也别慌,后端会自动用本地存储 |
| 4 | `Starting V2 backend ...` + `chain listener started` | 后端起来了,事件监听器(第 00 篇 0.9 第 ⑧ 步)开始工作 |
| 5 | Vite 输出 `ready` 字样 | 前端就绪,浏览器可以打开了 |

### 两个"为什么"要记住

- **为什么后端要等部署完才启动?**
  后端启动时要读部署文件(`localhost.json`)和合约 ABI(第 08 篇术语表)。
  部署没做 → 后端认为"链未配置",前端会显示黄条提示。

- **为什么前端最后启动?**
  前端要从后端 `/api/chain/info` 接口拿合约地址和 ABI(第 05 篇会讲这个接口)。
  后端没起 → 前端连不上,页面功能不可用。

## 2.3 健康检查:怎么确认系统没坏

跑一遍官方检查脚本:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\dev\check-health.ps1
# 或手动(浏览器/curl 都行):
curl http://127.0.0.1:8080/api/health
```

你会看到一堆 JSON(JSON 是什么见第 05 篇 5.1),关键字段逐个解释:

| 字段 | 期望值 | 它在说啥(大白话) |
|---|---|---|
| `status` | `ok` | 后端活着 |
| `chainReady` | `true` | 链连得上,且部署文件已加载(即步骤 1、2 都完成了) |
| `chainId` | `31337` | 连的是 Hardhat 本地链(第 00 篇 0.4 讲过这个编号) |
| `signerMode` | `creator-wallet` | 后端"零私钥"模式——它声明自己手里没有签名的私钥(核心特性) |
| `c2patool.available` | `true` | C2PA 签名工具可用,附版本号 |
| `c2paTrust` | `true` | 信任锚已配置——签名能被验证为 Trusted(第 00 篇 0.5) |
| `storageBackend` | `ipfs` 或 `local` | 当前文件存哪了 |

**怎么读**:一眼扫过去,凡是 `true` / `ok` 的地方都对;出现 `false` 或 `unavailable` 就是有问题,去第 07 篇按症状查。

## 2.4 MetaMask 连接网络(一次性配置)

前端右上角点"连接 MetaMask"时会**自动请求**添加 Hardhat Local 网络,一般不用手动配。
如果自动添加失败,手动填:

| 项 | 值 |
|---|---|
| 网络名 | Hardhat Local |
| RPC URL | `http://127.0.0.1:8545` |
| Chain ID | `31337` |
| 货币符号 | ETH |

> 小知识:Chain ID 31337 是 Hardhat 的固定编号,程序靠它区分"这是本地测试链,
> 不是真钱网络"——本项目的水龙头(第 03 篇)也只在这个编号下生效。

## 2.5 常见启动问题速查(详细版在第 07 篇)

| 现象 | 原因 | 处理 |
|---|---|---|
| 前端黄色横幅"链信息不可用——请先启动 Hardhat 并部署合约" | 步骤 1/2 没做,或后端先于部署启动 | 补做部署,然后**重启后端** |
| 钱包余额 0,交易发不出 | 新账户没有测试币 | 点顶栏"**领取测试币**"按钮,充 10 ETH(仅本地链;水龙头会自动补挖一个空块,余额立即可见) |
| MetaMask 交易一直 pending | 重启过 Hardhat,nonce 错乱(第 01 篇 1.4 坑 3) | MetaMask 设置 → 高级 → 清除活动与 nonce 数据 |
| 重启 Hardhat 后"一切消失了" | 本地链数据在**内存**里,重启即清零(设计如此) | 重新执行步骤 2 部署 + 重启后端;演示前建议删 `backend/data/index.db` 让链下索引一起归零(第 07 篇 E 节详解) |
| 上传报 500 且日志里有 c2patool | demo CA 没生成(第 01 篇第 5 步漏了) | 跑 `bash tools/ca/make-ca.sh` 后重启后端 |
| 上传报 400 "title is not valid UTF-8" | Windows curl 的 GBK 编码问题(第 01 篇 1.4 坑 1) | 用网页上传 |
