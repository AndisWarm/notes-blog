# 07 故障排查(小白版)

> 本篇目标:出问题时**不慌**,按"现象 → 原因 → 解法"三级结构自查。
> 对照原手册 `manual/07-故障排查手册.md`——本篇每一条都补了"为什么",并加了
> 7.0(排查思路)和 7.8(三件套信息收集法)两节方法论。
> 启动顺序类问题先看第 02 篇。

---

## 7.0 先学会排查思路(比任何条目都重要)

遇到问题的正确姿势,按顺序做:

```text
1. 别猜,先看现象:哪个页面/哪个按钮/什么提示?
2. 看两个信息源:
   ① /api/health 输出(后端、链、工具状态一目了然,第 02 篇 2.3)
   ② 后端窗口最近 30 行日志(大部分问题答案就在里面)
3. 对号入座查本篇表格;
4. 九成问题到这一步已经解决;没解决 → 按 7.8 收集三件套再求助。
```

**万能复位手顺**(本地链演示环境的"重启大法"):
关掉五个窗口 → 删 `backend/data/index.db` → 按第 02 篇顺序重启五服务 →
MetaMask 清除活动与 nonce 数据。能解决绝大多数"环境型"问题。

## 7.1 A 类:钱包与交易

| 症状 | 原因(大白话) | 解法 |
|---|---|---|
| 交易一直 pending,不弹确认或确认后无回执 | 重启过 Hardhat,但 MetaMask 还记着**旧的交易序号(nonce)**——链已经归零,序号对不上 | MetaMask 设置 → 高级 → 清除活动与 nonce 数据(选中该账户) |
| 弹窗报 internal JSON-RPC error / cannot estimate gas | 交易会 revert(如非作者操作),或链没起 | 看页面红色提示的中文原因;确认 8545 端口存活 |
| 余额明明充了还是 0 | 充到了别的网络/账户;或没出新块(钱包按块高缓存余额) | 确认 MetaMask 在 Hardhat Local + 正确账户;系统水龙头已自动补挖块,若手动 `setBalance` 需自行 `evm_mine` |
| 提示"已在钱包中取消" | 你(或误触)点了拒绝 | 重新操作即可(前端对 user rejected 的翻译) |
| 连接钱包后 chainId 不是 31337 | 没切到 Hardhat Local 网络 | 前端会自动请求切换/添加;手动参数见第 02 篇 2.4 |
| 换了自己的新账户,无法支付 gas | 新账户余额 0 | 顶栏"领取测试币"(仅本地链;测试网用公共水龙头) |

## 7.2 B 类:登记(prepare / 上链)

| 症状 | 原因 | 解法 |
|---|---|---|
| 400 `title is not valid UTF-8` | Windows curl 按 GBK 发中文表单(第 01 篇 1.4 坑 1) | 网页上传,或终端切 UTF-8(第 05 篇 5.10 提醒) |
| 409 `already registered (xxx hash match)` | 同一文件(或其签名版/声明)已登记 | **预期行为**=防重复;换文件;`matchTier` 指明撞哪层(第 06 篇 4.5) |
| `c2paStatus: "unavailable: …"` 且无 txRequest | c2patool 路径错/不可执行 | 核对 `C2PATOOL_PATH`;`c2patool --version` 手测;看 health 的 `c2patool` 字段诊断 |
| `c2paStatus: "valid-untrusted"` | 信任锚未配置或证书不匹配(第 00 篇 0.5) | 核对 `C2PA_TRUST_ANCHORS` 指向 `tools/ca/rootCA.pem`;证书重新生成过后端要重启 |
| `c2paStatus: "invalid"` | manifest 断言不合规——**升级 c2patool 后最常见**:缺 `digitalSourceType`(本项目已内置;若改过 `manifest.go` 需保留该字段,见原手册 01 篇的版本注意) | `c2patool <签名版> trust --trust_anchors …` 看 validation_results 的失败码定位 |
| 500 `c2patool embed failed` | 证书/私钥路径失效(相对路径坑) | 路径必须绝对(config 启动时已 Abs);确认 `tools/ca` 三件套存在,首次需 `bash tools/ca/make-ca.sh` |
| 500 `pack calldata` | artifacts 与部署不匹配(改过合约没重新编译/部署) | contracts 重新 `npx hardhat compile` + deploy,重启后端 |
| 相似预警误报担忧 | pHash 对噪声/渐变类图敏感(病态输入,第 00 篇 0.7) | 预警仅提示不拦截;原理见 `learning/09` 的 phash_probe 实验 |
| 点"② 钱包上链确权"无反应 | 未连接钱包 / prepare 未成功 / MetaMask 弹窗被浏览器拦截 | 看按钮旁错误提示;检查浏览器扩展弹窗权限 |

## 7.3 C 类:授权 / 分账 / 状态标记

| 症状 | 原因 | 解法 |
|---|---|---|
| "合约拒绝:当前钱包不是该作品的链上作者" | 用非作者账户操作(**演示攻击时这是预期结果**,第 03 篇 3.3) | 切回作者账户 |
| 签发成功但记录迟迟不出现 | 监听器 2s 轮询 + 前端 3s 后刷新;若长期不出现,监听器可能没起 | 等 3–5s;查后端日志有无 `chain listener started` 与报错;游标是否推进(第 06 篇 4.3) |
| 撤销后表格没变化 | 同上(事件镜像延迟) | 刷新;超 10s 查后端日志 |
| 分账回显"读取失败" | 未装 MetaMask(只读也需要 `window.ethereum` 作 provider) | 装插件;或用脚本读链核对 |
| 状态按钮点了没反应 | 未连接钱包(按钮 disabled) | 先连接 |
| revert 提示是英文原文 | 未收录进前端翻译表的 reason(如 already revoked) | 属预期;需要可在 `LicenseView.vue` 的 revertReason 映射里加 |

## 7.4 D 类:验证与证据

| 症状 | 原因 | 解法 |
|---|---|---|
| 登记过的图验证却是"无记录" | 传的不是登记时的**原字节**(重存/截图/压缩都会变哈希,第 00 篇 0.2),或改的是**原图**而非签名版 | 用登记时的原文件;区分方法见 `learning/01` 自测 4 |
| 想演示"签名后被篡改"却得到"无记录" | 篡改对象错了 | 必须改**签名分发版**(内嵌 manifest 幸存才可反查,第 03 篇 3.6) |
| 验证显示 source=chain | 本地索引缺该记录(删过库/别处登记) | **非故障**——链上反查兜底生效(第 06 篇 4.6),反而是演示点 |
| PDF 中文变问号/缺失 | 未配置 `PDF_UNICODE_FONT` 或字体路径无效 | 指向 simhei.ttf 等 .ttf;无字体时自动回退 ASCII 属预期降级 |
| PDF 二维码扫码打不开 | `VERIFY_BASE_URL` 与实际前端地址不符 | 按实际部署地址配置后端环境变量(第 01 篇 1.3) |

## 7.5 E 类:数据与一致性

| 症状 | 原因 | 解法 |
|---|---|---|
| 重启 Hardhat 后列表还有旧作品,但都无法操作 | 链清零而 SQLite 还在,`chainWorkId` 全部失效(第 02 篇 2.5 讲过"本地链在内存里") | 删 `backend/data/index.db` 重启后端(演示环境标准归零) |
| 后端宕机期间上链的作品状态没更新 | **正常**——重启后断点续扫自动补(第 06 篇 4.3) | 重启后端等几秒;日志见 `anchored: chainWorkId=…` |
| 怀疑索引与链不一致 | 任何原因 | 终极手段:停后端 → 删 index.db(或把 `chain_cursor.last_block` 置 0)→ 重启,全量重扫重建(幂等安全) |
| `anchored (no local row)` 日志 | 有人绕过后端直接调合约注册 | 非故障;该作品不入索引但链上反查可验(设计讨论见 `learning/06`) |
| 测试脚本第二遍全挂 invalid expiry | 前一遍 `evm_increaseTime` 把链时间推前了(第 04 篇 4.2 ③) | 重启 Hardhat 再跑;或用链上时间基准的 extended 脚本 |

## 7.6 F 类:环境与工具

| 症状 | 原因 | 解法 |
|---|---|---|
| make-ca.sh 生成的证书 Subject 是一串路径 | Git Bash 把 `-subj /C=CN/...` 当路径改写(第 01 篇 1.4 坑 2) | 脚本已内置 `MSYS_NO_PATHCONV=1`;手敲命令记得加 |
| c2patool 报 trust_anchors 是非法 URL | Windows 盘符路径被当 URL scheme(`C:\...` 的 `C:` 被当成协议) | 后端已规避(锚复制到资产目录用相对路径);手动操作照做 |
| ipfs config 参数被改写成 `C:/Program Files/Git/ip4/...` | 同 MSYS 路径改写 | 用 PowerShell 跑 ipfs 脚本,或 `MSYS_NO_PATHCONV=1` |
| 8080/8545/5173 端口被占 | 残留进程 | `netstat -ano | findstr :8080` 找 PID 结束;或改 `APP_PORT` |
| go run 首次极慢 | 首次拉取/编译依赖(项目内 .cache) | 等待;之后有缓存秒级 |

## 7.7 G 类:最容易吓到小白的"假故障"

| 现象 | 真相 |
|---|---|
| 列表里出现"无记录"验证结果 | 大概率是文件变了字节,不是系统坏了(第 00 篇 0.2) |
| 黄色相似预警 | 提示不是报错,不拦截任何操作 |
| 英文 revert 提示 | 合约的原文错误,前端没翻译而已 |
| `valid-untrusted` 而非 `trusted` | 证书链问题,不是文件问题 |
| 验证页红色争议警示 | 作者自己标的,正是系统功能 |

## 7.8 还没解决?按这套流程求助

**收集三样东西**(缺一样都容易白跑):

1. **`/api/health` 完整输出**(第 02 篇 2.3 有字段解读);
2. **后端窗口最近 30 行日志**;
3. **复现步骤**:哪个页面、哪个账户、点了什么,按顺序写下来。

> 九成问题在这三样东西里已有答案。带上它们再提问或查 `learning/`,
> 效率最高。
