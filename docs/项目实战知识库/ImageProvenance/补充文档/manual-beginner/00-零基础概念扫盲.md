## 0.1 这个系统到底在解决什么问题?

先看一个日常场景:

- 小明画了一张插画,传到网上。第二天发现有人把他的画 P 了一下当成自己的作品卖。
- 小明想证明:"**这张画是我的**,而且**这份被改过的文件不是我发的**"。

传统做法有什么难处?

| 难题 | 传统手段为什么不够 |
|---|---|
| 怎么证明"我的是我的"? | 谁都能说"这是我画的",口说无凭 |
| 怎么证明"这份文件没被改过"? | 复制粘贴太容易,改一个像素肉眼根本看不出来 |
| 怎么证明"我最早发布的"? | 截图、聊天记录都能伪造 |
| 别人怎么核实? | 找小明本人要说法,可信度存疑 |

这个项目(ImageProvenance V2)的答案,是用一套组合拳:

```text
文件指纹(SHA-256 哈希)     → 任何文件都有唯一"身份证号",改一个字节就变号
数字签名 + 时间戳(C2PA)    → 给文件盖"防伪章",盖章的时间可被第三方佐证
区块链(以太坊)             → 把"谁、在什么时候、登记了什么指纹"写进公开账本,谁也改不掉
IPFS / 本地存储            → 把签名后的文件存起来,按内容寻址(内容一样地址就一样)
验证网页                   → 任何人拿一份文件,几秒钟得到鉴定结论
```

下面逐个讲清楚。**这一篇不需要记任何细节**,只要建立"这东西是干嘛的"的直觉。

## 0.2 哈希(Hash)——文件的"指纹"

### 是什么

哈希是一种数学运算:把任意一段数据(一句话、一张图、一个电影)输入进去,
输出一段固定长度的"数字指纹"。本项目用的是 **SHA-256**,输出是 64 个十六进制字符
(如 `0x9f86d081884c7d659a2feaa0c55ad015a3bf4f1b2b0b822cd15d6c15b0f00a08`)。

### 三大特性(为什么可信)

1. **同样的输入 → 同样的输出**:同一张图片算一万次,指纹都一样。
2. **改一点 → 完全变样**:图片里改一个像素,指纹就变得完全不同(不是"变化一点",是面目全非)。
3. **几乎不可能反推**:从指纹推不出原图(数学上不可行,这叫"单向性")。
4. **几乎不可能碰撞**:找不到两张不同的文件拥有同一个指纹(概率低到可以忽略)。

### 用生活类比

哈希就像人的指纹:每个人指纹不同,碰一下就能比对身份。
文件也一样——**哈希就是文件的指纹**。以后任何人说"这张图是我的原图",
你只要把它算一遍哈希,和登记时存下的哈希比对,真假立判。

### 在本项目里的角色

系统给每张登记图片算**三个哈希**(合称"哈希三元组"),后面会反复见到:

| 哈希 | 算的是谁 | 用途 |
|---|---|---|
| `originalHash` 原图哈希 | 你上传的原始图片 | 证明"这张原图存在过、长这样" |
| `signedHash` 签名版哈希 | 签名后产出的新图片 | 证明"官方签名版是这张" |
| `manifestHash` 声明哈希 | 一段文字声明(JSON) | 证明"这段声明是谁写的、写了啥" |

> 记不住没关系,第 06 篇还有详解。现在只要记住:**哈希 = 文件的指纹**。

## 0.3 数字签名与公钥密码——"防伪章"

### 先讲个故事:图章

现实中盖公章:章在领导手里,别人盖不了;大家认章不认人。
数字世界没有实物章,于是用"**公钥 + 私钥**"这对钥匙来代替:

- **私钥**:只有你一个人知道的一串随机数(相当于你的签名笔迹,丢了就完了)。
- **公钥**:从私钥算出来的另一串数,可以公开给全世界(相当于你的印章图案,人人可核对)。

### 签名 = 用私钥"盖戳"

拿你的私钥对一段内容做运算,得到"签名"。任何人拿你的**公钥**都能验证:
"这段内容确实是持有那把私钥的人签的,而且内容没被改过"。

关键点:

- **私钥签名,公钥验证**:私钥只有你有,所以签名无法伪造(除非私钥泄露)。
- **内容被改动,签名立刻失效**:签名绑定的是"内容本身",内容变了验签就失败。
- **你无法抵赖**:签名是私钥产生的,全世界都能验证是你签的(这叫"不可否认性")。

### 以太坊账户就是一把"钥匙对"

- **地址(Address)**:形如 `0x70997970C51812dc3A010C7d01b50e0d17dc79C8`,
  相当于银行账号,可以公开。
- **私钥(Private Key)**:形如 `0x59c6995e...`,相当于银行卡密码,绝不能给别人。
- **交易(Transaction)**:以太坊上的任何操作(转账、调合约)都是一条"交易",
  必须用私钥签名后才能被网络接受——**谁签的名,网络就认为是谁在操作**。

> 本项目的核心设计"后端零私钥"就来自这里:上链操作必须由**创作者自己的钱包**签名,
> 后端(服务器)手里没有私钥,所以它想冒充创作者也做不到。谁签名,谁就是作者。

### 钱包(Wallet)是什么

钱包 = 管理私钥 + 帮你签名交易的软件。本项目用 **MetaMask** 浏览器插件。
它把私钥存在你本地浏览器里,每次需要上链时弹出窗口让你确认并签名。
**私钥永远不出你的电脑**,这就是"钱包直签"的含义。

## 0.4 区块链与以太坊——"无法篡改的公开账本"

### 是什么

区块链是一条**不断增长的记录链**:每一页(块)记录一批操作,并且每一页都
包含前一页的哈希(指纹)。所以:

- **改动任何一页,后面所有页的指纹全对不上** → 改不动(篡改即暴露)。
- **账本是公开的,人人可下载核对** → 无法偷偷改。
- **没有单一老板**:由很多节点共同维护,少数节点想删改也没用。

### 智能合约(Smart Contract)

账本不光能记账,还能执行程序:把一段规则写成代码部署到链上,
任何人都按规则与它交互,规则**一旦部署就不可更改**(代码即法律)。
本项目有三个核心合约,第 03 篇会逐个演示:

| 合约 | 管什么 | 类比 |
|---|---|---|
| RegistryV2 | 作品登记:存三个哈希、作者地址、作品状态 | 版权登记处 |
| LicenseV2 | 授权:作者给谁、用在哪、到什么时候 | 授权合同库 |
| RoyaltyV2 | 分账规则:收益怎么分 | 分成协议 |

### 交易、Gas、区块、事件——四个高频词

| 词 | 解释 | 类比 |
|---|---|---|
| 交易 Transaction | 你签名的每一条操作(登记、授权、改状态) | 盖了章的合同 |
| Gas | 执行交易要付的"手续费",用 ETH 支付 | 邮费/跑腿费 |
| 区块 Block | 一段时间内交易的集合,打包成一页账本 | 账本的一页 |
| 事件 Event | 合约执行时发出的"广播",链下可以监听 | 登记处贴出的公告 |

### 本项目为什么用 Hardhat(本地链)而不是真实以太坊?

| 对比项 | Hardhat 本地开发链 | 真实以太坊主网 |
|---|---|---|
| 部署成本 | 免费,秒部署 | 需要真金白银 ETH |
| 速度 | 秒级出块 | 十几秒一个块 |
| 安全性 | 随便折腾,坏了重启 | 操作不可逆,犯错损失真实资产 |
| 定位 | **本项目的默认运行环境** | 本项目不上主网(研究边界) |

Hardhat 会给你 20 个**测试账户**,每个都带 10000 ETH 测试币——这就是演示时
"甲、乙、平台方"三个角色的来源。本地链的 Chain ID 是 `31337`。

> ⚠️ Hardhat 的测试私钥是**公开的、全世界都知道的**。
> 只能用在本地链上,永远不要拿它去真实网络碰真实资产。

## 0.5 C2PA 与内容凭证——给图片"盖防伪章"

### 先理解"凭证"(Provenance)

凭证 = 一件东西的"来历记录"。对图片来说:谁创作的?什么时间?有没有被改过?
传统图片里,这些信息以"元数据"形式存在(如 EXIF 里的相机型号),
但**任何人都能改**,不可信。

### C2PA 是什么

**C2PA**(Coalition for Content Provenance and Authenticity,内容来源与真实性联盟)
是一个行业标准,由 Adobe、微软、BBC 等大厂共同制定。
它把"内容凭证"直接**嵌进文件本身**:图片里写入一段"声明"(manifest),
再用**数字证书签名**。于是:

- 图片里自带"出生证明"(谁、何时、什么内容);
- 用标准工具(c2patool)打开就能验证:签名有效吗?内容被改过吗?

### C2PA 的信任链(Trust Chain)

光有签名还不够——签名是谁签的?怎么知道他可信?答案是"证书链":

```text
根证书(rootCA)──签发──> 叶子证书(sign.crt)──签名──> 图片里的声明
     ↑                                        ↑
  "最可信的源头"                    验证时:从图片证书一路追到根证书
```

- 浏览器/系统内置了一批"根证书"叫**信任锚(Trust Anchor)**:证书链能追到
  信任锚,就判 **Trusted(可信)**;追不到,就判 **Valid(签名有效但不被信任)**。
- 真实世界的证书要花钱向机构买。本项目是教学/演示环境,所以**自建了一个
  根证书**(demo CA),把它的公钥配成"信任锚"——于是自己签的图片就是 Trusted。
  这个过程在安装时执行一次(`make-ca.sh`)。

### "Trusted" vs "Valid" vs "Invalid"(记三个词)

| 验证结果 | 含义 | 通俗说法 |
|---|---|---|
| Trusted | 签名有效 + 证书链落在信任锚内 | "正规渠道发的防伪章,验过了是真的" |
| Valid(untrusted) | 签名有效,但根证书不在信任列表 | "章是真的,但发章机构我不认" |
| Invalid | 签名/内容校验失败 | "章是假的,或文件被改过了" |

### 时间戳(Timestamp):防"事后补签"

签名只能证明"内容没被改",不能证明"签名是什么时候做的"——可以把旧文件
翻出来重新签名,冒充"当时就签了"。解法是**时间戳**:

- 本项目用**双重时间戳**:
  1. **区块时间**:交易被打进区块的时间(区块链背书);
  2. **RFC3161 可信时间戳**:向第三方时间戳服务器(TSA)申请,得到一份
     "在某时刻该内容确实存在"的带签名证明。
- 两者互为补充:区块时间证明"登记发生在块 X",RFC3161 证明"签名版在 T 时刻已存在"。

## 0.6 IPFS——"按内容寻址的云盘"

### 普通存储 vs IPFS

| | 普通云盘(按名字找) | IPFS(按内容找) |
|---|---|---|
| 你问服务器 | "给我 `photo.jpg`" | "给我内容哈希为 `Qm...` 的文件" |
| 地址由谁定 | 服务器管理员 | **文件内容本身**(内容相同地址必相同) |
| 文件被改 | 名字不变,内容变了 | 地址变(因为内容变了) |
| 好处 | 习惯 | **改一个字节,地址就变** → 天然防篡改证明 |

### CID(Content Identifier,内容标识符)

IPFS 里每个文件的地址叫 CID,形如 `QmXoypizjW3WknFiJnKLwHCnL72vedxjQkDDP1mXWo6uco`。
因为 CID 由内容算出,所以:**"拿到 CID 的文件" = "和当初存的字节一模一样"**,
中途任何改动都会让 CID 对不上。这就是"内容寻址"的意义。

### 本项目怎么用

- 签名完成后的图片和声明文件都会存进 IPFS(或本地等价实现),得到 CID;
- 你登记结果卡片上的"签名版 CID",就是它的取件地址;
- 本地模式(不开 Kubo)时,CID 形如 `local-<sha256>`,文件落在 `backend/data/objects/` 下,
  功能等价,只是没有 P2P 网络。

## 0.7 pHash(感知哈希)——"相似的指纹"

SHA-256 是"改一个字节就完全不同",但现实里更常见的是:
"有人把我的图调个亮度、转个角度、重新压缩一下再发出去"——字节全变了,
SHA-256 完全失效,但人眼一看还是"同一张图"。

**pHash(感知哈希)** 专门解决这个:它提取图片的**视觉特征**做成 64 位指纹,
视觉上相似的两张图,它们的 pHash 也相近(用"汉明距离"度量,距离越小越像)。

在本项目里的定位:

- 上传登记时,若与已登记图片**视觉相似**(汉明距离 ≤ 阈值),给出**黄色预警**;
- **仅提示,不拦截**——它只是提醒"这张图看起来和 X 很像,确认是你自己的吗";
- 注意边界:它**不是**相似图检索系统,对渐变、噪点类图片容易误报(病态输入),
  本项目不做 AI 生成检测、不做相似图搜索。
