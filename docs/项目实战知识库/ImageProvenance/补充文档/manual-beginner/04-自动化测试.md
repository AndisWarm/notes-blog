# 04 自动化测试与云端回归(小白版)

> 本篇目标:搞清楚"测试脚本都是干嘛的、什么时候跑、跑完看什么"。
> 不需要会写测试,只要会**跑**、会**读结果**。
> 对照原手册 `manual/04-自动化测试与云端回归.md` 阅读。

---

## 4.1 先建立直觉:为什么需要自动化测试?

手工演示(第 03 篇)一次只能验证一条路径,而且依赖人眼判断。
自动化测试 = 写好的"机器人",按脚本把系统**翻来覆去地检查**:

- 检查"正常流程"能不能通(快乐路径);
- 检查"坏人操作"会不会被拦(攻击用例);
- 检查"边界情况"(空参数、幽灵 ID、重复操作)会不会炸;
- 每次改完代码重跑一遍,确保没把旧功能改坏(回归)。

系统里有**四类**测试,覆盖不同层级:

```text
合约单测(最底层)      → 三个合约的每个函数对不对
后端单测(次底层)      → Go 代码的每个模块对不对
E2E 全链路(最顶层)    → 从上传到上链到验证,整条链路通不通
性能/Gas 采集(辅助)   → 每笔操作花多少钱、多快
```

---

## 4.2 四类测试逐一说清

### ① 合约单测:`cd contracts && npm test`

| 项 | 内容 |
|---|---|
| 用例数 | 20 个(其中含 6 组攻击用例) |
| 前置条件 | **无需任何服务**(用 Hardhat 内置网络) |
| 查什么 | 登记、查重、授权、撤销、分账、状态标记、越权回滚……每个合约函数 |
| 覆盖率 | `npx hardhat coverage` 可得 98.5% |
| 大白话 | "合约这个'法律文本'逐条验收:每个条款该执行的执行,该拒绝的拒绝" |

> 想加覆盖率报告:在 `contracts` 目录跑 `npx hardhat coverage`。

### ② 后端单测:`cd backend && go test ./...`

| 项 | 内容 |
|---|---|
| 范围 | repository(数据库层)/ c2pa(签名层)/ similarity(相似度)三个模块 |
| 前置条件 | 无需服务 |
| 大白话 | "后端每个零件单独质检" |

### ③ E2E 全链路测试(三个脚本,需要五个服务全启动)

| 脚本 | 用例数 | 查什么 |
|---|---|---|
| `node scripts\dev\e2e-demo.mjs` | 15 | 全链路验收:prepare → 上链 → 事件镜像 → 四态验证 → PDF,双账户正反用例 |
| `node scripts\dev\test-license-flow.mjs` | 22 | 状态流转 + 授权/撤销/过期/越权 + 分账专项 |
| `node scripts\dev\test-license-flow-extended.mjs` | 31 | 边界扩展:负例参数、幽灵 ID、双重撤销、hasRule、状态镜像、faucet 回归 |

**几个你必须知道的细节:**

1. **它们不需要 MetaMask**:脚本直接用 Hardhat 公开测试私钥签名发交易
   (第 03 篇 3.7 说过,签名需要私钥——测试私钥是公开的,脚本拿来就用);
2. **每轮生成随机像素 PNG**:哈希唯一,可反复运行,不会撞"重复登记";
3. ⚠️ **"长活节点"警告**(重要!):
   - `test-license-flow*.mjs` 会调用 `evm_increaseTime` 把链的时间**快进 2 小时**,
     而且**不可回退**;
   - `extended` 脚本以链上区块时间为基准,**可连续重跑**;
   - 主脚本 `test-license-flow.mjs` 用墙钟(`Date.now()`)算有效期,
     **在同一个不重启的节点上第二次运行会误报** `invalid expiry`
     (因为链时间被快进过,而脚本用本机时间算)——合约行为其实是正确的;
   - 解法:重启 Hardhat 再跑,或把脚本里那行换成
     `(await provider.getBlock('latest')).timestamp`。

### ④ 性能采集:`node scripts\dev\collect-performance.mjs 10`

| 项 | 内容 |
|---|---|
| 干什么 | 跑 10 轮,记录每步耗时和 Gas 消耗 |
| 产出 | `reports/test-results/performance-table.md`(人读表)和 `performance-raw.json`(原始数据) |
| 大白话 | "量一量系统跑得快不快、上链贵不贵" |

## 4.4 云端自动化回归(Claude Cowork)

### 这是啥?

把整套测试**交给云端沙箱跑**,不在你电脑上执行:

- **适合**:本机服务没起、不想占机器、想要"从源码从零复刻环境"级别的独立验证;
- **怎么做到的**:云端从项目源码搭出等价环境——用 go-ethereum v1.16.7 内核构建
  与 Hardhat 等价的开发链(同样的 chainId 31337、同一组测试账户、支持
  `evm_increaseTime`/`hardhat_setBalance`,合约部署地址与本机完全一致)、
  离线构建 Go 后端、从 crates.io 安装 c2patool——然后跑全部用例;
- **可信度锚点**:同一笔 `registerWork` 的 gas 消耗,云端 412,516 vs 本机 412,528
  (只差 12,几乎一致);四个合约地址逐一相同——说明两端环境是等价的。

### 怎么发起?

1. 打开 Claude 桌面版,新建 **Cowork 任务**;
2. 连接本项目文件夹;
3. 直接说明要测的范围,例如:

   > 帮我云端自动化回归:作品签名上链后的所有状态、授权管理中的签发授权方 / 分账 / 授权记录。发现小问题直接修并回写。

- 本机**无需启动任何服务**;进行中可以关笔记本,云端会话继续执行。

### 产出是什么?

- 测试报告写入 `reports/test-results/`(用例-预期-实测明细、环境差异表、问题分析);
- 确认的缺陷直接修复并回写项目文件,在 `docs/04-开发日志.md` 追加记录;
- 新增的可复跑脚本(如 `test-license-flow-extended.mjs`)同步落库。

### 云端跑不了的(需要本机补验的三件事)

| 项 | 为什么 |
|---|---|
| `web` 的 `npm run build` / Vite 构建 | 沙箱无 npm 源;前端改动云端只做语法级校验 |
| RFC3161 时间戳实测、IPFS 真实模式 | 沙箱无公网 TSA;IPFS 用本地内容寻址等价替代 |
| MetaMask 真实弹窗交互 | 属于人工验收环节,按第 03 篇走一遍即可 |

## 4.5 测试使用决策速查

```text
我只想验证合约逻辑         → cd contracts && npm test
我改了 Go 代码             → cd backend && go test ./...
我刚启动完五服务,想全面体检 → e2e-demo.mjs + test-license-flow*.mjs
我想看性能/Gas             → collect-performance.mjs 10
我不想在本机跑             → Claude Cowork 云端回归
```

> 记住一条:测试脚本跑出来的"失败"不一定是 bug——先看报错对应哪个用例,
> 对照第 4.2 ③ 的"长活节点警告",很多是环境/时序问题而不是代码问题。
