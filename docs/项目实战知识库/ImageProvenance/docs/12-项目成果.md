## 1. 功能成果

### 1.1 身份与登记闭环

- `POST /api/works/prepare` 完成原图哈希、重复检查、C2PA manifest 生成、签名、信任验证、pHash 预警和存储。
- 后端返回 `{to, data, chainId}` 形式的 `txRequest`，由前端 ethers v6 调用 MetaMask 发送 `registerWork`。
- `RegistryV2` 使用交易调用者作为作者，避免后端热钱包代签导致的身份失真。
- 作品状态从 `PENDING_ANCHOR` 进入 `ANCHORED` 后，监听器回填链上作品编号、作者地址、交易哈希和区块号。

### 1.2 四态来源验证

验证接口 `POST /api/works/verify-file` 的核心结果如下：

| `matchTier` | 含义 | 判断依据 |
|---|---|---|
| `original` | 原始登记文件 | 命中 `originalHash` |
| `signed` | 官方 C2PA 签名分发版 | 命中 `signedHash`，且签名有效 |
| `manifest-only` | 签名后被修改 | 文件内 manifest 仍指向已登记作品，但文件哈希不再匹配；C2PA 状态为 `Invalid` |
| `none` | 无记录或声明已被破坏 | 三哈希、链上反查和 manifest 反查均未形成有效关联 |

验证优先查询 SQLite；链下未命中时回退到 `RegistryV2.getWorkByHash`，因此 SQLite 是索引而不是唯一事实源。

### 1.3 授权、分账与状态闭环

- `LicenseV2` 支持按作品签发授权、指定被授权地址、用途和有效期，支持撤销、过期判断和按作品枚举。
- `RoyaltyV2` 使用基点记录创作者与平台分成比例，比例总和强制为 10000，并提供只读查询和前端回显。
- `RegistryV2.setStatus` 仅允许作者将作品标记为 Active、Disputed 或 Revoked。
- `LicenseGranted`、`LicenseRevoked` 和 `WorkStatusChanged` 事件会被监听器镜像，授权页和来源验证页可查看授权记录及权属风险提示。

### 1.4 可信内容凭证与取证材料

- 使用 P-256 Root CA 和 ES256 叶子证书为 C2PA manifest 签名。
- 对比实验表明：默认信任列表下为 `untrusted`，加载自建 Root CA 作为 trust anchor 后为 `Trusted`。
- 证据 PDF 包含三哈希、作者地址、交易与区块信息、区块时间、可选 RFC3161 时间戳以及直达验证页的二维码。

### 1.5 存储与可用性增强

- IPFS/Kubo 启动时使用内容寻址存储；未配置 IPFS 时自动回退本地内容寻址实现。
- pHash 使用汉明距离阈值 10 进行相似作品预警，仅提示，不阻断登记。
- 本地开发链提供仅限 chainId 31337 的测试水龙头；充值后主动挖空块，解决 `hardhat_setBalance` 不出块导致 MetaMask/ethers 余额缓存不刷新的问题。

## 2. 安全与质量成果

### 2.1 主动攻击用例

项目没有只验证正常流程，而是针对主要安全属性设计了攻击性测试：

| 威胁 | 防御机制 | 验证结果 |
|---|---|---|
| 重复注册或抢注 | 三个哈希都写入 `hashIndex`，后端先返回 409，合约再次拒绝 | 单测和 E2E 均通过 |
| 越权签发授权 | `LicenseV2` 校验 `registry.authorOf(workId) == msg.sender` | 非作者交易 revert |
| 越权修改分账 | `RoyaltyV2` 复用作者校验 | 非作者操作 revert，原规则不变 |
| 过期或撤销授权继续生效 | `isLicensed` 同时检查 `revoked` 和 `validUntil` | 快进时间或撤销后返回 false |
| 签名文件被篡改 | 三哈希精确匹配 + C2PA hard binding | 修改 1 字节可识别为 `manifest-only` / `Invalid` |
| 链下索引丢失 | 链上 `getWorkByHash` 回退，索引可从事件重放 | 验证分支和断点续扫通过 |

### 2.2 缺陷修复与兼容性成果

- **C2PA 前向兼容**：c2patool 0.27+ 对 C2PA 2.1 的 `c2pa.created` 要求更严格，补充 `digitalSourceType` 后，0.26 与 0.27 版本均可生成并验证为 `Trusted`。
- **中文编码防护**：针对 Windows curl 以 GBK 发送中文标题的问题，在 API 入口增加 UTF-8 有效性校验，异常字节直接返回 400，避免乱码数据进入 SQLite 和 manifest。
- **授权管理可观察性**：增加 royalty 只读合约通道，设置分账后可在授权页读回创作者比例、平台比例、平台地址和更新时间。
- **链上状态可见性**：补齐 `WorkStatusChanged` 事件镜像，作者标记争议或撤销后，列表、详情和验证页都能显示警示。
- **钱包余额缓存问题**：本地水龙头改为“充值 + 出块 + 前端读取到账余额”，修复“点击领取没反应”的演示故障。

## 5. 可直接写入简历的成果表述

可根据目标岗位选择 3～4 条：

- 设计并实现基于区块链与 C2PA 的图像确权溯源系统，采用创作者钱包直发交易和 `author = msg.sender` 模型，后端零私钥；通过 SHA-256 三哈希、链上 `hashIndex` 和 C2PA manifest 实现四态来源验证。
- 实现 Go/Gin 事件驱动链下索引：FilterLogs 轮询、游标断点续扫和幂等 upsert 镜像到 SQLite，支持链下索引丢失后的链上反查；10 轮性能采集验证查询均值约 3 ms。
- 实现 License/Royalty/Status 合约权限闭环，通过 `IRegistry.authorOf` 阻断越权授权和越权分账，覆盖授权撤销、过期判断、状态镜像和前端风险提示。
- 基于 OpenSSL 自建 ES256 demo CA 与 C2PA trust anchor，解决开发证书始终 `untrusted` 的问题；补充 `digitalSourceType` 后兼容 c2patool 0.26/0.27。
- 建立合约单测、后端单测、E2E 和独立环境回归四层测试体系：合约 20/20、行覆盖率 98.55%、两轮全量回归 76/76。

## 6. 诚实边界与后续方向

### 当前边界

- 当前验证环境为 Hardhat 本地链，尚未宣称已部署以太坊主网或公共测试网。
- 自建 CA 仅用于演示 C2PA 信任模型，生产环境需要接入正式信任列表成员证书和证书生命周期管理。
- `RoyaltyV2` 只保存分账规则，没有实现真实支付、自动结算或账单对账。
- pHash 只提供相似预警，不能替代大规模图像检索、版权比对或 AI 生成检测。
- `MockJudicialAnchor` 仅演示合约接口和事件形态，尚未对接真实司法链。
- 当前 API 面向本地演示，鉴权、限流、多实例部署、链重组确认数和公网上的存储多副本仍需补充。

### 可继续演进

- 使用 EIP-712 元交易降低用户首次使用时的钱包与 gas 门槛。
- 将事件轮询替换为 WebSocket 订阅，并保留游标和确认数机制处理断线与链重组。
- SQLite 迁移到 PostgreSQL，增加异步任务队列和 c2patool 工作池以支持并发 prepare。
- 接入生产级 IPFS pinning、多副本备份、正式 C2PA 证书和 CI 全量回归。
