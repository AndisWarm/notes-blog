# 答辩演示脚本（5 分钟版）

> 前置：按 README 顺序启动五个服务；MetaMask 导入 Hardhat 账户 #1（创作者甲）与 #2（用户乙），
> 网络切到 Hardhat Local（chainId 31337, http://127.0.0.1:8545）。
> 备好素材：一张原图 A.png；提前用 A.png 的官方签名版复制一份并用十六进制编辑器改 1 字节得 A-tampered.png。

## 开场 30 秒：一句话定位

"本系统面向多方互信场景，把 C2PA 国际标准的文件内来源声明与区块链的跨主体锚定结合起来，
解决图像作品在确权时点之后的声明、授权与取证问题。三个关键设计：链上作者就是创作者钱包本人、
哈希三元组支持链上直接反查、C2PA 签名在自建信任链下验证为 Trusted。"

## 第 1 幕（90 秒）：创作者确权 —— 身份闭环

1. 浏览器打开 http://127.0.0.1:5173，MetaMask 连接**账户甲**；
2. 创作者页上传 A.png，填标题 → 点"① 生成声明与签名"；
   - 指着结果卡讲三哈希：原图哈希 / 签名版哈希 / 声明哈希，以及 **C2PA trusted** 徽标；
3. 点"② 钱包上链确权" → MetaMask 弹窗（强调：**是我的钱包在签名，系统后端没有私钥**）→ 确认；
4. 列表状态变 ANCHORED，作者地址 = 甲的地址。
   - 讲点：一期常见做法是后端代签，链上作者全是服务器地址；本系统 author=msg.sender，确权真实。

## 第 2 幕（60 秒）：越权攻击演示 —— 授权闭环

1. MetaMask 切到**账户乙**，进"授权管理"，选甲的作品，给自己签授权 → 交易被合约拒绝，
   页面提示"当前钱包不是该作品的链上作者（越权保护生效）"；
2. 切回**账户甲**，同样操作 → 成功，几秒后授权记录出现在列表。
   - 讲点：License 合约通过 IRegistry.authorOf 跨合约校验，这是主动设计的攻击用例之一（共 6 组，见测试报告）。

## 第 3 幕（90 秒）：验证与篡改检测 —— 验证闭环

进"来源验证"页，依次拖入三个文件：
1. **A.png 原图** → 绿色"原始文件"（originalHash 命中）；
2. **官方签名版** → 绿色"官方签名分发版"（signedHash 命中）；
3. **A-tampered.png** → 红色"签名后被篡改"：嵌入的 C2PA 声明仍指向作品 #N，但字节不匹配，
   C2PA 校验状态 Invalid（hard binding 发现像素被改）。
   - 讲点：SHA-256"一改即变"正是篡改检测想要的性质；"图被压缩截图后找相似图"是相似检索问题，
     明确不在本系统边界内（研究边界第 6 条）。

## 第 4 幕（60 秒）：取证材料 —— 信任闭环收尾

1. 点作品的"证据 PDF"：展示三哈希、交易哈希、区块号、**双时间戳**（链上 block.timestamp + RFC3161）、
   C2PA 信任状态、二维码（扫码直达验证页）；
2. 一句边界声明收尾："PDF 是技术取证材料与维权线索，不直接宣称司法证据效力；
   合约层预留了 JudicialAnchor 接口，实际接入司法链需机构备案，超出本课题范围。"

## 备选加演（时间富余时）

- **相似预警**：上传一张加了小水印的近似图 → prepare 返回"与作品 #N 感知哈希相近"的黄色预警（仅提示不阻断）；
- **信任列表对照**：终端跑 `c2patool <签名图>`（untrusted）vs `c2patool <签名图> trust --trust_anchors rootCA.pem`（Trusted），讲 C2PA 信任模型；
- **断点续扫**：kill 后端 → 链上发交易 → 重启后端 → 索引自动补齐（链上链下一致性设计）。

## 答辩预期追问速查

| 追问 | 应答要点 |
|---|---|
| 后端没私钥，那谁付 gas？ | 本地链免费；生产环境用已设计的 EIP-712 元交易（docs/05），签名权与 gas 支付权分离 |
| 数据库被删了怎么办？ | 验证自动回退链上 getWorkByHash 反查，链下库只是加速缓存 |
| 自建 CA 有意义吗？ | 等价于联盟场景平台方 CA；演示的是 C2PA 信任模型本身——同一签名，信任列表内外结论不同 |
| Gas 多少？ | registerWork 实测均值约 36.8 万；比单哈希方案贵约 10 万 gas，换来链上反查与防抢注 |
