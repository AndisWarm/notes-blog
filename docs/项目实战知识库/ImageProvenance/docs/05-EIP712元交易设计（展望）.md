# EIP-712 元交易设计（展望，未实现）

> 定位：论文第 6 章"展望"的实体支撑。本文档只做设计，不在二期实现。
> 动机：当前主路径要求创作者钱包直接发交易（本地链免 gas，无门槛）。若部署到真实联盟链/测试网，
> 要求普通创作者持有 gas 代币会成为使用门槛。元交易（meta-transaction）让创作者只签名、平台代付 gas，
> 同时保持"链上作者 = 创作者"的身份闭环不被破坏。

## 一、问题定义

| 方案 | 作者身份 | 创作者需持 gas | 后端信任要求 |
|---|---|---|---|
| 一期：后端热钱包代签 | ❌ 失真（author=后端） | 否 | 完全信任（可伪造任何登记） |
| 二期：创作者钱包直发 | ✅ 真实 | 是 | 无需信任（后端无签名权） |
| 展望：EIP-712 元交易 | ✅ 真实（ecrecover 恢复） | 否 | 半信任（只能代发不能伪造） |

关键洞察：**签名权与 gas 支付权可以分离**。EIP-712 让创作者对结构化数据签名（钱包中可读展示，
不是盲签哈希），合约用 `ecrecover` 从签名恢复创作者地址作为 author，转发者（relayer）只出 gas。

## 二、合约设计（RegistryV3 增量）

```solidity
// EIP-712 域与类型
bytes32 private constant REGISTER_TYPEHASH = keccak256(
    "RegisterWork(bytes32 originalHash,bytes32 signedHash,bytes32 manifestHash,"
    "string imageCid,string manifestCid,uint256 nonce,uint256 deadline)"
);

mapping(address => uint256) public nonces;   // 防重放

function registerWorkWithSig(
    bytes32 originalHash, bytes32 signedHash, bytes32 manifestHash,
    string calldata imageCid, string calldata manifestCid,
    uint256 deadline,
    uint8 v, bytes32 r, bytes32 s          // 创作者的 EIP-712 签名
) external returns (uint256 id) {
    require(block.timestamp <= deadline, "signature expired");
    bytes32 structHash = keccak256(abi.encode(
        REGISTER_TYPEHASH, originalHash, signedHash, manifestHash,
        keccak256(bytes(imageCid)), keccak256(bytes(manifestCid)),
        nonces[creator]++, deadline));
    bytes32 digest = _hashTypedDataV4(structHash);   // OpenZeppelin EIP712
    address creator = ecrecover(digest, v, r, s);
    require(creator != address(0), "invalid signature");
    // 复用 registerWork 内部逻辑，author = creator（不是 msg.sender=relayer）
    id = _register(creator, originalHash, signedHash, manifestHash, imageCid, manifestCid);
}
```

安全要点：
1. **nonce 防重放**：同一签名只能上链一次；
2. **deadline 防囤签**：过期签名作废；
3. **域分隔符**（chainId + 合约地址）防跨链/跨合约重放；
4. relayer 无法篡改任何字段——改一个字节 ecrecover 就恢复不出创作者地址。

## 三、前后端流程

```text
创作者钱包                     后端(relayer)                    链
   |  eth_signTypedData_v4        |                             |
   |  (MetaMask 结构化展示) -----> |                             |
   |                              |  registerWorkWithSig(...,v,r,s)
   |                              |  relayer 私钥签名, 代付 gas -> |
   |                              |                              | ecrecover -> author=创作者
```

前端改动：`useWallet.js` 增加 `signTypedData(domain, types, message)`；
后端改动：恢复一个 relayer 钱包（但它**不能决定 author**，与一期代签有本质区别——
一期后端说谁是作者就是谁，元交易模式下 author 由密码学签名唯一决定）。

## 四、为何二期不实现

1. 本地 Hardhat 链 gas 免费，元交易解决的问题（gas 门槛）在演示环境不存在；
2. 增加 relayer 钱包管理、nonce 同步、签名过期处理三块复杂度，偏离二期"做实四个闭环"的主线；
3. 答辩表述："系统主路径为钱包直发；面向生产环境已完成 EIP-712 元交易设计（见设计文档），
   作为后续工作可在不破坏身份闭环的前提下消除创作者的 gas 门槛。"
