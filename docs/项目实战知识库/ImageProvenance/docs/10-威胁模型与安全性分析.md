# 威胁模型与安全性分析

> 方法:资产界定 → 信任边界 → 攻击者模型 → 威胁枚举(按 STRIDE 组织)→
> 防御与验证映射 → 残余风险。与 `reports/test-results/attack-cases.md`(测试证据)
> 互为表里:本文回答"防什么、为什么够",报告回答"验过没有"。
> 可整体改写为论文"安全性分析"一节;答辩讲安全从这里切入。

## 一、保护什么(资产)

| 资产 | 安全属性诉求 |
|---|---|
| A1 作品登记记录(三哈希、CID、时间) | 完整性、不可篡改、可公开验证 |
| A2 作者身份(author 字段) | 真实性——必须是创作者本人,不可被平台或他人顶替 |
| A3 授权关系与分账规则 | 只能由作者创建/变更;记录可追溯 |
| A4 证据材料(PDF、双时间戳) | 可独立核验,不依赖平台存活 |
| A5 作品内容本体 | 完整性可验;**保密性不在目标内**(登记即公开语义,见残余 R5) |

## 二、信任边界

```text
[用户钱包/MetaMask]──签名──▶[前端 Vue]──HTTP──▶[后端 Go]──RPC──▶[链节点/合约]
      可信根:用户私钥            不可信输入源        半可信(零私钥)      信任根:共识
                                                    │
                                              [c2patool+CA] [IPFS/本地存储] [TSA]
```

关键立场:**平台后端被设计为"即使被攻破也伪造不了作者身份"**——它没有私钥,
链上 author 来自交易签名,信任根在用户钱包与链共识,不在平台。

## 三、攻击者模型

| 攻击者 | 能力假设 |
|---|---|
| T1 外部匿名者 | 可访问全部 API(无鉴权)、可读链上全部数据、可任意上传文件 |
| T2 恶意用户(如乙) | T1 + 拥有合法钱包,可直接调用任何合约方法(绕过前端) |
| T3 被攻破的后端 | 控制 API 响应与链下数据库,但**无任何链上私钥** |
| T4 网络中间人 | 本地演示不设防(HTTP);生产需 TLS,记入残余 |
| 不设防 | 51% 算力攻击、用户私钥失窃、供应链投毒(超出课题边界,论文声明即可) |

## 四、威胁枚举与防御映射(STRIDE)

| # | STRIDE | 威胁场景 | 防御机制 | 验证证据 |
|---|---|---|---|---|
| S1 | 假冒 | 平台代签导致 author 失真(一期真实缺陷) | 创作者钱包直发交易,author=msg.sender;后端零私钥 | E2E"on-chain author == creator wallet";health.signerMode |
| S2 | 假冒 | T2 替他人作品签发授权/改分账/改状态 | LicenseV2/RoyaltyV2/Registry 三处 `authorOf==msg.sender` | 攻击用例三组"not author" revert;E2E 双账户实测 |
| S3 | 假冒 | 伪造 C2PA 声明(自签一个假 manifest) | 信任锚校验:非本 CA 签发 → untrusted,不得 trusted | trust 对照实验(c2pa-trust-comparison.md) |
| T1' | 篡改 | 改动已签名文件内容 | C2PA hard binding → Invalid;哈希不命中;manifest-only 定位到原作品 | flow"篡改签名版 → manifest-only + Invalid" |
| T2' | 篡改 | 篡改链下 SQLite(T3) | 链为唯一真相源:hashIndex 反查兜底、索引可全量重建 | "删库验证"实验(source=chain);断点续扫用例 |
| T3' | 篡改 | 抢注他人作品(先上传占坑) | 三哈希链上查重 revert + 后端 409 双拦截;pHash 近似预警 | E2E 409+duplicate revert;相似预警正例 |
| R1 | 抵赖 | 作者否认"登记/授权是我做的" | ECDSA 交易签名不可抵赖;链上记录+区块时间 | 密码学性质+链上可查 |
| R2 | 抵赖 | 平台被质疑伪造时间 | RFC3161 第三方时间戳与区块时间双锚定 | M5 实测 tsaTimestamp |
| I1 | 信息泄露 | 从链上记录反推作品内容 | 链上仅存哈希(单向)与 CID,不存内容 | 设计审查 |
| D1 | 拒绝服务 | 无鉴权 prepare 被刷(占存储/CPU) | **当前无防御** → 残余 R1 | — |
| D2 | 拒绝服务 | 后端宕机 | 验证可走链上反查;登记的链上部分不受影响;重启断点续扫补齐 | 停机补齐实测 |
| E1 | 提权 | 伪造/重放事件欺骗监听器 | 事件仅认合约地址过滤;交易重放被 nonce+chainId(EIP-155)拒止;镜像 upsert 幂等 | 游标归零重扫数据不乱(幂等实验) |
| E2 | 提权 | T3 返回假 calldata 骗用户签名 | 钱包展示 to/data 可核;registerWork 无资产转移,损失上界=登记错误数据;彻底解法(前端本地重算比对)记入展望 | 设计分析(诚实项) |

合约层通用防御:Solidity 0.8 内置溢出检查;全部外部输入 require 校验;
**无转账逻辑 → 无重入攻击面**;无特权角色(没有 owner 后门,平台自己也改不了记录)。

## 五、密钥与凭证管理

| 密钥 | 位置 | 策略 |
|---|---|---|
| 用户链上私钥 | 用户钱包 | 系统永不接触;丢失=身份丢失(自托管代价,展望:社交恢复/MPC) |
| C2PA 签名私钥(sign.key) | 后端可读 | 唯一由平台持有的密钥——只签"内容声明",**不能动任何链上资产**;泄露影响=可伪造平台签名的声明,处置=换叶子证书重签,链上记录不受影响(密钥职责分离的体现) |
| CA 根私钥(rootCA.key) | 演示环境本地 | demo 定位;生产应离线保存或直接改用外部 CA |
| Hardhat 测试私钥 | 公开 | 仅本地链,文档多处高亮警告 |

## 六、残余风险清单(诚实项,答辩/论文直接引用)

| # | 残余风险 | 现状与理由 | 对策方向 |
|---|---|---|---|
| R1 | API 无鉴权无限流,可被刷 | 本地单机演示定位 | 生产化:鉴权、配额、上传大小/频率限制 |
| R2 | "先上链者赢":真正首创者若后登记,系统无法自动裁定 | 技术边界——链只能证明时序,不能证明创作事实(GIGO) | 证据 PDF 服务司法裁定;更早的 TSA/工程文件由权利人自备 |
| R3 | 破坏性处理(截图/压缩)后无法关联 | C2PA 生态公开难题;相似检索被明确收窄 | 展望:水印互补(对照刘颖/陈家琰路线)、平台侧凭证保全 |
| R4 | 本地链无 reorg 处理;传输无 TLS | 演示环境不发生/不设防 | 公网部署:确认数延迟入账、HTTPS |
| R5 | 登记内容经 IPFS/CID 公开可取 | "公开可验证"目标的一体两面 | 需保密的作品可用 local 模式或"哈希上链、密文离线"变体 |
| R6 | 恶意后端可给用户"错误但无害"的 calldata | 已分析上界(E2), 未做前端复核 | 前端本地重算三哈希与 calldata 比对(展望) |

## 七、结论

系统的安全设计核心是**把信任根从平台移出**:身份根在用户钱包(S1/S2),记录根在链共识
(T2'/T3'),凭证根在信任锚(S3),时间根在链+TSA 双源(R2)。平台仅剩的密钥(C2PA 签名钥)
与资产完全隔离。全部 14 项枚举威胁中 12 项有已验证的技术防御,2 项(D1、E2)如实记为
残余并给出对策——受限环境下的完整威胁建模闭环,而非"全都防住了"的表演性安全。
