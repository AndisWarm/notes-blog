# 03 预备:哈希、签名与 C2PA 基础

**学习目标**:三个密码学积木(哈希 / 数字签名 / 证书链)+ C2PA 是怎么把它们组装起来的。
全部配命令行实验——这一章学完,第 08 章的信任链实操就只剩"照做"。

## 3.1 密码学哈希:内容的指纹

三条性质对应本项目三个用法:

| 性质 | 含义 | 本项目哪里在依赖它 |
|---|---|---|
| 单向 | 由哈希推不回原文 | 链上公开哈希不泄露作品内容 |
| 雪崩 | 改 1 比特,输出面目全非 | "改 1 字节即检出";四态验证的精确命中 |
| 抗碰撞 | 造不出同哈希的两个文件 | 哈希可以**代表**文件本体上链 |

**动手**:
```bash
echo hello > a.txt && sha256sum a.txt
printf 'hellp' > b.txt && sha256sum b.txt   # 差一个字母,对比两个输出
# 对照项目:backend/internal/hash/sha256.go 只有 20 行——读一遍,它是全系统的地基
```

**关键区分**:SHA-256 是**密码学哈希**(内容差一点,输出全不同);第 05 章会遇到的
pHash 是**感知哈希**(内容像,输出就像)——用途相反,别混。

## 3.2 数字签名:不可抵赖的"我说过"

- 私钥签名、公钥验签;签名绑定**内容 + 身份**:内容改了验不过,别人冒充签不出。
- 本项目两处独立使用,曲线不同用途相同:

| 场景 | 算法/曲线 | 签什么 | 谁验 |
|---|---|---|---|
| 以太坊交易 | ECDSA / secp256k1 | 整笔交易 | 每个链节点(恢复出 msg.sender) |
| C2PA 声明 | ES256 / P-256 | manifest(内含内容哈希) | 任何拿到文件的人(c2patool) |

**动手**(用项目自带的 CA 密钥体验一次签名/验签):
```bash
cd tools/ca
echo "test message" > /tmp/msg.txt
openssl dgst -sha256 -sign sign.key -out /tmp/msg.sig /tmp/msg.txt          # 私钥签名
openssl dgst -sha256 -verify <(openssl x509 -in sign.crt -pubkey -noout) -signature /tmp/msg.sig /tmp/msg.txt
# → Verified OK;改一下 msg.txt 再验一次 → Verification Failure
```

## 3.3 证书与信任链:签名可信的来源

签名只回答"没被改、是持钥人签的",**不回答"持钥人是谁、可不可信"**——这靠证书链:

```text
Root CA(自签,验证方预先信任 = trust anchor)
   └── 签发 → 叶子证书(绑定签名者身份 + 公钥,声明用途 EKU)
                  └── 用叶子私钥 → 给 C2PA manifest 签名
```

验证方沿链向上验到自己信任的根:根在信任列表内 → **Trusted**;不在 → untrusted
(签名有效但来源不认识)。本项目 `tools/ca/make-ca.sh` 就是造这条链:
EC P-256 根证书(10 年)→ ES256 叶子(3 年,KU=digitalSignature、EKU=emailProtection,
按 C2PA 证书 profile 要求设为 critical)→ 合并 `sign-chain.pem`。

**动手**:
```bash
openssl x509 -in tools/ca/rootCA.pem -text -noout | head -25   # 看 Issuer == Subject(自签根)
openssl x509 -in tools/ca/sign.crt  -text -noout | grep -A2 "Key Usage"   # 找 KU/EKU
openssl verify -CAfile tools/ca/rootCA.pem tools/ca/sign.crt   # → OK,这就是"链验证"
```

## 3.4 C2PA:把"声明+签名"装进文件里

- **是什么**:内容来源与真实性联盟(Adobe、微软、尼康、BBC 等)的开放标准——把创作声明
  (manifest)嵌入图片/视频文件内部(JUMBF 容器),随文件流转,任何人可离线验证。
- **manifest 三件套**:
  - assertions(断言):本项目放了 `c2pa.actions`(创作动作 + digitalSourceType)和
    `stds.schema-org.CreativeWork`(标题、创作者钱包地址、**originalHash**);
  - hard binding:对图像数据分块哈希——内容被改立即可检(validation_state=Invalid);
  - 签名:叶子证书私钥对以上全部签名。
- **本项目的关键设计**(面试/答辩高频):manifest 里嵌 originalHash、链上锚 manifestHash
  ——**文件内声明与链上记录互相引用**。文件被篡改后哈希全变,但幸存的 manifest 仍指回
  登记作品,这就是"签名后被篡改"态的实现原理。
- **业界坐标**:Adobe Content Credentials、相机厂商拍摄即签名、OpenAI/Google 给 AI
  生成图嵌 C2PA 标识——你学的不是玩具,是正在铺开的行业标准。

**动手**(5 分钟版,完整版在第 08 章):
```bash
tools/bin/c2patool.exe backend/data/objects/<任一local-目录>/c2pa-*.png 2>/dev/null | head -40
# 认一认输出里的:claim_generator、assertions 数组、signature_info、validation_state
```
