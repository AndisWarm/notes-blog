# 02 预备:区块链与以太坊基础

**学习目标**:掌握读懂本项目所需的最小以太坊知识集——账户、交易、gas、EVM、事件。
判断标准:能用裸 RPC(不借助任何前端)完成查询和解读。

**范围声明**:不需要学挖矿/PoS 共识细节、不需要学 DeFi,本项目用到的以太坊特性就这五样。

## 2.1 账户:私钥 → 公钥 → 地址

- 外部账户(EOA)由一把 secp256k1 私钥定义;地址 = 公钥 Keccak-256 哈希的后 20 字节。
- **没有"注册"这回事**:任何 32 字节都是合法私钥,算出地址即可用——所以 Hardhat 能把
  20 个测试账户直接印在屏幕上(全世界共用这套公开测试私钥,这也是它们绝不能碰真实网络的原因)。
- 合约账户没有私钥,由部署它的交易创建,地址由 `部署者地址 + nonce` 决定——
  这解释了第 01 章的观察:每次重启链后重新部署,四个合约地址**永远一样**
  (同一个部署者、从 nonce 0 开始)。

**动手**:
```bash
# 用 RPC 查询甲账户余额(结果是 16 进制的 wei)
curl -s -X POST http://127.0.0.1:8545 -H "Content-Type: application/json" -d "{\"jsonrpc\":\"2.0\",\"id\":1,\"method\":\"eth_getBalance\",\"params\":[\"0x70997970C51812dc3A010C7d01b50e0d17dc79C8\",\"latest\"]}"
# 换算:0x21e19e0c9bab2400000 / 1e18 = 10000 ETH
```

## 2.2 交易:改变世界状态的唯一方式

一笔交易 = {nonce, to, value, data, gas 参数} + **发送者的签名**。三个关键认识:

1. `from` 不在交易体里——它由签名**恢复**出来,伪造不了。这就是合约里 `msg.sender`
   可以直接当身份用的原因,也是本项目"链上作者=创作者"的全部依据;
2. `to` 为空 = 部署合约;`to` 是合约地址且 `data` 非空 = 调用合约方法;
3. `data` 前 4 字节是方法选择器(方法签名哈希的前 4 字节)。第 01 章抄下来的 txRequest
   里,`data` 开头就是 `registerWork(bytes32,bytes32,bytes32,string,string)` 的选择器。

**动手**:
```bash
# 取最新块(带完整交易),找一笔你在第 01 章发出的交易
curl -s -X POST http://127.0.0.1:8545 -H "Content-Type: application/json" -d "{\"jsonrpc\":\"2.0\",\"id\":1,\"method\":\"eth_getBlockByNumber\",\"params\":[\"latest\",true]}"
# 对照:from 是你的钱包地址、to 是 Registry 地址、input 前 8 个 hex 字符是方法选择器
```

## 2.3 Gas:计算要付费

- 每条 EVM 指令有固定 gas 价目;交易费 = gasUsed × gasPrice。存储(SSTORE)最贵——
  这直接解释了本项目的设计:**链上只存 32 字节哈希,不存图片**。
- 本项目实测:registerWork ≈ 41.3 万 gas(三哈希写入 + 三条索引),grantLicense ≈ 23.5 万。
  三哈希比单哈希方案贵约 10 万 gas——工程里"每个字段都有价格",这是链上开发与普通后端
  最大的思维差异。
- EIP-1559 了解到这层即可:用户出 maxFee/tip,实付 = baseFee + tip,多退。

## 2.4 EVM 与合约:世界计算机的沙箱

- 合约 = 部署在链上的字节码 + 自己的存储空间;调用它的交易在**每个节点上确定性重放**,
  所以不能有随机、不能发 HTTP——一切外部信息要么由交易带入,要么不存在。
  (这解释了为什么 C2PA 签名、IPFS 存储都在**链下后端**做,只把结果哈希上链。)
- `require(条件, "reason")` 失败 → 整笔交易回滚、状态零改动、reason 返回给调用方。
  第 01 章看到的"合约拒绝:当前钱包不是该作品的链上作者"就是前端翻译的 revert reason
  `not author`。

## 2.5 事件(Event/Log):链对外广播的唯一通道

- 合约 `emit WorkRegistered(...)` 不改状态,而是写入交易回执的日志区;日志可按
  **合约地址 + 主题(topic)** 高效过滤。indexed 参数进 topics,非 indexed 进 data。
- 链下程序(本项目的 listener)靠 `eth_getLogs` 增量拉取事件来感知链上发生了什么——
  第 01 章"授权记录 3 秒后出现"的延迟,就是 2 秒轮询间隔 + 处理时间。

**动手**:
```bash
# 拉取 Registry 合约的全部日志(地址换成你部署输出的)
curl -s -X POST http://127.0.0.1:8545 -H "Content-Type: application/json" -d "{\"jsonrpc\":\"2.0\",\"id\":1,\"method\":\"eth_getLogs\",\"params\":[{\"fromBlock\":\"0x0\",\"address\":\"0x5FbDB2315678afecb367f032d93F642f64180aa3\"}]}"
# 认一认:topics[0] 是事件签名哈希,topics[1] 是 indexed 的 workId,topics[2] 是 indexed 的 author
```

## 2.6 本地开发链的"作弊" RPC

Hardhat/本项目等价链额外提供测试专用方法:`evm_increaseTime`(时间快进,**不可回退**)、
`evm_mine`(手动出块)、`hardhat_setBalance`(直改余额)。两个本项目真实用例:
水龙头充值后必须补挖一个空块(否则钱包按区块高度缓存余额,界面刷不出来);
测试脚本快进 2 小时验证授权过期。
