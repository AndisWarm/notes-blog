## 练习一:分账规则变更历史(难度 ★★,预计 3–5h)

**需求**:授权管理页能看到某作品分账规则的**全部变更历史**(谁、何时、从多少改到多少)。

**现状与线索**:链上 RoyaltyV2 只存最新规则,但每次 setRoyaltyRule 都 emit 了
`RoyaltyRuleSet(workId, creator, platform, creatorShareBps, platformShareBps)`——
历史都在事件里;而 listener 目前**根本没监听 Royalty 地址**(第 06 章自测 5 的伏笔)。

**实施地图**(自己展开每一步):

```text
后端  repository:新表 royalty_history(work_id, creator, platform, creator_bps,
      platform_bps, tx_hash, block_number, created_at)+ 迁移(仿 chain_status 的防重入写法)
      listener:Addresses 加 RoyaltyAddr;handleLog 加 RoyaltyRuleSet 分支(幂等:
      同 tx_hash 不重复插入——想想用什么约束实现)
      api:GET /api/works/:id 响应里加 royaltyHistory 数组
前端  LicenseView 分账卡片下加历史表格(时间倒序)
测试  合约层补事件参数断言(第 09 章已做);扩展 mjs 加"改两次规则→历史两条"的用例
```

**验收**:设置 85/15 → 改 90/10 → 页面历史两条且顺序正确;重启后端历史不丢不重
(拿第 06 章的游标重扫实验验证幂等);全部旧测试仍绿。

**陷阱预告**:游标是全局的——新监听的地址不会自动"补扫历史"(游标已过的块不再扫)。
处理方案自选:文档声明"自部署起生效" / 提供一次性回填命令 / 游标归零重扫(幂等兜底)。
把你的选择和理由写进提交说明——**这个决策本身就是练习的一部分**。

## 练习二:授权到期提醒与有效性展示(难度 ★★☆,预计 4–6h)

**需求**:①授权记录表新增"链上实时有效性"列(调 isLicensed 的逐笔版:该笔未撤销
且未过期);②即将到期(<72h)的授权黄色高亮。

**设计要点**:镜像表里有 validUntil/revoked,"有效性"可以纯前端算——但**链上时间
≠ 本机时间**(evm_increaseTime 之后差 2 小时,第 09 章的坑);正确做法是取
latest block timestamp 做基准(readContract 或后端透出)。做完你会对
"分布式系统里'现在几点'不是一个简单问题"有肌肉记忆。

**验收**:签一笔 1 小时授权 → evm_increaseTime 快进 2 小时 + evm_mine →
刷新页面该笔显示已过期,而墙钟视角它"还没到期"——截图这个反直觉现场。

## 练习三:部署到公共测试网 Sepolia(难度 ★★★,预计 1 天,可选)

**需求**:整套系统跑在 Sepolia 上,拿到区块浏览器可查的真实交易。

**理论上只需要配置**(架构链无关性的实战检验):hardhat.config 加 sepolia 网络
(RPC + 部署账户私钥,用环境变量别硬编码!)→ `npm run deploy -- --network sepolia`
→ 后端改 `CHAIN_RPC_URL` / `DEPLOYMENTS_FILE` → MetaMask 切 Sepolia。

**预期会遇到的现实问题**(每个都是学习点):水龙头 403(设计如此,用公共 faucet 领
Sepolia ETH)、出块 12s(前端轮询要等更多轮)、RPC 限流(免费节点)、
evm_increaseTime 不存在(相关测试用例只能跳过——重新理解"测试专用 RPC"的边界)。

**验收**:Etherscan(sepolia)上能看到你的 registerWork 交易;verify-file 四态照常工作。
