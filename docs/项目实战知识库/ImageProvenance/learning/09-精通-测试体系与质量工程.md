# 09 精通:测试体系与质量工程

**学习目标**:理解四层测试金字塔各层"测什么、不测什么、为什么在这层测";
全部测试本机跑绿;学会攻击用例的思维方式并亲手补一个断言。

## 9.1 四层金字塔总览

| 层 | 位置 | 数量 | 速度 | 测什么 |
|---|---|---|---|---|
| L1 合约单测 | `contracts/test/*.test.js` | 20(含 6 组攻击) | 秒级 | 每个 require、每个状态转移、每个事件 |
| L2 后端单测 | `backend/internal/*/**_test.go` | 3 包 | 秒级 | 仓储三级查找/游标/幂等、C2PA 解析、pHash 边界 |
| L3 全链路 E2E | `scripts/dev/*.mjs` 三套 | 15+22+31 | 分钟级 | 跨进程集成:API→钱包→链→事件→镜像→前端数据源 |
| L4 独立环境回归 | 云端沙箱(见 manual/04) | 76 项 | 一次性 | 排除环境耦合:"不是只在我机器上能跑" |

**分层原则**(面试常问):失败定位成本递增,所以断言尽量下沉——
"非作者授权被拒"在 L1 用一行 expect revert 测,不需要起五个服务;
"授权记录 3 秒内出现在 API"只能在 L3 测(跨了链、监听器、SQLite 三个部件)。

## 9.2 L1 精读:攻击用例的思维方式

打开 `contracts/test/LicenseV2.test.js` 与 `RegistryV2.test.js`,注意结构:
**每个正向用例旁边都站着它的反面**。攻击用例六组对照表(`reports/test-results/attack-cases.md`
有威胁-防御-结果三段式完整版):

```text
威胁:抢注他人作品      → 测:三哈希各自重复注册 revert
威胁:替他人发授权      → 测:非作者 grantLicense revert "not author"
威胁:篡改他人分账      → 测:非作者 setRoyaltyRule revert
威胁:操作不存在的作品  → 测:幽灵 workId 各方法 revert
威胁:撤销/过期后仍有效 → 测:isLicensed=false(时间快进用 evm_increaseTime)
威胁:越权改状态        → 测:非作者 setStatus revert
```

**方法论**:先写威胁模型,再让每条威胁对应至少一个"必须失败"的用例——
权限系统的测试重点不是"能用",是"**该失败的必须失败**"。

跑起来:`cd contracts && npm test`,再 `npx hardhat coverage` 看覆盖率报告
(语句 98.2% / 分支 98.4%),打开 coverage/index.html 找找没盖住的分支是什么。

## 9.3 L2 精读:后端单测挑两个看

- `repository/work_repository_test.go`:三级哈希查找、UNIQUE 防重复、游标读写、
  授权镜像幂等——对照第 06 章的三性质,每条性质都有对应断言;
- `similarity/phash_probe_test.go`:**把实验发现固化成测试**的范例——
  噪声图/渐变图是 pHash 病态输入这个结论,不是写在文档里,是写成会跑的断言
  (文档会过时,测试不会说谎)。

跑起来:`cd backend && go test ./...`。

## 9.4 L3 精读:E2E 脚本的工程细节

三套脚本(e2e-demo 15 / test-license-flow 22 / test-license-flow-extended 31)共用的设计:

1. **随机像素 PNG**:每轮生成随机图 → 哈希唯一 → 可反复运行不撞防重复;
2. **双账户正反路径**:甲做正事,乙演攻击——L1 测过的 revert 在真实链+真实 ABI 上再验一遍;
3. **等待事件镜像**:授权后 sleep 3.5s 再查 API(2s 轮询 + 余量)——异步系统的测试
  必须显式等待或轮询,不能假设即时一致;
4. **链上时间基准**(extended 脚本):validUntil 用 `provider.getBlock('latest').timestamp`
  而非 `Date.now()`——因为 evm_increaseTime 会让链时间永久领先墙钟,墙钟基准的脚本
  在长活节点上第二遍就误报 invalid expiry。**这是本项目踩过的真实坑**,
  "测试自身的可重跑性"是容易被忽略的质量维度。

跑起来(五服务已启动):三条 `node scripts\dev\*.mjs` 依次执行,对着输出把 PASS 行
和你学过的章节内容连线。

## 9.5 L4:独立环境回归的意义

云端沙箱从源码复刻整套环境(等价链 + 离线构建后端 + crates 安装 c2patool)重跑全部用例,
76/76;等价性锚点:合约地址逐一相同、registerWork gas 412,516 vs 本机 412,528。
它回答的问题是 L1–L3 回答不了的:**环境假设有没有悄悄写死**(路径、版本、编码、时区…)。
副产品:c2patool 0.27 的 digitalSourceType 前向兼容缺陷正是这层发现的——
换个环境就爆的问题,只有换个环境才测得出来。发起方式见 `manual/04`。

## 9.6 动手实验(必做):补一个断言

`RoyaltyV2.test.js` 现有用例没有断言 **RoyaltyRuleSet 事件的参数**。补上:

```js
it("emits RoyaltyRuleSet with full params", async () => {
  await expect(royalty.connect(author).setRoyaltyRule(workId, platform.address, 8500, 1500))
    .to.emit(royalty, "RoyaltyRuleSet")
    .withArgs(workId, author.address, platform.address, 8500, 1500);
});
```

跑 `npm test` 看 21 passing。然后思考:这个断言在防御什么回归?
(事件字段顺序/类型被改 → 链下解析悄悄坏掉——事件是链上链下的**接口契约**,
契约要有契约测试。这正是第 10 章练习一的地基。)
