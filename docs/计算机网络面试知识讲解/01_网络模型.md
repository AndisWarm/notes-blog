# 01 网络模型

> 面试问法：网络OSI模型和TCP/IP模型分别介绍一下 / tcp、ip分别位于哪一层？

## Q1 网络 OSI 模型和 TCP/IP 模型分别介绍一下

### 一句话答案

OSI 是国际标准组织提出的**七层**理论模型（应用层、表示层、会话层、传输层、网络层、数据链路层、物理层）；TCP/IP 是实际在用的**四层**模型（应用层、传输层、网络层、网络接口层），Linux 系统就是按它实现的。

### 大白话讲解

**为什么要分层？**

想象一下寄快递：你写快递单（应用层）、快递公司分拣装车（传输层）、卡车按路线运输（网络层）、最后快递员按门牌号送到（链路层）。每一层只管自己的事，换快递员不影响你写字，换运输方式不影响分拣。网络也是一样——**分层就是为了让"多种设备能互相通信"并解决兼容性问题**。

**OSI 七层（教科书上的"完美模型"）**

每层管一件事，从上往下：

| 层 | 职责 | 生活类比 |
| --- | --- | --- |
| 应用层 | 给应用程序提供统一接口 | 你写的快递单 |
| 表示层 | 把数据转成对方能识别的格式 | 翻译官，把中文译成英文 |
| 会话层 | 建立、管理、终止通信会话 | 约好通话时间并开始通话 |
| 传输层 | 端到端的数据传输 | 快递分拣中心，保证包裹完整到达 |
| 网络层 | 路由、转发、分片 | 卡车按地图规划路线 |
| 数据链路层 | 封帧、差错检测、MAC 寻址 | 快递员按门牌号投递 |
| 物理层 | 在介质上传输比特流（0 和 1） | 马路、电线本身 |

关键点：**OSI 只是"概念理论"，没有提供具体实现**。它太复杂了，实际没人用完整的七层。

**TCP/IP 四层（实际在用的）**

| 层 | 代表协议 | 职责 |
| --- | --- | --- |
| 应用层 | HTTP、SMTP 等 | 给最终用户进程提供服务 |
| 传输层 | TCP、UDP | 主机到主机的通信 |
| 网络层 | IP | 寻址和路由数据包 |
| 网络接口层 | 以太网等 | 通过物理介质移动比特 |

TCP/IP 模型不包含物理层和数据链路层的完整实现，所以必须与其他协议协同工作，不能独立完成整个网络系统。

> 记忆口诀：七层从上到下「应表会传网链物」，四层从上到下「应传网链」。

## Q2 TCP、IP 分别位于哪一层？

### 一句话答案

- **TCP 在传输层**（负责可靠地传输数据）
- **IP 在网络层**（负责找到对方在哪）

### 大白话讲解

把网络通信比作寄包裹：**IP 是"地址系统"**，负责把包裹送到正确的城市和街道（找到主机）；**TCP 是"快递服务"**，负责保证包裹完整、不丢、不重复地送到（可靠传输）。两者配合：IP 负责"找得到"，TCP 负责"送得稳"。

## Q3 ARP 协议是什么？（数据链路层）

### 一句话答案

**ARP（地址解析协议）**：给定 IP 地址查出对应的 **MAC 地址**——负责"IP → MAC"的翻译，属于**数据链路层**（TCP/IP 四层里的网络接口层）。过程：**广播问"谁是这个 IP"，目标单播答"我是这个 MAC"，结果存缓存复用**。

### 大白话讲解

**为什么需要它？** 因为网络里有两套地址，各管一段：

| 地址 | 所属层 | 作用 | 类比 |
| --- | --- | --- | --- |
| **IP 地址** | 网络层 | 跨网络寻址（逻辑地址） | 收件人姓名 |
| **MAC 地址** | 数据链路层 | 局域网内寻址（网卡烧录的物理地址） | 门牌号 |

IP 包要封装成帧才能发出去，帧头必须填目的 MAC——但 IP 只告诉你"收件人姓名"，不告诉你"门牌号"。**ARP 就是查门牌号的电话簿**。

**工作过程（同子网，四步）：**

```
主机 A (192.168.1.10)                   主机 B (192.168.1.20)
     │                                     │
     │ ① 查自己的 ARP 缓存表                │
     │ ② 没有 → 发广播: 谁是 192.168.1.20? │
     │────────────────────────────────────→│  (广播: 局域网所有人都收到)
     │                                     │
     │ ③ 目标单播回复: 我是, MAC 是 XX      │
     │←────────────────────────────────────┤
     │ ④ 存入 ARP 缓存表，然后发数据帧       │
```

1. **查缓存**：先查 ARP 表有没有现成的 IP→MAC 记录（表项存活几分钟），有就直接用，不发广播；
2. **广播请求**：没有 → 发 ARP 请求**广播**："谁是 192.168.1.20？"——同网段所有设备都能收到；
3. **单播应答**：目标主机**单播回复**自己的 MAC（非目标直接丢弃请求）；
4. **缓存 + 通信**：映射写进 ARP 缓存，然后才能封装帧发送数据。

**为什么请求广播、应答单播？** 发起方不知道目标在哪，只能广播喊话；应答时目标已从请求里知道发起方的 IP 和 MAC，直接单播即可。

**跨子网时 ARP 查谁？（关键考点）** 目标不在同一子网时，数据不能直接发给目标，要先交**网关**转发：

- **同子网** → ARP 查**目标主机**的 MAC；
- **跨子网** → ARP 查**网关**的 MAC（帧的目的 MAC 是网关，IP 的目的 IP 仍是目标主机）。

> 一句话：**IP 是终点地址（全程不变），MAC 是下一跳地址（每跳一换）**。这就是"打开网页全过程"（《10》章）里第 4 步 ARP 的完整含义。

**安全威胁：ARP 欺骗（面试加分点）** ARP 靠广播请求 + 无认证应答，任何人都能应答：攻击者冒充网关回复"我就是网关，我的 MAC 是 XX" → 受害者 ARP 表被污染 → 发往网关的流量先经过攻击者 → **中间人攻击**。防御：静态 ARP 表、交换机端口安全、动态 ARP 检测（DAI）。

## 本单元面试追问点

1. 七层模型每层干什么？（从上到下背一遍即可）
2. 为什么实际用的是 TCP/IP 四层而不是 OSI 七层？（OSI 只有理论没有实现，太复杂）
3. TCP/IP 模型没有哪两层？（物理层和数据链路层的完整实现）
4. ARP 是查 IP 还是查 MAC 的？（IP 查 MAC，方向别反了）
5. 跨子网时 ARP 查谁？（查网关的 MAC，不是目标主机的 MAC）
6. 为什么 ARP 请求要广播、应答要单播？（不知道目标在哪 → 广播问；应答时已知道发起方 → 单播答）
