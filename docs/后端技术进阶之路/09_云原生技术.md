# 09 云原生技术

本章覆盖：Docker 与虚拟机区别、Docker 与 k8s 关系。

---

## 1. Docker 和传统虚拟机有什么区别？

### 一句话回答
虚拟机每个都是"一台完整电脑"（自带操作系统），Docker 容器是"一个进程"（共享宿主机的 Linux 内核），所以容器更轻、启动更快、密度更高。

### 展开讲

**虚拟机：**
- 基于 **Hypervisor**（VMware、VirtualBox、KVM）虚拟出完整硬件，每个虚拟机里装一个完整的**客户操作系统**（Guest OS）
- 隔离级别是**操作系统级**：虚拟机之间完全隔离，一个被攻破不影响其他
- 启动要经历 BIOS → 内核 → 系统服务，通常几十秒到几分钟
- 镜像几个 GB，一台物理机只能跑几个到几十个虚拟机

**Docker 容器：**
- 不虚拟硬件，直接**共享宿主机内核**，只把应用 + 运行环境（依赖库）打包成镜像
- 隔离靠 Linux 内核两大机制：
  - **Namespace**：让容器"看起来像一台独立机器"——独立的进程、网络、文件系统、用户视图（每个容器有自己的 PID 1、IP、挂载点）
  - **Cgroup**：限制和统计资源——CPU 配额、内存上限、磁盘 I/O 限制（防止一个容器吃光整台机器）
- 启动只需创建进程组，秒级完成；镜像几百 MB 到 1GB 左右；一台机器可跑几百个容器

**镜像分层：**
- 镜像由只读层叠加而成（UnionFS 联合文件系统）：基础层（OS 基础）+ 依赖层 + 应用层
- 多个容器/镜像**共享相同的底层**，只存差异层，省磁盘省带宽；改一层只影响该层及之上的层，便于缓存复用

### 对比表格

| 维度 | 虚拟机 | Docker 容器 |
|------|--------|-------------|
| 内核 | 每台一套完整 Guest OS | 共享宿主机内核 |
| 隔离机制 | Hypervisor 硬件虚拟化 | Namespace + Cgroup（进程级） |
| 启动时间 | 分钟级 | 秒级 |
| 镜像大小 | GB 级 | MB ~ 1GB 级 |
| 单机密度 | 几十个 | 几百个 |
| 隔离强度 | 强（系统级） | 弱（进程级，内核共享） |
| 资源开销 | 大（重复内核和系统服务） | 小（只有应用进程） |

**注意：** 隔离强的反面是安全隔离较弱——容器共享内核，内核漏洞可能跨容器利用，因此容器内不应跑不可信代码。

### 比喻
虚拟机像一栋楼里每家都自带厨房、水管、电表（完整 OS），重但互不干扰；Docker 像集体宿舍：共用一栋楼的基础设施（共享内核），每人只占一个房间（namespace），宿舍管理员限定每人用电上限（cgroup）——轻便，但隔壁漏水（内核漏洞）可能影响你。

## 2. Docker 和 k8s 之间是什么关系？

### 一句话回答
Docker 是"打包和运行单个容器"的工具，k8s（Kubernetes）是"管理成千上万个容器"的编排系统——Docker 管单兵，k8s 管军团。

### 展开讲

**各自职责：**
- **Docker**：负责构建镜像（Dockerfile → 镜像）、运行容器（run）、本地开发与单机部署
- **k8s**：负责**编排**——把容器部署到集群中合适的机器上，并持续维护"期望状态"

**k8s 的核心能力：**

1. **调度（Scheduling）：** 来了一个 Pod（k8s 最小调度单位，里面装一个或多个容器），调度器按资源需求、亲和性、污点容忍度决定放到哪台 Node 上；Node 资源不够会自动换机器
2. **服务发现与负载均衡：** 每个 Pod 有独立 IP 且会随时变动，k8s 提供 Service 对象做稳定入口（虚拟 IP + DNS 名），自动把流量分发给背后的一组 Pod；Pod 挂了重建后自动挂回 Service
3. **自动伸缩：** 两种方式——HPA（水平扩缩：按 CPU/内存/自定义指标自动增减 Pod 副本数）和 VPA（垂直扩缩：调整单个 Pod 的资源配额）；流量高峰自动加副本，低谷自动回收，不用人工熬夜扩机器
4. **滚动更新与回滚：** 发新版本时逐个替换旧 Pod（滚动更新），先起新 Pod 等健康检查通过再下线旧 Pod，全程不停服；发布出问题一条命令回滚到上一个版本
5. **自愈：** 健康检查失败的 Pod 自动重启或重建；Node 宕机后，上面的 Pod 自动被调度到其他机器；期望副本数（replicas）是"声明式"的——k8s 持续保证实际数量等于期望数量
6. **存储与配置：** Volume 挂载持久化存储、ConfigMap/Secret 管理配置，Pod 重建配置不丢

**关系总结：** Docker 解决"怎么把一个应用装进盒子"，k8s 解决"一整个机房几千个盒子怎么管"。k8s 本身不直接运行容器，它调用容器运行时（Docker 是其中一种，现在常用 containerd）来执行。

### 比喻
Docker 像集装箱（打包、搬运单个货物），k8s 像港口调度系统：知道每个集装箱放哪个泊位（调度）、哪个箱子在哪个吊机上（服务发现）、高峰期加派吊车（伸缩）、坏了的吊车自动换新的（自愈）、新旧货物无缝替换（滚动更新）——没有调度系统，一千个集装箱会乱成一锅粥。
