# 08 中断

本章覆盖：什么是中断、中断的分类（外部/内部、可屏蔽/不可屏蔽、陷阱/故障/终止）、中断的流程、中断的作用。

> 中断是理解"操作系统如何响应事件"的基础，也是系统调用（printf → 内核）的底层机制。建议把"陷阱/故障/终止"三个概念分清，面试常考。

---

## 1. 什么是中断？

### 一句话回答
**CPU 停下当前的工作任务，去处理其他事情，处理完后回来继续执行刚才的任务**，这一过程就是中断。

### 中断分类总览

```
中断
├── 外部中断（来自 CPU 外部，硬件产生）
│     ├── 可屏蔽中断（通过 INTR 线请求）
│     └── 不可屏蔽中断（通过 NMI 线请求，如断电）
│
└── 内部中断（来自 CPU 内部）
      ├── 陷阱（Trap）：有意的、预先安排的事件（如系统调用）
      ├── 故障（Fault）：可修复的意外事件（如缺页）
      └── 终止（Abort）：致命错误，程序只能终止
```

### ① 外部中断（硬件中断）

| 类型 | 请求线路 | 例子 | 能否屏蔽 |
|------|----------|------|----------|
| 可屏蔽中断 | **INTR 线** | 硬盘、打印机、网卡 | 可以（不影响系统运行，甚至可以不处理） |
| 不可屏蔽中断 | **NMI 线** | 电源掉电、硬件线路故障 | 不建议也不能屏蔽（问题太大，屏蔽没意义） |

> 注：INTR 和 NMI 都是 CPU 的引脚。

### ② 内部中断（异常）

| 类型 | 性质 | 处理完返回哪里 | 例子 |
|------|------|---------------|------|
| **陷阱** | 有意的、预先安排 | **下一条指令** | 系统调用、程序调试。如 32 位 Linux 的 `int 0x80`、64 位 Linux 的 `syscall` 指令 |
| **故障** | 意外的，指令未执行完 | **引起故障的那条指令**（重新执行） | 缺页异常——CPU 引用的虚拟地址没有对应物理页 |
| **终止** | 致命错误，不可修复 | **不返回**，直接终止程序 | 硬件错误 |

**陷阱详解**：编写程序时故意设下的陷阱指令，执行到后 CPU 调用特定程序处理，处理结束后**返回到陷阱指令的下一条指令**。`printf` 最底层就触发系统调用——32 位 Linux 用 `int 0x80` 陷阱指令，64 位 Linux 用开销更低的专用 `syscall` 指令。

**故障详解**：故障发生时会交由故障处理程序处理，**能修正错误就返回重新执行引起故障的指令**，不能修正就报错。典型例子：缺页——物理页从磁盘调进主存后，重新执行引起故障的指令就能顺利执行了。

> 记忆口诀："陷阱回下一条，故障重来一遍，终止直接完蛋。"

## 2. 中断的流程是什么？

### 一句话回答
中断流程三步：**发生中断（保存现场）→ 中断响应（查中断向量表找到处理程序）→ 中断处理（执行处理程序）**。

### 三步流程

```
步骤1：发生中断
  外部设备或软件程序发出中断信号
  处理器停止当前执行的指令，保存当前执行现场

步骤2：中断响应
  处理器根据「中断向量表」找到对应中断处理程序的入口地址
  保存当前执行现场（程序计数器、寄存器状态等），以便处理完恢复

步骤3：中断处理
  处理器跳转到中断处理程序的入口地址开始执行
  处理程序根据中断类型处理：保存现场、处理中断事件、执行特定任务等
```

> 类比：你正在写代码，同事（中断源）喊你有急事——你先保存文档（保存现场），看一眼是老板还是前台（查向量表），然后处理对应的事（中断处理），办完回来继续写（恢复现场）。

## 3. 中断的类型有哪些？

### 一句话回答
按**事件来源**分类：来自 CPU 外部的叫**外部中断**（硬件中断，分可屏蔽/不可屏蔽），来自 CPU 内部的叫**内部中断**（分软中断和异常）。

### 分类详解

**外部中断（硬件中断）**
- 事件来源在 CPU 外部，必然是某个硬件产生的（网卡、声卡、显卡等）
- 通过两根信号线通知 CPU：
  - **INTR**：不影响系统运行的信号，CPU 可以屏蔽（设置中断屏蔽寄存器 IF 位）
  - **NMI**：影响系统运行的严重错误（断电、电源故障），不可屏蔽——系统已经无法运行，屏蔽没意义

**内部中断**
- 事件来源在 CPU 内部
- **软中断**：软件主动发起的中断，常用于**系统调用**
- **异常**：指令执行期间 CPU 内部产生的错误（除 0、越界访问等）
- 异常不受 eflags 寄存器 IF 位影响
- 区别：不可屏蔽中断的事件导致**处理器无法运行**（断电等）；异常是**影响系统正常运行**的中断（除 0 等）

## 4. 中断的作用是什么？

### 一句话回答
中断让计算机具备**及时应对突发事件**的能力，**大幅提高 CPU 工作效率**——没有中断，CPU 只能轮询外设，效率极低且无法及时响应紧急事件。

### 对比轮询

| 方式 | 工作模式 | 效率 |
|------|----------|------|
| **轮询**（没有中断） | CPU 按程序顺序逐个查询外设 | 低：外设没事件时 CPU 也在空转等待 |
| **中断**（有中断） | CPU 干自己的活，外设有事主动"喊"CPU | 高：CPU 不空等，紧急事件能及时响应 |

> 面试金句："中断的本质是让 CPU 从'主动询问'变成'被动响应'，把宝贵的 CPU 时间用在真正的工作上。"
