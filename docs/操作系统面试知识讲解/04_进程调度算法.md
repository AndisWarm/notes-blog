# 04 进程调度算法

本章覆盖：六大经典调度算法（先来先服务、最短作业优先、高响应比优先、时间片轮转、最高优先级、多级反馈队列）的原理、优缺点和适用场景。

> 面试常考"算法对比"，建议把每个算法用"一句话 + 一个例子 + 优缺点"来记。

---

## 1. 进程调度算法有哪些？

### 一句话回答
六大经典算法：**先来先服务（FCFS）、最短作业优先（SJF）、高响应比优先（HRRN）、时间片轮转（RR）、最高优先级（HPF）、多级反馈队列（MFQ）**。它们从"公平"到"高效"到"兼顾"层层演进，**多级反馈队列是现代操作系统实际采用的主流方案**。

### 演进关系一览

```
FCFS（太偏向长作业）
   │
   ▼
SJF（太偏向短作业，长作业饿死）
   │
   ▼
HRRN（引入"响应比"权衡长短作业）
   │
   ▼
RR（公平轮转，但不区分优先级）
   │
   ▼
HPF（引入优先级，低优先级可能饿死）
   │
   ▼
MFQ（多级队列 + 反馈，兼顾长短作业和响应时间）★ 现代主流
```

## 2. 逐个算法详解

### ① 先来先服务（FCFS，First Come First Served）

**核心思想**：先来后到，每次从就绪队列选择**最先进入队列**的进程，一直运行直到**退出或阻塞**，再选下一个。

**例子**：
```
就绪队列顺序：[作业A(运行10分钟), 作业B(运行1分钟)]
→ A 先运行 10 分钟，B 干等 10 分钟
```

**优点**：简单、公平（按到达顺序）
**缺点**：一个长作业先到，后面所有短作业都干等 → **对短作业极不友好**
**适用**：CPU 繁忙型作业的系统；**不适用** I/O 繁忙型作业的系统

> 类比：食堂打饭只开一个窗口，前面的人点一大桌菜，后面赶时间的只能干瞪眼。

---

### ② 最短作业优先（SJF，Shortest Job First）

**核心思想**：优先选择**运行时间最短**的进程来运行。

**例子**：
```
就绪队列：[作业A(运行10分钟), 作业B(运行1分钟)]
→ B 先运行，A 等待
```

**优点**：有助于提高系统**吞吐量**（单位时间完成的任务多）
**缺点**：**对长作业极不友好**，可能造成极端现象——长作业排队时不断被后来的短作业插队，**周转时间无限变长，长期得不到运行**（饥饿）

> 类比：医院先看"小病"，大病一直被小病插队，永远轮不到。

---

### ③ 高响应比优先（HRRN，Highest Response Ratio Next）

**核心思想**：权衡短作业和长作业。每次调度时计算"**响应比优先级**"，选最高的运行：

```
响应比 = (等待时间 + 要求服务时间) / 要求服务时间
       = 1 + 等待时间 / 要求服务时间
```

**公式的两个推论**：
- 等待时间相同 → 要求服务时间越短，响应比越高 → **短作业容易被选中**
- 要求服务时间相同 → 等待时间越长，响应比越高 → **长作业等久了也能轮上**（等待时间足够长时响应比升得很高）

**优点**：兼顾短作业的效率和长作业的公平（防止饿死）
**缺点**：每次调度都要计算响应比，有一定开销

> 类比：银行叫号系统——既让短业务快点办完，又保证排了很久的人不被无限插队。

---

### ④ 时间片轮转（RR，Round Robin）

**核心思想**：最古老、最简单、最公平、使用最广。**每个进程被分配一个时间段（时间片）**，在该时间段内运行：
- 时间片用完进程还在运行 → 释放 CPU，分配给另一个进程
- 时间片结束前进程阻塞或结束 → CPU 立即切换

**时间片长短很关键**：
- 太短 → 过多进程上下文切换，**降低 CPU 效率**
- 太长 → 对短作业的**响应时间变长**
- 通常 `20ms ~ 50ms` 是合理折中值

**优点**：公平（人人有份）
**缺点**：不区分任务重要性，紧急任务也要排队

> 类比：开会限时发言——每个人最多讲 3 分钟，超时就被请下台换下一个人。

---

### ⑤ 最高优先级（HPF，Highest Priority First）

**核心思想**：从就绪队列中选择**优先级最高**的进程运行。

**优先级分类**：
- **静态优先级**：创建进程时就确定，运行期间不变
- **动态优先级**：随进程状态变化调整——运行时间增加则降优先级，等待时间增加则升优先级

**抢占方式**：
- **非抢占式**：运行完当前进程，再选优先级高的
- **抢占式**：高优先级进程一出现，立即挂起当前进程让它先跑

**缺点**：**低优先级进程可能永远得不到运行**（饿死）

> 类比：VIP 通道永远优先，普通客户可能一直排不上。

---

### ⑥ 多级反馈队列（MFQ，Multilevel Feedback Queue）★ 重点

**核心思想**：「时间片轮转」+「最高优先级」的综合与发展，现代操作系统的主流调度算法。

- **「多级」**：有多个队列，每个队列优先级从高到低，**优先级越高时间片越短**
- **「反馈」**：有新的进程进入高优先级队列时，立刻停止当前进程，转去运行高优先级队列

**工作流程**：

```
新进程 → 队列1（最高优先级，时间片最短）
          ├── 在时间片内完成 → 结束 ✅
          └── 没完成 → 降级到 ↓
队列2（次高优先级，时间片较长）
          ├── 在时间片内完成 → 结束 ✅
          └── 没完成 → 降级到 ↓
队列3（最低优先级，时间片最长）
          └── 依次类推，直至完成
```

**三条规则**：
1. 新进程放入**第一级队列末尾**，按先来先服务排队；一级队列时间片内没运行完 → 转入第二级队列末尾，以此类推
2. **高优先级队列为空**，才调度低优先级队列的进程
3. 进程运行时，有**新进程进入高优先级队列** → 停止当前进程并移入原队列末尾，先运行高优先级进程

**为什么它这么好？**
- **短作业**：在第一级队列很快就能被处理完
- **长作业**：一级队列处理不完，移入下级队列等待，虽然等待时间变长，但**运行时间也更长**了
- 完美**兼顾长短作业**，同时有**较好的响应时间**

> 类比：医院的急诊分诊——重病（高优先级、短时间片）优先处理；轻症（低优先级）等一等，但一定轮得到你，不会饿死。

## 3. 算法速查表

| 算法 | 一句话 | 优点 | 缺点 | 适用 |
|------|--------|------|------|------|
| FCFS | 先来先跑 | 简单公平 | 长作业拖死短作业 | CPU 繁忙型 |
| SJF | 最短先跑 | 吞吐量高 | 长作业饿死 | 批处理 |
| HRRN | 按响应比跑 | 兼顾长短作业 | 计算开销 | 权衡场景 |
| RR | 轮流限时跑 | 最公平 | 紧急任务也排队 | 通用分时系统 |
| HPF | 优先级高的先跑 | 重要任务优先 | 低优先级饿死 | 多用户系统 |
| MFQ | 多队列+降级反馈 | 长短兼顾、响应好 | 实现复杂 | **现代主流** |

> 面试金句："多级反馈队列之所以成为主流，是因为它把'短作业优先'（一级队列快速处理）和'长作业不饿死'（逐级降级但保证运行）两个目标统一了起来。"
