# 06 内存管理基础

本章覆盖：操作系统内存管理概览、虚拟内存与物理内存、页表、段表、虚拟地址到物理地址的转换、程序内存布局、堆与栈的区别。

> 内存管理是操作系统面试的另一大核心（与进程线程并列）。建议先理解"虚拟内存"这个总概念，再逐步看页表、地址转换等细节。

---

## 1. 操作系统内存管理概述

### 一句话回答
操作系统通过**虚拟内存**隔离每个进程：每个进程都有自己独立的虚拟地址空间，程序不直接和物理内存打交道。**分页**是 Linux 管理内存的方式，虚拟地址和物理地址通过**页表**映射，映射工作由**MMU（内存管理单元）**完成。

### 虚拟内存带来的三大好处

**① 进程可"超用"物理内存**
- 程序运行符合**局部性原理**（CPU 访问内存有明显重复访问的倾向性）
- 不常访问的内存可以换出到物理内存之外（如硬盘上的 **swap 区域**）
- 所以进程能运行超过物理内存大小的程序

**② 解决多进程地址冲突**
- 每个进程有自己的**私有页表**，虚拟内存空间互相独立
- 进程无法访问其他进程的页表 → 不同进程可以使用相同地址互不干扰

**③ 提供安全性**
- 页表项除了物理地址，还有**属性比特**：读写权限、页是否存在等
- 操作系统对内存访问提供更好的保护（比如只读的代码段不能被改写）

### 分页管理

- **分页**：把整个虚拟和物理内存空间切成一段段**固定尺寸**的大小
- 一段连续且尺寸固定的内存空间叫**页（Page）**，Linux 下每页 **4KB**
- 虚拟地址与物理地址通过**页表**映射
- 页表存在内存里，**MMU（内存管理单元）**负责把虚拟地址转换成物理地址
- 进程访问的虚拟地址在页表中查不到时 → 产生**缺页异常** → 进入内核分配物理内存、更新页表 → 返回用户空间继续运行

## 2. 什么是虚拟内存和物理内存？

### 一句话回答
**物理内存**是计算机上真实存在的内存硬件；**虚拟内存**是操作系统给每个程序提供的"假想地址空间"，程序以为自己在独占一大片内存，实际上由操作系统映射到物理内存上。

### 逐个讲

**虚拟内存**
- 操作系统提供给每个运行中程序的**地址空间**
- 每个程序都认为自己拥有这块内存，**大小可以远大于物理内存**
- 实现方式：把程序地址空间划分成固定大小的**页或段**，映射到物理内存的不同位置
- 作用：高效利用物理内存、隔离进程

**物理内存**
- 计算机**实际存在的内存**，是真实的硬件部件（内存条）
- 虚拟内存最终都要落在物理内存上才能被 CPU 访问

> 类比：虚拟内存像"每个员工都觉得自己有一个专属工位"（其实是工位轮换制），物理内存像"公司实际租用的办公面积"。

## 3. 讲一下页表

### 一句话回答
页表是**记录虚拟页号和物理页号映射关系**的数据结构；虚拟地址分为**页号 + 页内偏移**，MMU 用页号查页表拿到物理页基地址，再加上偏移量得到物理地址。

### 虚拟地址 → 物理地址（三步）

```
虚拟地址 = 页号 + 页内偏移
1. 把虚拟内存地址切分成页号和偏移量
2. 根据页号从页表查询对应的物理页号
3. 物理页号 + 偏移量 = 物理内存地址
```

### 缺页异常

- 进程访问的虚拟地址在页表中**查不到** → 产生**缺页异常**
- 进入内核空间：分配物理内存 → 更新页表 → 返回用户空间恢复进程运行

### 分页 vs 分段（碎片问题）

| 对比项 | 分页 | 分段 |
|--------|------|------|
| 外部碎片 | **没有**（页与页紧密排列） | 有（段与段之间产生空隙） |
| 内部碎片 | 有（不足一页也分配一页，页内有浪费） | 基本没有 |

> 注意：分页解决了"外部碎片"，但引入了"内部碎片"——分配的最小单位是一页，程序不足一页也得占一整页。

## 4. 讲一下段表

### 一句话回答
分段机制把程序的虚拟地址分成 **4 个段**，每个段在**段表**中有一个项，通过"**段基地址 + 段内偏移**"找到物理地址。

### 地址转换

```
段 3 的基地址 7000 + 偏移量 500 = 物理地址 7500
```

分段机制按**逻辑单位**（代码、数据、栈）切分内存，符合程序的自然结构，但段与段之间会产生外部碎片（这是分段被分页取代的原因之一）。

## 5. 虚拟地址是怎么转化到物理地址的？

### 一句话回答
由硬件 **MMU（内存管理单元）** 完成：把虚拟地址拆成**页号 + 页内偏移**，查**页表**得到物理页号，再组合出物理地址。为了提高效率，还引入了**多级页表**和 **TLB（快表）** 缓存。

### 转换流程

```
程序访问虚拟地址
      │
      ▼
MMU 把虚拟地址分解为：页号 + 页内偏移量
      │
      ▼
MMU 查找页表：根据页号找到对应的页表项（PTE）
      │
      ▼
页表项中包含物理页的地址或页框号
      │
      ▼
物理页地址 + 页内偏移量 = 物理地址
```

### 效率优化机制

- **多级页表**：页表本身很大（虚拟空间大），多级结构按需分配，节省内存
- **TLB（Translation Lookaside Buffer）**：页表查询的"快表"缓存，命中时跳过内存查表，大幅提高地址转换速度

> 类比：TLB 像前台的小本子，记着最常用的房间号，不用每次都翻整本通讯录。

## 6. 程序的内存布局是怎么样的？

### 一句话回答
用户空间内存从**低地址到高地址**依次是：**保留区、代码段、数据段、BSS 段、堆（向上增长）、文件映射段、栈（向下增长）**。

### 内存布局（从低到高）

```
高地址
┌─────────────────────────┐
│         栈段             │ ← 局部变量、函数调用上下文，大小固定（一般 8MB）
│         ↓ 向下增长        │
├─────────────────────────┤
│       文件映射段          │ ← 动态库、共享内存等
│         ↑ 向上增长        │
├─────────────────────────┤
│         堆段             │ ← 动态分配的内存（malloc）
│         ↑ 向上增长        │
├─────────────────────────┤
│        BSS 段            │ ← 未初始化的静态变量和全局变量
├─────────────────────────┤
│        数据段            │ ← 已初始化的静态常量和全局变量
├─────────────────────────┤
│        代码段            │ ← 二进制可执行代码
├─────────────────────────┤
│        保留区            │ ← 不可访问区域（防止空指针等问题）
低地址
```

### 各段解释

| 段 | 存放内容 | 分配方式 |
|----|---------|----------|
| 代码段 | 二进制可执行代码 | 静态 |
| 数据段 | 已初始化的静态常量和全局变量 | 静态 |
| BSS 段 | 未初始化的静态变量和全局变量 | 静态 |
| 堆段 | 动态分配的内存 | **动态**（malloc，向上增长） |
| 文件映射段 | 动态库、共享内存 | **动态**（mmap） |
| 栈段 | 局部变量、函数调用上下文 | 静态（编译器管理，大小固定约 8MB） |

### 为什么有保留区？

- 大多数系统认为**较小的地址不是合法地址**（C 语言里无效指针赋值为 NULL，NULL 通常就是 0）
- 保留区防止程序 bug 读写到小地址内存数据而"跑飞"

### 哪些段是动态分配的？

**堆和文件映射段**：用 C 标准库的 `malloc()` 在堆分配，`mmap()` 在文件映射段分配（详见 07 章第 3 节）。

## 7. 堆和栈的区别？

### 一句话回答
**堆是程序员手动管理的动态内存（大、慢、易泄漏），栈是编译器自动管理的函数内存（小、快、自动释放）**。

### 三个维度对比

**① 分配方式**
- **堆**：动态分配，由**程序员手动申请和释放**，存储动态数据结构和对象
- **栈**：静态分配，由**编译器自动分配和释放**，存函数的局部变量和调用信息

**② 内存管理**
- **堆**：程序员手动管理，管理不当会**内存泄漏**或**内存溢出**
- **栈**：编译器自动管理，遵循**后进先出（LIFO）**，变量生命周期由作用域决定——函数调用时分配，返回时释放

**③ 大小和速度**
- **堆**：通常**大**，但动态分配释放有**时间开销**
- **栈**：大小**有限**（一般 8MB），但分配释放**快**（编译器自动管理）

### 记忆表

| 对比项 | 堆 | 栈 |
|--------|-----|-----|
| 分配方式 | 程序员手动（malloc/free） | 编译器自动 |
| 释放方式 | 手动 free | 函数返回自动释放 |
| 大小 | 大 | 小（固定约 8MB） |
| 速度 | 慢（动态分配有开销） | 快 |
| 风险 | 内存泄漏、内存溢出 | 栈溢出（递归过深） |
| 典型数据 | 对象、动态数组 | 局部变量、函数参数 |
