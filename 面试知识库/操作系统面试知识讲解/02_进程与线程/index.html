02 进程与线程¶

本章覆盖：进程 vs 线程 vs 协程、为什么进程之下还要有线程、多线程优劣、进程/线程切换、进程五种状态、进程上下文、fork 与写时复制。

本章是操作系统面试的"主战场"，几乎必考。建议先把第 1-3 节（进程/线程/协程的关系）吃透，再往后读。

1. 线程和进程的区别是什么？¶

一句话回答¶

进程是操作系统资源分配的基本单位，线程是任务调度和执行的基本单位。 进程像"一家公司"（拥有独立的办公室、资金、设备），线程像"公司里的员工"（共享办公室和资源，各自干活）。

四个维度逐个讲¶

① 本质区别 - 进程：操作系统分配资源的基本单位（内存、文件句柄等） - 线程：CPU 调度和执行的基本单位

② 开销方面 - 每个进程有独立的代码和数据空间（程序上下文），进程间切换开销大 - 同一进程的线程共享代码和数据空间，每个线程只有自己独立的运行栈和程序计数器（PC），线程切换开销小

③ 稳定性方面 - 进程里某个线程崩溃，可能导致整个进程崩溃（一个员工出错，公司可能倒闭） - 一个进程崩溃，不影响其他进程（一家公司倒闭，别的公司照常经营）

④ 内存分配方面 - 系统为每个进程分配独立的内存空间 - 线程不单独分配内存（除了 CPU 资源），用的是所属进程的内存，线程组之间共享资源

记忆表¶

对比项 进程 线程
本质 资源分配的基本单位 调度和执行的基本单位
地址空间 独立 共享所属进程的
切换开销 大（要切换地址空间等） 小（只切栈和 PC）
崩溃影响 互不影响 一个崩了可能带崩整个进程
通信 需要 IPC 机制 直接读写共享内存

2. 进程、线程、协程的区别是什么？¶

一句话回答¶

三者是"越来越轻"的三层执行实体：进程有独立内存、最重；线程共享进程内存、较轻；协程是用户态的轻量级线程、最轻，调度完全由程序自己控制，不需要内核参与。

逐个讲¶

① 进程 - 资源分配和调度的基本单位，拥有独立的堆和栈，不与其他进程共享 - 进程间通信需要管道、消息队列、信号量等专门机制 - 优点：稳定性和安全性高（内存隔离）；缺点：上下文切换开销大（要保存恢复整个进程状态）

② 线程 - 进程内的执行单元，是 CPU 调度的基本单位 - 共享进程的内存空间（堆和全局变量），通信高效——直接读写共享内存 - 切换开销小：只需保存恢复线程上下文 - 缺点：共享内存带来数据竞争和线程安全问题，需要同步互斥机制（锁）解决

③ 协程（Coroutine） - 用户态的轻量级线程，调度完全由用户程序控制，不需要内核参与 - 拥有自己的寄存器上下文和栈，但与其他协程共享堆内存 - 切换开销非常小：只保存恢复协程上下文，不做内核级切换 - 处理大量并发任务时效率极高 - 缺点：需要程序员显式调度和管理，编程模型更复杂

记忆表¶

调度者 操作系统 操作系统 用户程序（自己）
栈 独立 独立 独立
堆 独立 共享 共享
切换开销 大 中 极小
通信 IPC 机制 共享内存 共享内存
典型例子 每个 Chrome 标签页 Java 多线程 Go 的 goroutine

3. 为什么进程崩溃不会对其他进程产生很大影响？¶

一句话回答¶

因为进程隔离性 + 进程独立性：每个进程有独立的内存空间、不共享资源，一个崩了，操作系统只回收它自己的那一份，不影响别人。

两个原因¶

① 进程隔离性 - 每个进程有自己独立的内存空间 - 一个进程崩溃，操作系统回收它自己的内存，不会碰其他进程的内存 - 类比：酒店每个房间独立，一间房着火，不会烧到别的房间

② 进程独立性 - 进程之间不共享资源（文件、网络连接等） - 一个进程崩溃，不会对其他进程使用的资源产生影响

注意：线程就不一样了——同一进程的线程共享内存，一个线程崩了可能带崩整个进程（见第 1 节）。

4. 进程是分配资源的基本单位，这个"资源"指什么？¶

一句话回答¶

主要指三类资源：虚拟内存、文件句柄、信号量。

展开讲¶

  • 虚拟内存：每个进程拥有自己独立的虚拟地址空间
  • 文件句柄（文件描述符）：进程打开的文件、socket 等
  • 信号量：进程间同步互斥的计数资源

面试补充：正因为进程是"资源容器"，所以创建进程要分配资源（开销大），而线程直接复用进程的资源（开销小）——这正好解释了"为什么要有线程"（第 5 节）。

5. 为什么进程之下还要设计线程？¶

一句话回答¶

因为进程太重、进程间通信太麻烦，而实际任务（比如视频播放器的读数据、解压、播放）需要并发执行 + 共享数据，所以需要一种更轻的实体——线程。

用一个例子讲清楚（视频播放器）¶

假设写一个视频播放器，核心功能有三步：从文件读数据 → 解压缩 → 播放。

方案一：单进程（顺序执行）

读数据 → 解压缩 → 播放 → 读数据 → 解压缩 → 播放 → ...

问题： - CPU 不强时，Read（读数据）可能长时间等待 I/O，画面声音会卡顿不连贯 - 各个函数不是并发执行，资源使用效率低

方案二：多进程

进程A: 读数据
进程B: 解压缩
进程C: 播放

问题： - 进程之间如何通信、共享数据？（需要 IPC，麻烦） - 维护开销大：创建进程要分配资源、建立 PCB；终止要回收资源、撤销 PCB；切换要保存状态

方案三：线程（正确答案）

需要一种新实体，满足两个特性： - 实体之间可以并发运行 - 实体之间共享相同的地址空间

这个实体就是线程。线程之间可以并发运行，且共享相同地址空间——既解决了并发问题，又避开了进程间通信和维护开销的麻烦。

面试金句："线程 = 共享地址空间的轻量级执行流，是为了在并发性和资源共享之间取得平衡而设计的。"

6. 多线程比单线程的优势、劣势？¶

一句话回答¶

优势：提高运行效率，充分利用多核 CPU，同时处理多个任务；劣势：数据竞争需要加锁（有开销、有死锁风险），且每个线程都消耗资源。

优劣对比¶

优势 - 提高程序运行效率，充分利用多核处理器的资源 - 同时处理多个任务，加快程序执行速度

劣势 - 数据竞争：多线程同时访问共享数据，需要锁机制保证线程安全 - 加锁开销：锁本身有性能损耗 - 死锁风险：锁用不好会死锁 - 资源消耗：每个线程都占内存和处理时间，线程多了会消耗更多系统资源

7. 多线程是不是越多越好？太多会有什么问题？¶

一句话回答¶

不是越多越好。线程太多主要带来两类问题：切换开销过大（系统负载高）和竞争/死锁问题（数据不一致、程序卡死）。

两类问题¶

① 切换开销 - 线程的创建和切换消耗系统资源（内存 + CPU） - 线程太多会占用大量资源，系统负载过高 - 某个线程崩溃后，可能导致整个进程崩溃（还记得吗？线程共享进程内存）

② 竞争条件和死锁 - 竞争条件：多个线程同时访问修改共享资源，没有合适的同步机制 → 数据不一致或错误 - 死锁：多个线程互相等待对方释放资源 → 程序无法继续执行

类比：一家公司招太多员工，工位不够、内耗严重，反而产出下降。

8. 进程切换和线程切换的区别？¶

一句话回答¶

进程切换要切换整个进程的"家当"（地址空间、全局变量、文件描述符），线程切换只需切换"个人物品"（堆栈、寄存器、程序计数器），所以进程切换开销大、线程切换开销小。

展开讲¶

① 进程切换 - 涉及内容：整个进程的地址空间、全局变量、文件描述符等 - 开销通常比线程切换大

② 线程切换 - 只涉及：线程的堆栈、寄存器、程序计数器等 - 不涉及进程级别的资源（因为线程共享进程的地址空间） - 开销较小

为什么线程切换省了这些？¶

线程共享同一进程的地址空间，切换时不需要切换内存映射表（MMU 地址转换的底表），省下了进程切换中最大的一块开销。

9. 线程切换详细过程是怎么样的？上下文保存在哪里？¶

一句话回答¶

线程切换分四步：保存当前线程上下文 → 切换到调度器 → 调度器选下一个线程并恢复其上下文 → 切换执行权给新线程。上下文保存在线程控制块（TCB）里。

四步过程¶

步骤1：上下文保存
  当前线程的上下文（寄存器状态、程序计数器、堆栈指针等）被保存

步骤2：切换到调度器（Scheduler）
  操作系统把执行权交给调度器，调度器按调度算法选择下一个线程

步骤3：上下文恢复
  从被选中线程的 TCB 中取出之前保存的上下文，恢复执行状态

步骤4：切换到新线程
  执行权交给新线程，新线程从上次停下的地方继续执行

上下文存在哪里？¶

保存在线程控制块（Thread Control Block，TCB）中： - TCB 是操作系统管理线程的数据结构 - 包含：线程状态、寄存器的值、堆栈信息等 - 切换时，操作系统通过切换 TCB 来保存和恢复上下文

类比：TCB 就像每位员工的"档案柜"，里面存着每个人的工作状态；换人干活时，先归档当前人的状态，再从档案柜取出下一位的状态。

10. 进程的状态（五种状态）如何切换？¶

一句话回答¶

进程有五种状态：创建、就绪、运行、阻塞、结束，它们之间的切换由创建、调度、时间片用完、等待事件、事件完成等动作触发。

五种状态¶

状态 含义 类比
创建（New） 进程刚被创建 新员工刚入职
就绪（Ready） 万事俱备，等 CPU 员工坐在工位等分配任务
运行（Running） 正在 CPU 上执行 正在干活
阻塞（Blocked） 等某个事件（如 I/O） 等打印机/等资料送达
结束（Terminated） 运行完成或出错 离职

状态切换路径¶

创建 ──初始化完成──▶ 就绪 ──被调度器选中──▶ 运行 ──运行完成/出错──▶ 结束
                         ▲                    │
                         │ 时间片用完          │ 请求 I/O 等事件
                         │                    ▼
                         └──────────────── 阻塞 ──等待的事件完成──▶ 就绪

逐条解释： - NULL → 创建：新进程被创建时的第一个状态 - 创建 → 就绪：创建完成并初始化后，一切就绪，等待运行（这个过程很快） - 就绪 → 运行：被进程调度器选中，分配 CPU 正式运行 - 运行 → 结束：运行完成或出错，被操作系统作结束处理 - 运行 → 就绪：运行时间片用完，被操作系统变为就绪态，换其他进程运行 - 运行 → 阻塞：请求某个事件必须等待时（如请求 I/O 事件） - 阻塞 → 就绪：等待的事件完成时，从阻塞变回就绪，等下一次被调度

11. 进程上下文有哪些？（进程上下文切换）¶

一句话回答¶

进程的上下文切换，不仅包含虚拟内存、栈、全局变量等用户空间资源，还包含内核堆栈、寄存器等内核空间资源；进程由内核管理，所以切换只能发生在内核态，交换信息保存在进程的 PCB 里。

从 CPU 上下文说起¶

CPU 要运行一个任务，必须先知道"任务从哪里加载、从哪里开始运行"，这依赖两样东西： - CPU 寄存器：CPU 内部容量小但速度极快的存储。类比：口袋（快）> 书包（内存）> 家里柜子（硬盘） - 程序计数器（PC）：存 CPU 正在执行或即将执行的指令位置

CPU 寄存器和程序计数器合起来叫 CPU 上下文。

CPU 上下文切换：把前一个任务的 CPU 上下文保存起来 → 加载新任务的上下文 → 跳转到新位置运行。

进程的上下文切换¶

任务分三类：进程、线程、中断，所以上下文切换也分三种。

进程的上下文切换切换什么？ - 用户空间资源：虚拟内存、栈、全局变量 - 内核空间资源：内核堆栈、寄存器 - 交换信息保存在进程的 PCB（Process Control Block）里，运行时从 PCB 取出上下文恢复到 CPU

关键点¶

  • 进程切换只能发生在内核态（进程由内核管理和调度）
  • 上下文切换的开销希望越小越好：让进程把更多时间花在执行上，而不是浪费在切换上

面试金句："进程上下文切换 = 用户态资源 + 内核态资源的双重切换，而线程切换只需要切换内核态的那部分。"（线程共享地址空间，不用切换虚拟内存）
