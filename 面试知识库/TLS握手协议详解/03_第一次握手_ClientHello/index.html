03 第一次握手：ClientHello¶

本章目标：看懂客户端开场白 ClientHello 里装的三样东西——TLS 版本、密码套件清单、随机数，以及为什么这三样都必不可少。

ClientHello 是什么时刻发出的？¶

在每一次新的握手流程中，ClientHello 消息总是第一条消息。 客户端会在三种情况下发送它：

  1. 新建连接之后：你刚在浏览器里输入网址，浏览器与服务器建立 TCP 连接（快递链路通了）后，立刻发出 ClientHello；
  2. 希望重新协商（renegotiation）时：比如连接建立很久了，客户端想重新换一套参数；
  3. 响应服务器发起的重新协商请求时：服务器有时会主动要求重新握手。

一句话：只要是新握手，第一句话永远是 ClientHello。

ClientHello 里装了什么？¶

原文给出的抓包视角示例（这是数据包分析工具 Wireshark 里看到的样子，不用背，看懂结构即可）：

Version: TLS 1.2                          ← ① 我支持的最高 TLS 版本
Random: b76fjdiaei04q9jfea0fjdioaidofja... ← ② 我生成的随机数（Client Random）
Cipher Suites                              ← ③ 我支持的密码套件清单
    Cipher Suites: TLS_ECDHE_ECDSA_WITH_AES_128_GCM_SHA256
    Cipher Suites: TLS_ECDHE_RSA_WITH_AES_128_GCM_SHA384
    Cipher Suites: TLS_ECDHE_ECDSA_WITH_AES_256_GCM_SHA256
    Cipher Suites: TLS_ECDHE_RSA_WITH_AES_256_GCM_SHA384

里面装的东西就三样核心信息：

字段 含义 打个比方
Version 客户端支持的最高 TLS 版本号 "我最高会说 1.2 版的暗号"
Random 客户端生成的随机数（Client Random） "我这边先随机报一个数字，作为配方配料"
Cipher Suites 客户端支持的所有密码套件列表 "这些加密套餐我都会，你挑一个"

为什么是"清单"而不是"选好的一种"？¶

因为双方第一次见面，客户端不知道服务器擅长什么、偏好什么。所以客户端把自己会的全部列出来（像餐厅菜单），由服务器在 ServerHello 里挑选一种（像客人点菜）。这就是"协商"的起点：客户端列菜单，服务器点菜。

随机数 Random 为什么这么重要？¶

很多小白第一次看握手会困惑："握手半天，就为了传一个随机数？"

是的——随机数是生成密钥的最核心配料。原因有两点：

  1. 防止"撞钥匙"：如果每次握手都用固定的数字去算密钥，那么攻击者只要破解一次，所有连接的密钥都暴露了。每次连接生成新的随机数，就能保证每次连接的密钥都不同（即使同一台设备、同一个网站）。这叫"会话"独立——一次连接被破解，不影响其他连接。
  2. 防重放攻击：如果密钥固定，攻击者可以把之前录下的加密消息"重放"一遍（比如重复提交一次转账请求）。随机数让每次握手的密钥都独一无二，旧消息在新连接里根本解不开。

原文的原话是："在握手时，Client 和 Server 都会提供随机数，它们也是生成对称秘钥的必备条件。" 注意"双方都提供"——最终的主密钥（会话密钥）要用 三个随机数 一起算出来（Client Random + Server Random + pre-master），第 6 章会详细展开，这里先记住 Client Random 是其中第一味配料。

一段"翻译成人话"的 ClientHello¶

把报文翻译成日常对话，ClientHello 就是在说：

"你好，我是客户端。我最高支持 TLS 1.2 版本。我这里随机选了一个数字（Client Random），请你收好。另外我把我会的加密套餐都列出来了——ECDHE_ECDSA 配 AES 128、ECDHE_RSA 配 AES 128……总之一共十几种，你从中挑一种你和我都满意的，然后把你的选择告诉我。"

注意：这条消息是明文发送的（此刻双方还没有密钥）。被窃听也没关系——消息里没有秘密，只是能力清单和一个随机数，就算被偷看，攻击者也用不上。

本章知识点小结¶

  • ClientHello 是每一次握手的起点，出现在新建连接、客户端主动重新协商、响应服务器重新协商三种场景。
  • 它包含三样东西：支持的 TLS 版本（Version）、客户端随机数（Client Random）、密码套件清单（Cipher Suites）。
  • 版本表示"我最高会什么"；清单表示"我全部会什么"；随机数是以后生成密钥的必备配料之一。
  • 客户端列出菜单，由服务器点菜——协商的主动权在服务器手里。
  • 每次握手都生成新随机数 → 每次连接密钥不同 → 防"一破全破"、防重放。
  • 此刻一切都是明文，但没秘密可偷。
