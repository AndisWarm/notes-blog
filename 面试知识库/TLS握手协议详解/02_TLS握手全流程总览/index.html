02 TLS 握手全流程总览¶

本章目标：把一次完整握手的 13 步从头到尾过一遍，先建立"地图感"，后面每章再放大细节。读完后你能对任何人复述："TLS 握手就是先打招呼、再亮证书、再换钥匙、最后互相验证。"

先记住一个核心悬念¶

整场握手，双方忙活了半天，最终目的是什么？

让客户端和服务器各自独立地算出同一把会话密钥——用它加密握手之后的所有数据。

关键在"各自独立地算出"这六个字。为什么不能直接一方算好寄给对方？因为钥匙在网络上传来传去就可能被偷。所以 TLS 的设计是：双方各自贡献一点"配料"（随机数），然后用同一套公式算出同一个结果。就像两个人各带一勺盐，按同一份菜谱做菜，做出的是同一锅汤——但谁都没有把整锅汤端到网上。

握手消息全景图¶

先看整体。这是一次完整的 session（会话）握手流程，总共 13 步（原文编号）：

Client（客户端/浏览器）                        Server（服务器/网站）
     │  ① ClientHello                                │
     │   "我能支持 TLS1.2，这是我的密码套件清单       │
     │    和随机数，请选"                             │
     ├──────────────────────────────────────────────→│
     │  ② ServerHello                                │
     │     "好，就用 TLS1.2 + 套件 X，这是我的随机数"  │
     │  ③ Certificate                                │
     │     "这是我的身份证（数字证书）"                │
     │  ④ ServerKeyExchange（视算法而定）             │
     │     "生成钥匙还需要这些额外信息"                │
     │  ⑤ CertificateRequest（可选）                  │
     │     "我也要看看你的身份证"                     │
     │  ⑥ ServerHelloDone                           │
     │     "我说完了，该你了"                         │
     │←──────────────────────────────────────────────┤
     │  ⑦ Certificate（可选）                         │
     │     "这是我的身份证"                            │
     │  ⑧ ClientKeyExchange                          │
     │     "这是我生成的额外随机数，用你的公钥加密了"   │
     │  ⑨ CertificateVerify（可选）                   │
     │     "证明这把钥匙真是我的"                      │
     │  ⑩ ChangeCipherSpec                           │
     │     "我这边开始用加密模式了！"                  │
     │  ⑪ Finished（加密消息）                        │
     │     "把之前说的话做个指纹给你验"                │
     ├──────────────────────────────────────────────→│
     │  ⑫ ChangeCipherSpec                           │
     │     "我这边也切换加密模式了！"                  │
     │  ⑬ Finished（加密消息）                        │
     │     "我的指纹也给你验"                          │
     │←──────────────────────────────────────────────┤
     │                                               │
     ▼ 验证通过，握手完成 ▼                           │
     │  从此之后：所有数据用会话密钥加密传输            │
     │◄═════════════════════════════════════════════►│

原文把 13 步按"四次往返"归组，习惯上叫四次握手（4 次消息往返）：

轮次 谁 → 谁 包含的消息 一句话概括
第一次握手 Client → Server ① ClientHello 客户端亮出自己会什么
第二次握手 Server → Client ② ServerHello ③ Certificate ④ ServerKeyExchange ⑤ CertificateRequest ⑥ ServerHelloDone 服务器选定方案 + 亮出身份
第三次握手 Client → Server ⑦ Certificate ⑧ ClientKeyExchange ⑨ CertificateVerify ⑩ ChangeCipherSpec ⑪ Finished 客户端交出密钥配料 + 切换加密
第四次握手 Server → Client ⑫ ChangeCipherSpec ⑬ Finished 服务器切换加密 + 收尾验证

用"寄保险柜"类比走一遍¶

把 TLS 握手想象成两人第一次合作寄机密包裹，全程都在打电话（网络）里完成：

  1. ① 甲方（客户端）打电话给乙方（服务器）："我这边能用三种密码锁（密码套件清单），另外我随机说了一个数字 7，作为我们约定的配料之一。"——这是 ClientHello。

  2. ② 乙方回复："那就用第二种锁；我也随机说一个数字 3，作为另一个配料。"——这是 ServerHello。 ③ 乙方接着说："为了让你相信我是真乙方，我把盖了公证处（CA）章的身份证明拍给你看。"——这是 Certificate。 ④ 如果用的锁比较特殊，乙方还要附上用法说明——这是 ServerKeyExchange。 ⑤ 如果乙方的生意要求验明甲方身份，他会说："也把你的证明发来看看。"——这是 CertificateRequest（可选）。 ⑥ 最后乙方说："我说完了，该你了。"——这是 ServerHelloDone。

  3. ⑦ 如果乙方要求了，甲方发自己的身份证明——Certificate（可选）。 ⑧ 甲方说："我这边再提供一个随机数 11，我用你的公钥把它锁进只有你能打开的箱子里寄给你。"——这是 ClientKeyExchange，寄出的随机数叫 pre-master。 ⑨ 如果走了身份验证流程，甲方要证明"这个随机数确实是我发的"——CertificateVerify（可选）。 ⑩ 甲方宣布："从现在起，我的话都用我们算出来的新钥匙加密。"——ChangeCipherSpec。 ⑪ 甲方用新钥匙加密一条消息发给乙方："这是我们刚才所有对话的指纹，你验一下。"——Finished。

  4. ⑫ 乙方也宣布切换到加密模式——ChangeCipherSpec。 ⑬ 乙方用新钥匙加密同样的指纹消息发给甲方验证——Finished。

双方各自验过指纹、确认新钥匙没问题之后，握手正式完成，之后双方就用这把会话密钥加密传输真正的 HTTP 请求和响应。

13 步里哪些"不总是出现"？¶

注意全景图里打了"可选"标记的三条消息：

  • ③ Certificate（服务器证书）：仅当需要服务器身份验证时发送——而现实中几乎总是需要（不然你连的网站就没法验明正身了），所以它实际上次次出现。
  • ⑤ ⑦ ⑨ CertificateRequest / Certificate / CertificateVerify（客户端身份验证）：仅当服务器要求验证客户端身份时才出现。普通网站访问通常不需要（谁都能浏览），但在银行、企业内部系统等场景会出现——服务器也要确认"你是你"。
  • ④ ServerKeyExchange：取决于密钥交换方式。用 ECDHE 等算法时需要，用某些固定 RSA 方式时不需要。

把握主线时，把这 4 条"可变消息"先忽略，记住 9 条必出现的消息即可：

ClientHello → ServerHello → Certificate → ServerHelloDone
→ ClientKeyExchange → ChangeCipherSpec → Finished
→ ChangeCipherSpec → Finished

记忆法：打个招呼（Hello×2）→ 亮个身份（Certificate）→ 我准备好了（HelloDone）→ 交钥匙配料（KeyExchange）→ 切换加密（CCS×2）→ 指纹互验（Finished×2）。

一张图总结（九宫格版）¶

阶段 做的事 使用的工具
打招呼 双方报版本、报能力、报随机数 明文（此刻还没加密）
亮身份 服务器出示证书，客户端验证 数字证书 + CA 公钥 + 哈希
交配料 客户端用服务器公钥加密寄出 pre-master 非对称加密
算钥匙 双方用 3 个随机数算出同一把会话密钥 密钥派生公式
切加密 双方先后宣布改用新钥匙 ChangeCipherSpec
互验 双方用指纹确认之前没人搞鬼 哈希 + 对称加密
开工 用会话密钥加密传输 HTTP 数据 对称加密
